# 安装手册

要求本地已安装 [Node.js](https://nodejs.org/)（需 22.22 及以上）。装好后在侧栏「设置」里配置模型 API Key（自带密钥，仅存本机）；默认地址 `http://127.0.0.1:4321/`。

## 方式一：本地服务（推荐）

### 1. 安装

```bash
npx lantern-harness
```

执行后会安装全局短命令 **`lantern`**。产品名 **Lantern Harness**；npm 包名 `lantern-harness`，命令 `lantern`。

- 升级：`lantern update`（最新版本）或 `lantern update <版本>`（指定版本）。若后台服务正在运行，更新完成后会自动用新版本重启；没有运行则下次 `lantern web` 生效。升级后在浏览器里正常刷新一次即可看到新版本，不用清缓存（从 0.1.28 及更早版本升上来时，仍需手动刷新一次）。
- 卸载命令：`lantern uninstall`（保留数据空间）
- 查看可用版本：`lantern list`

### 2. 初始化数据空间池根

首次必做；可再次执行以更换池根：

```bash
lantern init
lantern init --scope=both   # 同时写入产品与本地开发（默认）
lantern init --scope=web    # 仅产品：lantern web / npx
lantern init --scope=dev    # 仅本地开发：pnpm dev
```

按序号选择目录：

```text
选择数据目录：
  1) 打开系统文件夹选择器
  2) 当前目录（当前终端所在位置）
  3) 自定义路径（手输）
请输入 1 / 2 / 3（默认 1）：
```

未加 `--scope` 时还会再问一次作用域（仅产品 / 仅开发 / 两者）。选项 `2` 的「当前目录」指执行命令时终端所在的工作目录。

结果记在本机配置（`lantern config` 查看路径）：

- `dataRoot`：产品服务（`lantern web` / npx）
- `devDataRoot`：本地 `pnpm dev`（未单独配置时回退 `dataRoot`；再没有则回退源码仓库根）

两边写成**同一路径**就共用同一份数据；写成不同路径则互不影响。池根被移动/重命名/删除后，请重新 `lantern init`。

### 3. 常用命令

```bash
lantern init           # 选择并记住数据空间
lantern web            # 启动本地 Web 服务
lantern stop           # 停止服务
lantern restart        # 重启服务
lantern status         # 运行状态、端口、数据空间
lantern open           # 在浏览器中打开工作台
lantern path           # 显示当前数据空间路径
lantern config         # 显示配置文件地址
lantern logs           # 查看服务日志
lantern doctor         # 检查运行环境与配置是否正常
lantern help           # 显示操作命令列表
lantern version        # 显示当前版本号
lantern list           # 显示可用版本列表
lantern update         # 更新到最新版本（在跑的服务会自动重启）
lantern update 0.1.x   # 更新到指定版本（同上）
lantern uninstall      # 卸载本机 lantern 命令（保留数据空间）
lantern wipe           # 删除当前数据空间（需确认；不可恢复）
lantern ask            # 进阶：无界面单轮问答，lantern ask <问题或要求>
lantern rpc            # 进阶：以 stdio JSON-RPC 暴露本地问答能力
lantern acp            # 进阶：以 ACP 子集供外部编排驱动无 UI Agent
lantern mcp            # 进阶：以 stdio MCP 向 Codex 暴露 Lantern 能力（可选 --url / --port）
```

无头入口与 Web 工作台的权限对照（策略模块 `agent-policy`）：

| 入口          | 默认 access                         | 默认工具            | 覆盖方式                                                                                  |
| ------------- | ----------------------------------- | ------------------- | ----------------------------------------------------------------------------------------- |
| Web 工作台    | 会话 `access`（新会话取设置页默认） | 按插件 / 权限档组装 | 会话菜单改权限；计划模式强制只读                                                          |
| `lantern ask` | 空间配置 `access`，缺省 `readonly`  | 无工具              | `--access` · `--tools none\|fs-readonly`                                                  |
| `lantern rpc` | 同上                                | 无工具              | 启动 flag 或 RPC `ask` 参数 `access` / `tools`                                            |
| `lantern acp` | 同上                                | 默认关工具          | `--tools none\|fs-readonly\|fs`；session 参数 `tools` 可为布尔或同名字符串（与 rpc 对齐） |
| `lantern mcp` | 通过 Bridge 调用 Lantern 现有能力   | 由具体工具声明      | Codex MCP 配置；工具写操作按 MCP annotation 审批                                          |

说明：无头目前即使打开工具也只有 **fs 只读子集**（list/read/glob），与 Web 全量工具集不同；`--access` 用于策略对齐与后续扩展，不会在 ask 默认路径下放开写盘。

**外接 MCP（可选）**：推荐在工作台「我的插件 → MCP」里添加（含腾讯文档一键模板）；也可手写当前数据空间 `.lantern/local/mcp.json`，例如：

```json
{
  "servers": [
    { "name": "demo", "transport": "stdio", "command": "npx", "args": ["-y", "some-mcp-server"] },
    {
      "name": "tencent-docs",
      "transport": "http",
      "url": "https://docs.qq.com/openapi/mcp",
      "headers": { "Authorization": "<MCP Token>" }
    }
  ]
}
```

工作台会把远端工具注入为 `mcp__demo__…` / `mcp__tencent-docs__…`；页面保存或 `POST /__tb_mcp/reload` 后生效。管理 API：`GET/PUT/DELETE /__tb_mcp/servers`。详见 [`docs/全局插件.md`](./全局插件.md)「mcp-client」。

### 4. 打开工作台

浏览器打开终端提示的地址（或 `lantern status` / `lantern open`），在侧栏「设置」配置模型即可。

### 5. 首次进入看到什么

新空间侧栏提供「我的工作台」「插件仓库」「帮助中心」。在「插件仓库 → 技能」维护独立技能和空间基础规则；扩展能力仍通过仓库开关启用，首次开启时准备推荐技能，保留已有正文且不覆盖技能启停。原提示词目录在迁移后作为兼容备份，独立提示词菜单移除。

| 分类       | 插件                                                                       | 新建空间默认 |
| ---------- | -------------------------------------------------------------------------- | ------------ |
| 内容库     | 用例管理、知识库管理、需求文档库、测试模板库                               | 关           |
| 内置能力   | 空间基础规则（插件仓库 → 技能）                                            | 常驻         |
| 生成能力   | 生成测试用例、生成知识库                                                   | 关           |
| 记忆与检索 | 知识库检索、会话记忆                                                       | 关           |
| 待办与效率 | 任务管理、待办事项                                                         | 关           |
| 人生管理   | 人生管理（KR 待办 / KR 任务 / Objective / OKR 复盘 / 年度计划 / 人生阶段） | 关           |
| 开发工具   | 插件开发                                                                   | 关           |

## 方式二：源码启动

适合改代码或二次开发。

### 1. 克隆仓库

```bash
git clone https://github.com/yychuiyan/lantern-harness.git
cd lantern-harness
```

### 2. 开发模式

热更新，含本地落盘 API。池根与产品服务分开配置：默认跟 `dataRoot`，也可用 `lantern init --scope=dev` 单独指定（例如指到 iCloud 与 `lantern web` 共用，或指到仓库根做沙箱）。

```bash
pnpm install
pnpm dev
```

`lantern status` 可同时看到产品池根与开发池根。

### 3. 预览静态页

需先打包；无本地落盘：

```bash
pnpm build
pnpm preview
```

更完整的产品用法见 [操作手册](https://lantern.yychuiyan.com/docs/manual/)。

## 业务地图 AI 识别运行环境

先在「设置」配置模型，再在业务地图系统详情启动 AI 自动识别。文档与源码识别不需要浏览器；页面识别使用 Playwright + Chromium，不要求先创建自动化测试项目。

源码安装后执行一次：

```bash
pnpm exec playwright install chromium
```

全局 CLI 安装后，可使用与 Lantern 依赖一致的 Playwright 版本安装 Chromium（当前依赖 `playwright@1.65.1`）：

```bash
npx playwright@1.65.1 install chromium
```

已有项目安装 Playwright 时，也可在识别「采集限制与排除范围」填写该项目目录作为浏览器运行时。页面登录态在系统设置中选择现有 storageState JSON；缺少浏览器或登录态失效时，任务显示具体原因，可准备环境后重试。仅文档 / 源码可用时仍可选择它们完成识别。

后台任务属于本机服务进程。浏览器页面关闭后继续运行；服务关闭会中断，重新启动服务后从业务地图的「后台任务」重试。任务与检查点保存在当前空间 `.lantern/local/business-map/analyses/`，不要将其中的业务来源正文随意共享。

### 技能目录与兼容迁移

首次打开「插件仓库 → 技能」按当前空间迁移已有提示词，保留正文和变体；`技能管理/` 支持现有内容分组定位。迁移后的标准结构为同目录 `SKILL.md` 入口与 `references/business-rules.md` 业务规则，可选 `scripts/`；旧规则文件名继续供已有配置引用。当前空间迁移不会改其他空间。

技能历史与恢复清单位于 `.lantern/local/skills/`，备份空间时应同时保留技能目录与原提示词目录。新空间沿用现有初始化内容，再纳入技能，不要求额外安装执行环境。独立校验脚本可用 Node 读取标准输入 JSON；仅校验数据，不安装依赖、不启动实际测试。

### Codex MCP

`lantern mcp` 使用 stdio MCP 暴露当前空间能力。安装全局命令后可执行 `codex mcp add lantern -- lantern mcp`；源码环境使用 `codex mcp add lantern -- node /绝对路径/cli/lantern.mjs mcp`。已有 `lantern web` 时直接连接，否则 Bridge 启动仅供 MCP 使用的内嵌服务。更新后重启 Lantern 服务及 MCP 进程，并新建 Codex 会话，可发现 `lantern_mcp_tools` / `lantern_mcp_call`，直接复用当前空间已连接的腾讯文档等外接 MCP，无需重复配置凭据。完整配置、Skill 安装和并发冲突处理见 [Codex MCP 集成](Codex-MCP集成.md)。

### Codex 缺陷提交技能

在 Lantern 开启「缺陷规则」插件并配置目标入口后，可将仓库 `skills/lantern-defect-submit/` 复制到 `~/.agents/skills/`。继续使用现有 Lantern MCP 配置，新建 Codex 会话发现缺陷上下文、草稿、提交及回执工具。AI 按 `platform` 选择匹配连接器；当前腾讯文档适配复用空间已有的 `tencent-docs` MCP 服务。

缺陷规则现使用 `/defect-rules/` 卡片管理页，新建和编辑在右侧面板进行。支持链接识别与手动字段，每个字段保存 rule 填写口径、defaultValue 独立默认值、required 和 source 来源。`POST /rules/save` 保存规则，允许手动规则暂不配置链接。旧 /templates API 和历史模板数据继续兼容。

### 业务地图登录运行环境

业务地图的账号密码及手动登录需要本机 Playwright Chromium（可沿用自动化测试已安装的运行时）；尚未安装浏览器时执行 `pnpm exec playwright install chromium`。手动登录、验证码与扫码需要图形桌面；SSO / 接口登录不需要打开浏览器。登录配置入口为「业务地图 → 系统设置 → 登录配置」，凭据存放在本机用户配置目录 `business-map/auth/<空间路径哈希>/<系统ID>/`，不随地图数据导出。升级代码后重启 Lantern 后端使新登录接口生效。
