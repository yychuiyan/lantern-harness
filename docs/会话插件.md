# 会话插件

来源：[`src/lib/builtin-plugin-catalog.ts`](../src/lib/builtin-plugin-catalog.ts) 的 `SESSION_PLUGIN_CATALOG`（决策清单「做」）。

- **策略**：会话默认能力，无用户开关。
- **实现层**：目录展示 ≠ Cordis 包；会话已落地 Runner 在 [`builtin/session/`](../builtin/session/)；扩展/基建仍在 `lh-plugins/`。
- **与扩展关系**：扩展 Tab 为可开关产品能力（用例生成、记忆等）；`tool-web` / `tool-fs` 为会话内置，实现文件在 `builtin/session/`，不放在 `lh-plugins/`。
- **服务端回合**：[`session-runs.mjs`](../builtin/session/session-runs.mjs) 提供 `/__tb_sessions/runs`（start / SSE / stop）。有一体服务时 ChatApp 把回合放到进程内跑，刷新/切页可重连；手动停止展示「已停止」。无服务时降级浏览器流。

## agent-instructions

- **分类**：会话能力
- **作用**：加载 AGENTS.md/CLAUDE.md。
- **状态**：已就绪
- **Lantern Harness 映射**：`lh-fs` `/__tb_fs/agent-instructions` + ChatApp system 注入

**行为**：每次发送前（本地 dev + 工作区可用时）加载指令并并入 system。

**候选文件**（目录内按序、内容去重）：`AGENTS.md`、`CLAUDE.md`；可选 overlay：`AGENTS.local.md`、`CLAUDE.local.md`。

**作用域**：当前工作区目录 +（若不同）项目根 `projectRoot`；由宽到窄拼接。

**预算**：`maxBytes = 65536`；超限先丢更宽文件，再截断最具体文件。

**实现**：

- 在 [`builtin/session/lh-fs.mjs`](../builtin/session/lh-fs.mjs) 增加 `GET/POST /__tb_fs/agent-instructions`（读盘、截断、返回 `{ text, files[] }`）
- [`src/lib/fs-tools.ts`](../src/lib/fs-tools.ts) 增加 `fetchAgentInstructions()`
- [`ChatApp.tsx`](../src/components/islands/ChatApp.tsx) 在 `buildPluginMessages` 前拼入一段固定中文引导 + 正文（无文件则不加）

**边界**：无本地 fs / 无工作区：静默跳过，不报错打断发送。本批不做全局指令链、不做嵌套目录 touch 刷新。

## time-context

- **分类**：会话能力
- **作用**：注入当前时间与耗时。
- **状态**：已就绪
- **Lantern Harness 映射**：`src/lib/session-context.ts`（纯前端）

**行为**：每次发送前向 system 注入时钟上下文（纯前端，无需新 `tb-*`）。

**内容**：

- 当前时间（ISO 形态 + IANA 时区）
- 浏览器时区策略
- 距上一轮用户可见消息的耗时

**节流**：同一会话内默认最少间隔 **10 分钟**（`refreshIntervalMs: 600000`）；间隔内可注明沿用上次采样，避免每轮刷 system。

**实现**：新建 [`src/lib/session-context.ts`](../src/lib/session-context.ts)（`formatTimeContext` + 节流状态），由 ChatApp 写入 system 附加段。

**边界**：不写入 durable user 消息；不依赖 Cordis。

## tool-bash

- **分类**：会话能力
- **作用**：模型可调用 bash 在本机执行命令（默认同步；可 `background` 挂 jobs）。
- **状态**：已就绪
- **Lantern Harness 映射**：`lh-bash.mjs` / `bash-tools.ts`

**行为**：工具 `bash`：`command`（必填）、`workdir`（可选）、`background`（可选）。经 `/bin/bash -lc`（Windows 为 `bash`）。`background=true` 时立即返回 `jobId`。

**状态**：已就绪（会话默认；需本地服务；访问权限须为「工作区内修改」或「完全权限」）。

**Lantern Harness 映射**：

- Runner：[`builtin/session/lh-bash.mjs`](../builtin/session/lh-bash.mjs) → `/__tb_bash`
- 客户端：[`src/lib/bash-tools.ts`](../src/lib/bash-tools.ts)
- 同步：默认超时 30s（上限 120s）；stdout/stderr 各截断约 32KB
- 后台：见 [`tool-jobs`](#tool-jobs)

**边界**：软沙箱策略（命令黑名单 + 精简 env，非 OS 隔离）；持久会话见 `bash_session_*`（PTY 优先 / 管道回退）；无跨服务重启持久化；改文件优先 `fs_*`。

**持久会话**：`bash_session_open` / `exec` / `write` / `signal` / `read` / `close` / `list` → `/__tb_bash/session/*`（对齐全局 `persistent-bash` / `terminal-bash` / `pty`）。`write` 写 stdin（默认追加换行、不等待 prompt）；`signal` 支持 SIGINT/SIGTERM/SIGTSTP/SIGHUP。

## tool-fs-search

- **分类**：会话能力
- **作用**：模型可用 glob / grep 搜索工作区文件（内置 ripgrep）。
- **状态**：已就绪
- **Lantern Harness 映射**：`lh-fs` `/__tb_fs/glob`、`/__tb_fs/grep` + `fs_glob` / `fs_grep` 工具

**行为**：模型通过 `fs_glob` / `fs_grep` 搜索工作区（`glob` / `grep` 语义；工具名带 `fs_` 前缀以统一本仓库约定）。

**工具**：

- `fs_glob`：`pattern`（必填）、`path`（可选目录）；无 `/` 的 pattern 按任意深度匹配 basename；最多返回 100 条（mtime 新→旧）
- `fs_grep`：`pattern`（正则）、`path`（文件或目录）、`include`（可选 glob）；最多 250 条匹配

**实现**：

- [`builtin/session/lh-fs.mjs`](../builtin/session/lh-fs.mjs)：优先调用本机 `rg`，不可用时 Node 遍历回退
- [`src/lib/fs-tools.ts`](../src/lib/fs-tools.ts)：`FS_TOOLS_SEARCH`，随 `fsToolsForAccess` 一并注册（只读权限也可用）

**边界**：跳过 `node_modules` / `.git` / `dist` 等；不装 Cordis；不做 spill 完整结果落盘。

- **状态**：已就绪
- **Lantern Harness 映射**：`lh-fs` `/__tb_fs/skills` · `/__tb_fs/skill-load` + [`skill-tools.ts`](../src/lib/skill-tools.ts)

**行为**：

- `skill_list`：合并当前空间已启用技能与工作区 / 项目约定目录；空间技能使用 `space:<id>` 标识

- `skill_validate`：对空间技能的输出执行结构、模板列、编号、引用、枚举、统计等确定性检查；不调用模型、不写业务数据。

- `.cursor/skills/<name>/SKILL.md`
- `.agents/skills/<name>/SKILL.md`
- `skills/<name>/SKILL.md`
- `<name>/SKILL.md`（一层）

**实现**：

- [`builtin/session/skill-fs.mjs`](../builtin/session/skill-fs.mjs) + `lh-fs` HTTP
- ChatApp 在本地 fs 可用时与 `tool-fs` 一并注入

**边界**：无本地 fs 时不注入；不装 Cordis 技能注册表；不做全局 skill 链。底座条目见全局 [`skill`](./全局插件.md#skill)。仓库内置 Office 技能见 [`skills/office/SKILL.md`](../skills/office/SKILL.md)（全局 [`skill-office`](./全局插件.md#skill-office)）。

## Lantern MCP Bridge

- **作用**：把当前空间技能、需求、需求拆解、用例执行、业务地图和缺陷能力以 stdio MCP 工具提供给 Codex。
- **外接 MCP**：`lantern_mcp_tools` 返回当前空间已连接工具、参数和连接错误，`lantern_mcp_call` 按真实名称转发读写，复用工作台凭据与远端权限，保留原始内容和结构化结果。调用前重新校验当前工具目录，不自动重试；缺陷提交优先用专用草稿 / 提交 / 回执工具。
- **命令**：`lantern mcp`；可连接已运行服务，也可按需启动内嵌服务。
- **工具范围**：需求导入、分析列表 / 读取 / 保存 / 删除、用户故事维护、故事审查、测试点、需求拆解 XMind、用例执行文件与单条运行 / 等待 / 停止 / 写回 / 统计同步、业务地图读写 / 登录 / 本地资料 / AI 识别、缺陷规则 / 草稿 / 提交 / 回执，以及技能列表 / 加载 / 校验。
- **业务流程约束**：业务地图 AI 助手生成和应用流程时均检查证据、有效承载功能与下一步目标；纯人工环节须明确设置 `manual=true`。`next` 使用目标步骤编号（多个目标用逗号分隔，结束留空），`branch` 使用「条件→步骤编号」，多个条件用分号分隔；无法验证的分支保留为待补全。补充回合会读取上一版草案、已有流程及近期对话。
- **用例执行写回**：`lantern_case_execution_start` 仅启动单条执行，`get` / `wait` 读取待确认建议与证据；用户验证并明确选择状态后调用 `apply` 写回。页面也不自动选择最终状态，写回使用文件哈希及用例内容 / 需求基线校验，冲突拒绝覆盖。统计同步兼容历史 P / F 等状态。
- **并发保护**：修改已有分析要求最新 `expectedRevision`；服务端原子比对，冲突返回 `409`，避免页面与 Codex 互相覆盖。
- **边界**：MCP Bridge 读取启用的 Lantern 技能正文和服务端校验；不在 Bridge 内复制业务规则，不通过浏览器驱动 Lantern UI。

## tool-schedule

- **分类**：会话能力
- **作用**：模型可创建/查询/更新/删除定时提醒，到点投递回原会话。
- **状态**：已就绪
- **Lantern Harness 映射**：`schedule_create` / `schedule_list` / `schedule_update` / `schedule_cancel`

**行为**：

1. 模型用工具创建提醒（`dueAt` ISO 或 `delayMinutes`）

**状态**：已就绪（会话默认；主机级见全局 `schedule`）。

**实现**：

- 主机：[`builtin/session/lh-schedule.mjs`](../builtin/session/lh-schedule.mjs)
- 客户端：[`src/lib/session-schedule.ts`](../src/lib/session-schedule.ts) + ChatApp

**边界**：无 Service Worker；主机投递依赖本地服务进程；消息带 `<!--tb-schedule:id-->` 去重。

## tool-result-pruner

- **分类**：compaction
- **作用**：裁剪过长的工具返回（头/中/尾保留），省 token。
- **状态**：已就绪
- **Lantern Harness 映射**：`tool-result-pruner.ts` + `llm.ts` tools loop

## present

- **分类**：会话能力
- **作用**：模型可声明「交付了哪些工作区文件」，便于 UI 展示/打开。
- **状态**：已就绪
- **Lantern Harness 映射**：`present` tool + `/__tb_fs/open` + 消息卡片

**行为**：模型工具 `present`，声明已存在的工作区交付文件，便于 UI 展示/打开。

**Tool schema**（）：

- `files`: `[{ path, description? }]`
- 单次最多 **4** 个；通常 1–2 个最重要交付物

**Runner**：校验路径在工作区策略内且为已存在普通文件（复用 `__tb_fs`）；失败返回明确错误。

### 空间技能与会话入口

技能管理位于「插件仓库 → 技能」，按独立技能展示；一个技能可包含多个内部变体，进入详情后选择变体并在工作台加载。顶部展示本次技能与版本，可取消关联。浏览器与服务端回合使用同一空间技能服务；服务端 `/skill/list`、`/skill/read`、`/skill/validate` 与浏览器既有工具路由行为一致。已关联业务的技能默认启用且不可停用；未关联自定义技能可独立启停。当前空间基础规则仍常驻注入，不作为普通任务技能自动关闭。

静态预览没有本地技能服务，只展示内置只读技能目录；正文、版本、启停和写操作不可用。需要实际技能管理请启动本地 `lantern web` 或 `pnpm dev`。

## 业务地图系统登录

业务地图的系统设置与识别任务共享本机登录配置，支持账号密码、SSO / 接口及手动验证码登录；接口登录复用 UI 自动化的 SSO 解析与登录态保存逻辑。验证码由用户完成后保存 Cookie / localStorage，再继续原识别任务。凭据按空间与系统隔离存放在本机用户配置目录，密码不回显，不进入地图 JSON、导出、源码采集或模型上下文。识别阶段继续保持只读拦截。

### 用例生成、计划与验收 MCP

`lantern_case_generation_setup` 默认返回聊天确认所需的推荐值、需求候选、故事 / 测试点数量和上下文候选；客户端在对话中按组展示真实需求名、用例类型名、对应模板名、输出格式（Excel / CSV / Markdown）、XMind 和业务系统名称及编号选项；用户可回复编号、名称或“按推荐配置生成”。已显式提供的故事和测试点范围会保留，不自动扩大到全部。只有明确传 `presentation=form` 时才尝试 MCP elicitation。确认结果交给 `lantern_case_generation_context`，后者按 `caseType` 解析类型技能、模板、表头、需求基线和多个业务地图系统。`validate` 校验字段和所选真实引用，`save` 带原 revision / sourceFileHash 保存可执行文件，省略 `folder` 时进入该类型目录。`lantern_case_review_context` / `save` 共用用例审查记录，过期文件哈希拒绝写入。`lantern_case_execution_prepare_columns`、`lantern_case_baseline_link` 均先 preview，确认后 apply。

计划工具包括 `lantern_case_execution_plans`、`plan_create`、`plan_get`、`plan_start`、`plan_stop`、`plan_result`（前缀均为 `lantern_case_execution_`）。创建必须使用实际 caseIds 和环境 / 构建，启动需要用户明确授权；API / App 复用已有自动化项目和指定文件，缺环境时阻塞。`lantern_case_acceptance` 返回当前基线的设计 / 执行 / 通过覆盖与验收阻塞原因，可传 environmentKey 隔离环境。新工具需重启后端并新建 Codex 会话发现。

### 通用测试统计 MCP

- `lantern_test_stats_list`：from / to 为含边界的真实日期，dimension 精确匹配，query 搜索日期 / 维度 / 数量；默认排除空占位草稿，includeDrafts=true 可查看。返回 items、全部 dimensions、summary 与 revision。
- `lantern_test_stats_create` / `update` / `delete`：新增明确日期、单维度和数量的记录；按真实 ID 增量修改或删除指定记录，不猜测未提供的统计数量。
- `lantern_test_stats_dimension_create` / `rename` / `delete`：独立新增维度、同步重命名引用记录、删除未使用维度。
- 所有写入传 expectedRevision，值来自最新查询或写入返回；409 后必须重新读取并核对，不能盲重试新增。默认数量口径与页面一致，不将不同统计维度的总数量称为覆盖率 / 通过率。此能力与 `lantern_case_execution_sync_stats` 分别管理通用测试统计和用例执行统计。
