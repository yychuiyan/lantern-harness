# 插件仓库与技能整合方案

日期：2026-11-21。状态：方案与实施记录。后续迭代已落地统一入口、空间技能管理、正文迁移、工作台调用、公共校验和兼容读取，并彻底移除提示词管理页面、插件与文档 API；下文保留目标设计，具体交付范围见末尾实施记录。

## 目标与结论

把工作台中的插件管理移到独立侧栏「插件仓库」，统一提供「扩展插件 / MCP / 技能」三个标签页。现有提示词全部纳入技能管理，补齐必要的执行流程、资源及确定性校验；完成引用迁移后移除独立「提示词管理」菜单。

技能不是单纯改文件名，也不是要求每项功能都运行一段新脚本。复用已有插件执行器；把跨入口可复用、可以确定性验证的部分提取成工具或脚本；模型负责需要语义判断的工作。

## 现状与范围

- 当前空间实际有 20 份提示词 Markdown：13 份登记为插件提示词、1 份空间默认、5 份其他自定义提示词、1 份旧名 Playwright 提示词。仅用于确定迁移范围，不将个人正文写入本方案。
- `PluginsPage.tsx` 已提供扩展插件、MCP 两类。MCP 已有当前空间配置、连接探测、工具列表与调用；不需要重做协议接入。
- `skill-tools.ts`、`skill-fs.mjs` 已有 `skill_list` / `skill_load`，扫描工作区和项目中的约定目录；尚不等于空间技能管理、业务绑定、执行记录已经完成。
- 静态检查发现：服务端回合转发 Skill 到 `/__tb_fs/skill/list`、`/skill/read`，而文件中间件实现为 `/skills`、`/skill-load`。实施时先复现并修通，增加浏览器回合、服务端回合一致性检查。
- 需求分析已有确定性覆盖检查，业务地图已有采集、模型分批分析、证据验证和检查点，自动化项目与执行已有实际执行器；应作为技能适配器复用。
- 当前存在 `promptFile` 持久化引用、保护文件规则、插件开关补种、空间默认提示词及导航固定入口，不能只删除菜单。
- 本表覆盖当前空间 20 份文件。实施迁移工具还必须扫描其他空间和自定义文件，仓库内其他内联系统指令另列审计清单，不自动把所有内部指令暴露为用户技能。

## 产品布局

### 侧栏与入口

1. 增加独立「插件仓库」，建议保留 `/plugins/` 为唯一页面路由，使用 `?tab=extensions|mcp|skills` 定位。
2. 从工作台移除插件管理面板和重复按钮；会话保留「本次使用哪些技能 / 工具」的选择入口，并链接到仓库管理。
3. 移除「提示词管理」侧栏项、固定导航项和用户可见的提示词库开关。内部兼容旧插件 ID 与内容目录，不能通过关闭旧开关使运行时读不到内容。
4. 直接删除 `/prompts/` 页面与 `/__tb_prompts` API；旧配置只通过技能 `legacyPath` 解析。业务页面统一使用「配置技能 / 关联技能」。

### 三类能力的边界

| 类别     | 管理内容                                       | 典型动作                                       | 与另外两类的关系                             |
| -------- | ---------------------------------------------- | ---------------------------------------------- | -------------------------------------------- |
| 扩展插件 | 平台业务模块和数据入口                         | 开启、配置、进入功能                           | 声明依赖的技能及工具，不复制技能正文         |
| MCP      | 外部连接与实际工具                             | 配置、测试连接、查看工具、授权                 | 技能可以声明工具依赖；技能不能自动授予权限   |
| 技能     | 提示词、步骤、模板、参考资料、脚本与执行适配器 | 新建、导入、编辑、试运行、绑定、停用、版本恢复 | 可被会话和业务插件共用；停用后显示受影响入口 |

首期「仓库」指本机与当前空间的能力管理，不建设公共在线商店、付费分发或自动安装未知依赖。

### 技能页面

- 列表展示名称、简介、来源、作用域、关联功能、工具就绪状态、是否启用和最近修改；支持搜索、分类及可用状态筛选。
- 详情分为「概览 / 指令与流程 / 资源 / 关联与依赖 / 版本与验证」。提示词正文就在指令或资源中编辑，不再设置平行提示词管理入口。
- 普通用户默认看到名称、用途、必要输入和操作按钮；脚本与执行器配置放到进阶区。
- 「试运行」可以选择现有材料，展示执行步骤、实际来源、校验结果及输出预览；默认不写入正式业务数据，正式保存继续走对应业务入口的既有规则。
- 空间默认规则也在技能标签页维护，作为「空间基础规则」固定项常驻加载，不参加任务匹配、不当作普通技能随意停用。

## 技能结构与统一调用

### 文件与作用域

空间内通过现有内容根解析器定位 `技能管理/<skill-id>/`，避免假定内容根一定在空间顶层。标准技能结构：

```text
技能管理/<skill-id>/
  SKILL.md                  # 标准名称、用途、输入、步骤、输出与校验说明
  references/               # 业务规则、示例、参考资料（需要时创建）
    business-rules.md       # 当前技能完整业务规则
  assets/                   # 实际模板（需要时创建）
  scripts/                  # 确有必要的可执行校验/转换（需要时创建）
```

不是每个技能都需要所有子目录。现有项目 `.agents/skills`、`.cursor/skills`、`skills` 中的技能继续支持读取；不能自动搬走外部项目文件。

- 技能标识使用稳定 ID，中文名称可变；引用包含作用域，不靠名称猜测同名技能。
- 空间技能可编辑、随空间同步；项目技能按原项目边界使用，初期在仓库中只读查看，可显式复制到空间。
- `SKILL.md` 保持通用格式；平台特有字段放 sidecar，不让通用技能导入依赖私有执行器。
- 默认规则的提示词正文同样保留原文，通过基础规则适配器加载一次，避免重复注入。
- 运行缓存、迁移日志、试运行历史放 `.lantern/local/skills/`；MCP 凭据继续留在 `.lantern/local/mcp.json`，不放技能包。

### 两种执行方式，共用一个注册与解析服务

1. **会话调用**：先注入少量可用技能摘要；用户选择或模型按需加载指定技能。加载资源和实际调用工具记录在会话中。显式选择优先；匹配存在歧义时让用户选择。
2. **业务入口调用**：通过绑定的 `skillId + variantId` 精确解析，由后台执行器运行固定任务；不必把现有稳定任务改成模型自由规划。

注册服务负责枚举、作用域、版本、资源读取、依赖检查、别名及失效诊断；浏览器回合与服务端回合共用，避免出现两套不同的 Skill API。

当前业务地图等任务继续使用既有执行器。技能版本、适配器版本、输入与模板指纹记录到每次运行；任务启动后固定快照，编辑技能只影响新任务。检查点复用必须包含这些版本，防止沿用旧规则结果。

`SKILL.md` 中的步骤是工作说明，不直接转成任意 shell 命令。脚本通过显式注册的执行入口运行，继承原会话或业务权限、工作目录、取消和超时机制；缺少工具时给出依赖说明。

### 脚本补齐原则与优先级

- 优先补公共校验：模板列/枚举、编号与来源引用、覆盖率/分母/单位、输出结构；可复用代码应提取共享函数，不复制一套独立脚本。
- 项目检查、浏览器采集、后台任务等已有执行器，给技能注册适配器即可。新 `scripts/` 仅用于确需独立运行的转换、导入、验证，并给出输入输出协议和明确错误。
- 需求歧义、业务规则判断和场景遗漏属于语义分析，用流程约束、样例及模型评估提升，不用形式脚本伪装成客观验证。
- 每个技能至少有正常输入、缺失材料、错误引用/格式三类回归样本。无需新脚本的技能也需验证可加载、可调用及保持原行为。

## 迁移流程与兼容设计

### 阶段 1：建立统一入口和调用底座

- 增加插件仓库侧栏及技能标签页，复用现有扩展与 MCP 面板。
- 先将当前空间提示词以兼容技能记录显示，编辑仍指向唯一的旧正文；此时不能复制出第二份可编辑正文。
- 修通会话 Skill 加载，增加作用域解析、稳定 ID、技能描述及入口绑定模型。
- 现有提示词入口暂保留为跳转；不能在后台迁移还没完成时先下线内容读取。

### 阶段 2：全量导入与执行能力补齐

1. 按空间扫描全部文件、实际路径、内容 hash、保护属性及消费者引用，生成预览清单。兼容关闭状态插件、自定义目录及同名冲突。
2. 完整保留用户正文导入技能包，通过引用添加流程、模板和适配器；不自动润色或覆盖现有提示词，也不改根 `prompt/` 参考稿及硬编码种子正文。
3. 写入 `legacyPath → skillId + variantId` 映射，将项目、生成配置、报告配置与业务入口引用一并迁移。无法明确匹配的保留旧引用并报告，不能静默选错变体。
4. 校验正文 hash 和所有引用后按空间提交切换；迁移日志支持中断重试和回退，不重复创建技能。
5. 已成功导入的正文成为唯一运行时来源；旧文件归档只读，旧读取接口通过别名解析技能。未迁移项继续原路径读取，失败不阻断原功能。
6. 新空间仍利用现有补种内容初始化技能；为现有 `ensurePluginPrompt` 提供统一适配，已迁移项不再重复生成活跃的旧文件，不能出现两个维护入口。

迁移只覆盖用户打开的当前空间；其他空间首次进入时独立检查和迁移，不跨空间批量写入。并发编辑使用 revision/hash 冲突检测。

### 阶段 3：切换业务绑定并移除旧菜单

- 业务入口改为绑定技能及变体，同时兼容旧 `promptFile` 数据。
- 会话保留明确技能选择并展示本轮实际使用项；业务后台使用固定技能绑定。
- 默认规则迁入「空间基础规则」技能并验证常驻生效；旧 `/prompts/` 页面直接下线。
- 待当前空间全部 20 份正文和实际绑定通过回归，再移除旧菜单；移除导航不删除旧数据。
- 已关联业务的技能默认启用且不可停用；未关联自定义技能可停用。被依赖的技能不允许无提示删除；解绑、替换后再删除。插件关闭保留技能与业务数据。

### 阶段 4：完善版本和质量评估

- 内容版本、变体对比与回退，运行记录关联实际版本；回退配置不撤销已经发生的业务写入。
- 建立离线回归样本，对比输出可解析率、引用有效率、人工返工和完成时间；取得实测结果后再宣称提效，不预设百分比。
- 技能依赖 MCP 的缺失、断连和权限不足明确提示；不要因为管理项统一就让任务静默扩大权限。

## 上线验收条件

1. 插件仓库为唯一管理入口，扩展插件、MCP、技能三类均可定位；工作台不再嵌套重复管理页。
2. 当前空间 20 份正文都有迁移项或明确的保留变体；hash 一致，迁移重复执行不新增重复项，不丢用户修改。
3. 默认规则常驻生效；浏览器回合和服务端回合均能列出/加载技能；同名跨作用域不误选，切空间不串数据。
4. 项目及各插件旧引用可解析，关闭再开启不重置正文，新空间初始化不重复补种；旧链接能正确跳转。
5. 表中每个技能的流程和校验都落实；应有脚本/工具的能实际运行，无工具依赖的不会伪装执行成功。
6. 已有生成、审查、自动化、汇报和业务地图的结果与保存行为保持一致；模型任务取消/重试/版本快照可验证。
7. 中断、文件冲突、依赖缺失和迁移回退可恢复；迁移失败时原功能仍可运行。
8. 浅/深主题、搜索聚焦、下拉等宽、长文本预览及空态沿用现有统一组件。
9. 实施提交前同步相关文档，按仓库要求运行 build/lint/test；本方案阶段仅核对清单与设计，不运行无关整套构建。
