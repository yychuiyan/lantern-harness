# 全局插件

来源：[`src/lib/builtin-plugin-catalog.ts`](../src/lib/builtin-plugin-catalog.ts) 的 `GLOBAL_PLUGIN_CATALOG`（决策清单「做」）。

- **策略**：平台默认能力目录；插件页「全局」Tab 展示，多数无用户开关。
- **实现层**：本文件为规格说明；**不等于**已全部实现。与扩展/`tb-*` 有重叠的在「Lantern Harness 映射」注明。
- **扩展插件**（可开关，另见 `plugins.ts`）：`cases` / `knowledgeLib` / `requirements` / `templates` / `testReports`（侧栏库入口与内容根）以及 `caseGen` / `knowledgeGen` / `knowledge` / `memory` / `todos` / `tasks` / `projects` / `iterations` / `pmRequirements` / `bugs` / `reports` / `testStats` / `caseExec` / `caseExecution` / `uiAuto` / `reqBreakdowns` / `dashboard` / `pluginDev` — 对应 `lh-kb`、`lh-memory`、`lh-project-docs`（含 `/__tb_test_reports`）、`lh-todos`、`lh-tasks`、`lh-pm`、`lh-reports`、`lh-stats`、`lh-case-execution`、`lh-uiauto`、`lh-req-breakdown-library` 等。`caseGen`、`testReports`、`reports`、`uiAuto` 均由插件按业务类型自动使用默认技能，页面不提供手动挂载；`caseGen` 还可按需求自动读取需求拆解库最新 XMind 与匹配的业务地图系统，只向提示词注入业务规则和流程，不注入登录凭据。`uiAuto` 准备「自动化生成与执行」「自动化项目创建」技能；旧 `Playwright提示词.md` 只作为迁移来源，项目骨架种子在 `.lantern/config/uiauto/skeleton/playwright-ts.json`，插件种子指纹在 `.lantern/local/plugin-prompts.json`。

- **用例执行扩展边界**：`caseExecution` 对应 `lh-case-execution` 与 `/case-execution/`，API 前缀为 `/__tb_case_run`，默认关闭。它复用 `用例管理/` 中的 `.xlsx` / `.csv` / `.md`，逐条执行 AI 浏览器用例；`.xls` 要求先另存为 `.xlsx`。页面不显示重复标题，文件切换使用顶部可搜索下拉，测试地址与登录态默认收进可展开的执行配置，用例表使用整页宽度。顶部紧凑统计栏汇总总数、已执行、未执行、通过、未通过、阻塞、跳过和执行率；已执行不包含待验证，历史 P / F 会按通过 / 不通过统计。列表的「执行结果」列垂直居中，状态胶囊可直接点击切换并自动保存；右侧「缺陷地址」列在存在链接时显示「打开缺陷」并新窗口跳转。点击用例行会打开“用例详情与执行结果”统一抽屉，原始字段均可编辑；字段采用无额外卡片的扁平双列布局，实际结果后紧接缺陷地址，长文本默认两行、自动增高且无内部滚动。文本停止输入约 0.6 秒或失焦后自动保存，状态下拉与缺陷地址同样自动保存，成功后重新读取文件并刷新表格。文件缺少「缺陷地址」列时，首次保存会安全追加该列；其他未知字段仍拒绝写入。缺执行列时其他已有字段仍可编辑，执行列补齐后才出现完整结果控件。模型工具只操作本次目标站点，通过页面快照、点击、填写、选择、按键、等待、截图、控制台和网络取证；单条运行有停止入口和 SSE 日志。AI 执行结束后页面自动保存运行结果；写前备份到 `用例管理/备份列表/`，只更新已存在的表头并用文件哈希拒绝旧结果覆盖新内容。运行记录、日志和截图保存在 `.lantern/local/case-execution/`，不进入用例文件。失败或阻塞可从页面进入缺陷工作台，不自动提交；统计同步先预览，已有同日手工记录必须明确覆盖；统计同步兼容历史 P / F 等状态。Codex 通过 `lantern_case_execution_*` 使用同一 API 和当前空间技能，MCP 写入仍保留显式确认工具。

- **需求拆解库扩展边界**：`reqBreakdowns` 对应 `lh-req-breakdown-library` 与 `/requirement-breakdowns/`，默认关闭。需求分析保存 `sourceExport` 时生成实际平铺文件 `需求拆解库/*.xmind`，列表元数据放在隐藏目录 `.lantern/local/requirement-breakdowns.json`；内容目录不出现 JSON 或内部分组层级。旧版嵌套目录和可见 JSON 首次读取时自动无损迁移。不保存 XMind 内容快照。列表支持搜索筛选、手动上传、历史补录、标题 / 备注修改、系统默认程序打开和移入废纸篓删除。文件可在 Lantern 外直接编辑，读取时以磁盘现状为准。插件不准备新技能，复用需求分析与原文结构提取；关闭需求分析后仍可独立管理。Codex 通过 `lantern_requirement_breakdown_*` 工具读写同一份数据，所有写入使用 `expectedRevision`。

- **业务地图扩展边界**：`businessMap` 对应 `lh-business-map` 与 `/business-map/`，默认关闭，数据保存于当前空间的 `业务地图/业务地图.json`。系统详情只保留「功能目录 / 业务流程」：目录和功能使用真实菜单驱动的树结构，支持搜索、手工 CRUD、拖拽移动/排序和级联删除确认；业务流程保留纵向步骤、角色、参与系统、输入输出、下一步、分支和承载功能。系统卡片桌面端一行两列。复制配置会复制名称（追加副本后缀）、说明、入口、源码目录、文档范围、识别范围和完整登录方式配置，但不复制目录、功能、流程、提案、历史、资料、浏览器登录态、Cookie 或 localStorage。采集器同时识别标准 ARIA 菜单和自定义 SPA 侧边导航，保留 DOM 顺序与缩进层级并提供给 AI 作为权威菜单清单。AI 助手使用右侧宽抽屉，先基于菜单与页面生成目录/功能草案，用户确认应用后再基于已确认功能识别流程；生成不写图，应用才落盘且不会删除草案未包含的已有内容。会话、日志、进度和草案落盘到 `.lantern/local/business-map/assistant/`，关闭窗口后后台继续运行，SSE 可重新连接。Codex 可通过 `lantern_business_*` MCP 工具直接读写同一份地图，并通过 `lantern_business_assistant_*` 启动、等待、停止和应用 AI 草案；所有写入继续受 `expectedRevision` 保护。默认只读系统页面，文档/本地资料/源码按用户要求附加；模型凭证只在运行内存中使用。系统新建/设置支持原生目录选择及无需登录、账号密码、SSO/接口和手动验证码登录，凭据独立保存在本机用户配置目录，不进入地图或模型输入。旧版 `analyses` 任务、提案和发布字段仅为数据兼容保留，新 UI 不再创建或展示。

- **业务地图 MCP 扩展**：Codex 还可用 `lantern_business_login_*` 检查登录方式 / 登录态并基于已保存配置启动、完成或取消验证，用 `lantern_business_material_*` 列出、上传和删除本地 Word / Excel / Markdown / XMind / PPTX 资料。登录工具不接收密码，资料上传受 25MB 限制。

## session-checkpoint-policy

- **分类**：会话 / 存储
- **作用**：会话检查点策略。
- **状态**：部分就绪（含恢复 UI）
- **Lantern Harness 映射**：[`session-persist.mjs`](../lh-plugins/session-persist.mjs) → `.local/checkpoints/<sessionId>-latest.json`；侧栏「从检查点恢复」；`GET /__tb_sessions/checkpoints[/:id]`

**行为**：活跃会话消息数 ≥ 2 且为 10 的倍数时，写入最近 80 条消息检查点（含 goal/todos）；侧栏可确认后覆盖当前消息恢复。

**说明**：无多版本时间线，仅 latest。

## session-log-deepseek

- **分类**：会话 / 存储
- **作用**：DeepSeek 侧增量无损会话日志请求扩展。
- **状态**：部分就绪（本机 JSONL）
- **Lantern Harness 映射**：[`session-log-deepseek.mjs`](../lh-plugins/session-log-deepseek.mjs) → `POST /__tb_sessions/log` → `.local/session-log/<id>.jsonl`

**行为**：每轮对话成功结束后追加一行 `{ messages: [{role,content,reasoning_content?}] }`（DeepSeek 可回传形态）。

**说明**：非远端 DeepSeek 官方会话仓；仅本机增量备份，失败静默。

## session-persistence-jsonl

- **分类**：会话 / 存储
- **作用**：会话以 JSONL 持久化。
- **状态**：部分就绪

## session-query-sqlite

- **分类**：会话 / 存储
- **作用**：会话全文/结构化查询（sqlite）。
- **状态**：部分就绪（sqlite + JSON 回退）
- **Lantern Harness 映射**：[`session-query-sqlite.mjs`](../lh-plugins/session-query-sqlite.mjs) → `.local/session-query.sqlite`；`GET /__tb_sessions/query`；侧栏仍可用 [`session-query.ts`](../src/lib/session-query.ts) JSON 回退

**行为**：会话 PUT 时同步 sqlite 索引（标题+正文）；侧栏搜索优先走 sqlite LIKE，失败则线性扫 JSON。

**说明**：依赖 Node `node:sqlite`（22.5+）；CJK 用 LIKE（非 FTS5 分词）；不可用时自动回退 JSON。

## 插件仓库与空间技能

侧栏提供独立「插件仓库」一级菜单，其中整合扩展插件、MCP 和技能；提示词管理菜单、页面、内容库插件和对应后端文档 API 均已移除。

空间技能由 `builtin/session/space-skills.mjs` 提供注册、原文迁移、版本、资源交换和启停；技能按独立名称与描述管理，旧规则变体收在技能内部。已有插件配置通过稳定的 `legacyPath` 解析到技能正文。插件通过 `pluginRefs` 标记关联业务；已关联技能默认启用且不可停用，未关联自定义技能可独立启停。插件开关本身不删除技能，保留共享技能与数据。空间基础规则常驻。MCP 管理与凭据位置保持原边界，技能不自动授权工具或执行导入脚本。

后台业务复用原执行器；业务地图任务记录技能标识、版本和内容指纹，并在任务开始后固定规则正文。

## Lantern MCP Server

`lantern mcp` 以 stdio MCP 把 Lantern 当前空间暴露给 Codex。当前提供空间、技能、需求分析列表 / 读取 / 保存 / 删除、需求拆解 XMind、用例执行单条运行与写回、业务地图读写 / 登录 / 本地资料 / AI 识别、缺陷规则 / 草稿 / 提交 / 回执，以及外接 MCP 通用发现与调用。Bridge 通过现有 `/__tb_*` API 读写同一份数据空间，不复制业务规则，也不通过浏览器操作 Lantern 页面。

Codex 采用委托推理：Lantern 提供技能正文、原文、存储与校验，Codex 根据上下文生成结构化故事和测试点，再调用保存工具落盘。已有分析以内容 revision 做服务端并发校验，页面和 Codex 的更新不会互相静默覆盖；已停用技能不会进入自动上下文。接入方式见 [`Codex-MCP集成.md`](./Codex-MCP集成.md)。

## 缺陷提交插件

`defectSubmit` 默认关闭，开启后显示 `/defect-submit/`。独立中间件为 `lh-defect-submit`，API 前缀为 `/__tb_defect_submit`。入口与执行平台解耦：任务会携带 `platform` 和目标定位，由 AI 选择与目标平台匹配的连接器；腾讯文档、JIRA、禅道等都只是入口，不能默认使用腾讯文档。当前随包已实现腾讯文档 SmartSheet 的字段识别和提交适配，复用当前空间已有的 `tencent-docs` MCP 配置查询子表、字段、选项和关联记录，并按记录 ID 回读核验；其他平台接入对应连接器后可沿用同一规则与工作台流程。

`GET /context` 返回目标、模板、映射和上下文版本。`POST /inspect` 只读发现目标，`POST /rules/save` 保存规则，`POST /rules/delete` 删除规则，`POST /draft` 校验并保存草稿，`POST /submit` 提交指定草稿版本。`GET /receipt?id=...` 回读回执，`GET /drafts` 列出本空间记录。Codex 通过对应的 `lantern_defect_rule_*`、`lantern_defect_drafts` 与草稿 / 提交 / 回执工具使用同一 API。插件停用时 API 返回 403。

草稿绑定当前空间、目标配置、字段结构和模板版本。提交使用持久化占位文件避免并发或重复创建，写入结果不确定时保留 pending。只有回读字段一致且取得自动编号时才返回 submitted。支持文本、单多选、关联记录、数字和复选框字段。其他入口支持复制草稿。模板和提交记录保存在当前空间 `.lantern/local/defect-submit/`。

缺陷模板管理页为 `/defect-submit/templates/`。`GET /templates` 读取命名模板和 selectedId，`POST /select-template` 按 id 选择。保存模板可传 templateId 编辑已有项，省略则新建。旧 target.json 自动作为默认模板读取。

缺陷提交页面仅展示所选模板信息。点击「提交」携带模板快照到我的工作台任务卡，输入缺陷描述或更新要求后，由 AI 根据 `platform` 选择与目标平台匹配的连接器，定位、新建或更新缺陷并回读核验。模板在独立页面管理。

缺陷规则现使用 `/defect-rules/` 卡片管理页，新建和编辑在右侧面板进行。当前迭代只在卡片底部维护，编辑抽屉内不重复显示；下拉选中值以带箭头的胶囊显示，点击后打开搜索菜单。该列表仅由用户手动维护，不从目标表识别结果自动灌入；输入新名称回车即可新增，每行可改名或删除，变更立即保存且不触发卡片编辑。标题下平台名称右侧展示字段数和必填数。目标字段「迭代版本」自动使用当前迭代，字段默认值显示为「取自当前迭代」，AI 不再重复询问。支持链接识别与手动字段，每个字段保存 rule 填写口径、defaultValue 独立默认值、required 和 source 来源；默认值控件内联在字段标题行，说明使用悬停提示，窄屏时回落到标题下方。选项和关联值使用当前平台要求的稳定标识，多值使用标识数组。图片字段使用目标平台上传后取得的 image ID 数组；附件字段仅在连接器支持上传和回写时填写，非必填的图片 / 附件没有材料时留空且不阻塞提交。rule 是 AI 必须执行的判断或生成口径，严重程度、优先级等字段只要规则提供标准，就应根据事实判断并说明依据；defaultValue 只在没有用户值、材料证据或 rule 结果时兜底。通用规则引用其他文档、知识库页面或目标平台记录时，AI 先读取并核对其中的项目、测试分项目、经办人和迭代映射，再填写对应字段。整理重现步骤时，账号密码、登录账号、权限和特定数据准备等前置内容统一放到末尾「前置条件：」编号列表，不能混进操作步骤或编造账号密码。单选和多选字段可在规则编辑抽屉中修改选项显示名；自动识别字段可通过 `optionLabels` / `hiddenOptions` 在规则内改名或隐藏，手动字段的选项列表直接保存在规则中，删除即移除，所有调整都不回写远端入口。草稿未提供字段时自动套用默认值，显式值优先。`POST /rules/save` 保存规则，允许手动规则暂不配置链接。旧 /templates API 和历史模板数据继续兼容。

`POST /__tb_defect_submit/rules/delete` 按 id 删除空间内规则，前端通过 ConfirmDialog 二次确认。同步更新 selectedId 和兼容配置，空规则列表保持为空，避免旧配置再次迁入。当前规则上下文以规则列表的 selectedId 为准。
