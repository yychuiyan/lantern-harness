# 操作手册

界面从左到右为：左侧导航（功能入口）→ 中间内容区（工作台 / 内容库）→ 底部「设置」。首次使用请先完成模型配置。

| 区域     | 内容                                                                                                                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 左侧导航 | 新建空间默认有「我的工作台」「提示词管理」「帮助中心」；提示词管理固定在帮助中心上方、不参与分组排序，其余内容库开启插件后才出现用例管理 / 知识库管理 / 需求文档库 / 测试模板库（可自行建分组） |
| 底部设置 | 通用设置与模型（BYOK）配置                                                                                                                                                                      |
| 帮助中心 | 版本日志 / 操作手册 / 安装手册，以及「问题与建议」外链                                                                                                                                          |

## 模型配置（BYOK，自带密钥）

点击侧栏底部「设置」→「模型」→「+ 添加模型提供商」，填入任意 OpenAI 兼容接口：

| 预设     | Base URL                                            | 模型示例         |
| -------- | --------------------------------------------------- | ---------------- |
| DeepSeek | `https://api.deepseek.com/v1`                       | `deepseek-flash` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus`      |
| OpenAI   | `https://api.openai.com/v1`                         | `gpt-4o-mini`    |
| 自定义   | 任意 OpenAI 兼容端点                                | 任意模型名       |

- 可添加多个提供商；在输入区右侧「模型 / 推理等级」菜单中切换，打开菜单时会实时请求端点 `GET /models` 刷新候选模型。
- 推理等级：**Low**（响应更快，适合简单问答）／ **High**（默认，质量与速度均衡）／ **Max**（最深推理，适合复杂分析）。
- 通用设置中可指定「子代理模型」，默认跟随主会话模型。

> 模型名以设置弹窗自动识别的下拉列表为准（来自 `GET /models` 的实时返回）。例如 DeepSeek 的 `deepseek-chat` / `deepseek-reasoner` 已于 2026-07 停用，当前可用型号为 `deepseek-flash`（V4.1 Flash）。
>
> **安全提示**：Key 仅保存在本机（本地服务写入 `.lantern/local/app.config.json`，静态站回退浏览器 localStorage），不上传任何服务器，也不会进入仓库。请勿在公共电脑上使用；请勿把 Key 写入任何会被提交的文件。

## 我的工作台

侧栏进入「我的工作台」。空会话居中展示品牌与标志语「提灯的人不问路」，并隐藏会话标题与「对话 / 回合 / 记忆」Tab；发出首条消息后顶栏与 Tab 出现。

### 会话与工作区

- 「新会话」创建空对话；无消息的空会话在切换走时会被丢弃。
- 会话可置顶、重命名、归档、软删除；永久删除仅对已归档会话开放。标题由首条消息经模型自动生成短标题。
- 顶部搜索框可按工作区 / 会话标题 / 消息内容检索。
- 会话按工作区文件夹组织；输入区可切换 / 添加本地工作区，模型读写文件即落在该工作区。

### 对话 Tab

- 流式回复；思考与工具步骤在时间线中折叠展示，点击可展开全文。
- 每条助手消息显示用量与耗时（模型用时、工具用时、TTFT、TPS）；「+」→「会话统计」可查看整会话摘要。
- 生成中「发送」按钮变为「停止」；离开底部时会出现「回到底部」悬浮按钮。
- 有一体服务时，回合可在服务端继续跑，刷新 / 切页可重连；手动停止展示「已停止」。
- 上下文过长时自动摘要压缩；也可用「+」→「压缩」手动压缩以上对话。

### 输入区

输入框下方工具栏：

| 位置 | 控件            | 说明                                                             |
| ---- | --------------- | ---------------------------------------------------------------- |
| 左   | `+`             | 添加面板：文件、目标、计划、扩展插件、（指令）压缩、会话统计     |
| 左   | 工作区          | 显示当前目录，可切换 / 添加工作区                                |
| 左   | 访问权限        | 仅可查看 / 工作区内修改 / 完全权限；圆点表示本地文件服务是否在线 |
| 右   | 模型 · 推理等级 | 切换提供商、模型与推理等级                                       |
| 右   | 发送 / 停止     | 生成中为停止，空闲为发送                                         |

- `+` →「文件」添加本地附件（文本、Excel、Word 转正文附件）；也可直接粘贴图片或本地文件路径。
- `@` 引用知识库 / 模板 / 工作区文档（可继续输入关键词过滤，↑↓ 选择，Enter 确认），引用的文档随消息发送。
- 输入末尾 `/` 唤起已启用的面板型插件；未启用会提示先到「我的插件」打开。
- Enter 发送；生成中 Cmd/Ctrl+Enter 按通用设置选择的「排队发送」或「插话发送」执行。

### 回合 Tab

- 按轮次列出用户 / 助手摘要，可展开查看完整正文（不含思考）。
- **从此处继续**：截断到该轮末，切回「对话」，填入「请从第 N 轮继续」并自动发送。待回复或生成中时按钮不可用。

### 记忆 Tab

需先启用扩展插件「会话记忆」。见下文「会话记忆」。

### 计划模式、目标与定时

- **计划模式**：`+` →「计划」进入。探查阶段模型只读不改，先给出方案（`submit_plan`），批准后才实施；输入区显示「计划模式·探查中 / 已批准」胶囊，可随时退出。
- **目标**：`+` →「目标」设置本会话的长期任务目标；目标写入系统提示，模型可读写并按目标驱动多轮续跑。
- **定时提醒**：模型可创建定时任务，到点以系统通知与消息回到原会话。
- **子代理 / 工作流**：模型可按需派生子代理并行执行子任务（子代理模型见通用设置）。

## 内容目录约定

磁盘目录与侧栏 / 文案一致，均为**中文**。文件即数据：放入对应目录并 push，构建后上架；本地服务下也可在界面里增删。

| 目录          | 用途                                 |
| ------------- | ------------------------------------ |
| `需求文档库/` | 需求文档（`.md` / `.txt` / `.docx`） |
| `用例管理/`   | 生成的测试用例                       |
| `提示词管理/` | 提示词（系统提示词不可删）           |
| `知识库管理/` | 规范 / 方法论 / 环境约定             |
| `测试模板库/` | 用例与报告模板                       |

> 目录**按插件开关懒建**：新建 / 首次选中的数据空间只有隐藏的 `.lantern/` 元数据，启用对应内容库插件后才出现上表目录并补入种子文件；旧版本留下的空目录（只有 `.gitkeep`）会自动收起，已有文件的目录不动。**`提示词管理/` 是唯一例外**：每个空间都有默认提示词，因此该目录与 `默认提示词.md` 会始终铺好。

> 「空间管理」默认展示全部空间：右上角「+ 新增空间」新建并立即写入默认提示词；每行的「编辑」可修改空间名称、提示词要求与默认提示词正文，保存后工作台立即生效。

> 旧版英文目录（`requirements/` / `cases/` / `prompts/` / `knowledge/` / `templates/`）在启动时**自动改名**为上述中文目录，无需手工迁移；若目标目录已存在则不覆盖。

### 整体拷贝 / 扫描纳入

把一份空间文件夹（带 `.lantern/space.json` 清单）整体拷进数据目录后，在「空间管理」点「扫描文件夹」，即可纳入列表：名称以目录名为准，清单里的 id 与已有空间撞车时自动换新。

「空间管理」里的「复制」是另一种做法：在数据目录内**逐文件复制**出一个新空间（含 `.lantern/local` 下的待办、任务、会话、记忆与配置），新空间直接出现在列表里、不需要再扫描。

- 复制会跳过 `node_modules` / `.git` / `.astro` / `dist` 与 `.DS_Store`；也会跳过可重建的派生缓存（`.lantern/local/session-query.sqlite` 及其 `-wal` / `-shm`、`.lantern/local/spill/`），避免拷到写了一半的文件。
- 复制品里的工作区注册表会被改指新目录，所以新空间的「工作区」停在自己身上，而不是被复制的那个空间。
- 有会话正在运行时不允许复制（与切换空间一致，先停止再操作）。
- 复制**不会**自动切过去；切到新空间时页面会重载，待办 / 任务等按新空间的数据重新加载。
- 浏览器本地存储里按空间 id 记的界面偏好（列宽、侧栏展开状态等）不会跟着复制，新空间用默认值。

同一目录里其它**不是空间**的文件夹会在扫描后列出来，勾选并确认才纳入：

- 纳入只把文件夹登记进列表，**不写入 `.lantern/space.json`，也不铺内容目录、不播种子**，文件夹内容保持原样。
- 不勾选直接「忽略」则什么都不做。
- 切换到这类空间时才会写运行时配置（`.lantern/config`、`.lantern/local`，插件开关与会话需要落地），内容目录与文件仍按原样保留。
- 命令行等价操作：`lantern space discover`（列出候选）→ `lantern space discover --adopt <文件夹名>`。

### 侧栏分组即文件夹

侧栏分组会落成空间根下的真实文件夹：分组名就是文件夹名，文件夹里的 `.group.json` 记录分组 id 与成员菜单（子文件夹即子分组）。把整个空间目录拷到另一台机器后，本地服务扫一遍目录即可还原分组，不依赖本机配置。

**组内的内容目录会一起搬进分组文件夹**：把「需求文档库」拖进「文档组」后，磁盘上是 `文档组/需求文档库/`；取消分组再搬回空间根。子分组同理（`父组/子组/用例管理/`）。这样只看文件夹结构就能看出哪份内容属于哪个分组。搬到目标位置时若已有同名文件，不会覆盖，只把冲突条目留在原处并给出提示。

```text
任务空间/
├── 文档组/
│   ├── .group.json          # {"id":"ng_xxx","items":["requirements"]}
│   └── 需求文档库/
├── 用例管理/                # 未分组的内容仍在空间根
└── 提示词管理/
```

- 只认带 `.group.json` 的目录，空间里其它随手建的文件夹不会被当成菜单分组。
- 内容目录按「分组内优先、其次空间根」解析，所以把整份空间拷过来后（配置可能还没生成）也能直接读。
- 每个菜单项都带图标，可在三点菜单的「选择图标」里从内置图标中更换；图标不随分组变化而消失。
- 删除分组时，组内内容目录先搬回空间根；目录里还有用户放的其它文件时，会保留目录、只移除分组关系。
- 首次识别到内容目录（有文件，或已被分组引用）时，自动打开对应的管理插件（用例 / 提示词 / 知识库）；之后尊重手动关闭。

```text
用例管理/
  # 平铺存放（不再按用例类型分子目录）
测试模板库/
  功能测试用例/  接口测试用例/  性能测试用例/  自动化测试用例/
  功能测试报告/  接口测试报告/  性能测试报告/
知识库管理/
  # 平铺存放；分类写在文档 frontmatter 的 category（测试规范 / 方法论 / 环境约定）
```

### 各库操作

| 库         | 操作                                                                            |
| ---------- | ------------------------------------------------------------------------------- |
| 用例管理   | 双击本地打开；批量删除；「在会话中打开」                                        |
| 提示词管理 | 双击本地打开；删除（系统提示词不可删）；「生成提示词」跳转工作台                |
| 知识库管理 | 双击本地打开；批量删除；「在会话中打开」；「生成知识库」跳转工作台              |
| 需求文档库 | 新建文件夹 / 上传文件（`.md` / `.txt` / `.docx`）；单击预览，双击本地打开；删除 |
| 测试模板库 | 分类浏览；双击本地打开；`.md` 可在线预览与下载                                  |

> 双击本地打开、读写文件依赖本地文件服务（`lantern web` 或 `pnpm dev`）；静态站仅能浏览与下载。

### 测试模板库格式

| 格式             | 行为                                                                   |
| ---------------- | ---------------------------------------------------------------------- |
| `.md`            | 在线上架预览 + 下载（须带 frontmatter）                                |
| `.xlsx` / `.xls` | 按分类上架；读取工作表名与首行表头，列表展示字段摘要；**仅下载**不预览 |
| `.docx` / `.doc` | 按分类上架，**仅下载**（不做在线预览）                                 |

模板库分类共七类：功能测试用例 / 接口测试用例 / 性能测试用例 / 自动化测试用例 / 功能测试报告 / 接口测试报告 / 性能测试报告。

Markdown frontmatter（构建期校验，不合规会构建报错）：

```yaml
---
title: 显示标题 # 必填
category: 功能测试用例 # 必填；模板库七类之一
description: 一句话描述 # 可选
version: '1.0' # 可选
---
```

知识库条目（`知识库管理/**.md`）frontmatter 为 `title` / `category` / `description`，缺省时用 `未命名` / `未分类`，不会中断构建。

## 我的插件

工作台会话栏「新会话」下方点「插件」进入：

- **我的插件**（`/plugins/`）：分「扩展插件 / 会话插件 / 全局插件」三个 Tab（默认打开扩展插件），Tab 标题带数量；点击卡片展开详情。扩展为可配置项，可开关；开关状态存本机。插件随仓库代码发布，不提供远程安装 / 更新。
- 扩展插件按「内容库 / 生成能力 / 记忆与检索 / 待办与效率 / 开发工具」五类分组展示，分类标题带数量，可点击折叠 / 展开；分类与插件注册表的 `category` 字段一致。

| 分类       | 插件         | 新建空间默认 | 说明                                                                                                  |
| ---------- | ------------ | ------------ | ----------------------------------------------------------------------------------------------------- |
| 内容库     | 用例管理     | 关           | 侧栏进入用例库；关闭后入口隐藏，「生成测试用例」一并关闭；磁盘文件仍保留                              |
| 内容库     | 提示词管理   | 开（内置）   | 侧栏进入提示词库，并维护当前空间的「默认提示词」；每个空间都需要，因此常开不可关闭                    |
| 内容库     | 知识库管理   | 关           | 侧栏进入知识库；关闭后入口隐藏，「生成知识库」一并关闭；磁盘文件仍保留                                |
| 内容库     | 需求文档库   | 关           | 侧栏进入需求文档库；关闭后入口隐藏，生成用例时不再引用需求文档；磁盘文件仍保留                        |
| 内容库     | 测试模板库   | 关           | 侧栏进入测试模板库；关闭后入口隐藏，生成用例时不再选用模板；磁盘文件仍保留                            |
| 生成能力   | 生成测试用例 | 关           | 配置类型 / 输出格式 / 需求 / 模板 / 提示词后对话生成用例，写入 `用例管理/`（需本地服务落盘）          |
| 生成能力   | 生成提示词   | 关           | 配置类型后对话生成提示词，质检通过写入 `提示词管理/`（需本地服务）                                    |
| 生成能力   | 生成知识库   | 关           | 配置分类后对话生成规范 / 方法论等，质检通过写入 `知识库管理/`（需本地服务）                           |
| 记忆与检索 | 知识库检索   | 关           | 工作台输入 `@` 引用 `知识库管理/`、`测试模板库/` 与工作区文档                                         |
| 记忆与检索 | 会话记忆     | 关           | 长期记忆 / 项目关键 / 项目日志等记忆轨 + 待确认队列；`.lantern/local/memories/`（需本地服务）         |
| 待办与效率 | 任务管理     | 关           | 侧栏进入任务列表：任务池 / 进行中 / 已完成 / 已关闭，自动汇总任务下待办的数量与完成进度（需本地服务） |
| 待办与效率 | 待办事项     | 关           | 侧栏进入待办列表：筛选、行内改状态、手动增删改；工作台会话可用工具记录同一份待办（需本地服务）        |
| 开发工具   | 插件开发     | 关           | 固定提示词开发扩展插件：先评估并用选项确认，确认后才改代码，完成后并入「扩展插件」（需本地服务）      |

> **新建空间默认开启「提示词管理」，其余插件默认关闭**：每个空间都会带上自己的「默认提示词.md」，因此提示词管理是内置常开项；其余入口与「生成」能力仍要在「我的插件」里按分类手动开启，已有空间也保持原开关。种子文件（默认提示词、模板）不会让其它插件自动打开，只有用户自己放进空间的内容才会触发首次识别。

### 待办事项

「我的插件」→「待办与效率」→「待办事项」开启后，侧栏出现「待办事项」入口（`/todos/`）。

- 数据落在当前数据空间的 `.lantern/local/todos.json`，随空间走、不进 git；切换空间后看到的是各空间自己的待办。
- 字段：待办名称、待办状态（待开始 / 进行中 / 已完成 / 已取消）、紧急程度（重要紧急 / 重要不紧急 / 紧急不重要 / 普通）、所属任务、开始日期、截止日期、结束日期、备注。
- **结束日期是只读派生值**：状态改为「已完成 / 已取消」时自动记为当天（再改其他字段不会刷新）；状态改回「待开始 / 进行中」时清空，界面上显示「待办未完成」。表格行内、抽屉、AI 工具（`todo_update`）改状态都按同一规则处理。
- 新建待办（抽屉与「+ 新增记录」）的**开始日期 / 截止日期默认是当天**，可直接改。
- 「所属任务」从「任务管理」里选（需同时开启该插件），选中后写回任务 id 与任务名称；**已关闭的任务不出现在选项里**。待办关联任务时，任务会从「任务池 / 已完成」被拉回「进行中」（已关闭的不动）；打开待办页时也会对「仍有未完成待办」的已关联任务做同样处理。任务管理开启时，旧数据里只存了任务名的待办会按名称自动补上关联，任务管理关闭时该列显示「任务管理插件未启用」，原任务名不会丢。
- 「待办周期」与「剩余天数」由日期自动算出（含首尾）；未完成且过了截止日期显示「已延期」，存储状态不变。
- 表格按飞书多维表格的方式展示：默认按「待办状态」分组（进行中 / 待开始 / 已延期 / 已完成 / 已取消），每组标题带记录数，点标题可折叠；顶部的分组下拉可切换为「按紧急程度分组」或「不分组」。
- 单元格直接改：点名称 / 所属任务 / 日期 / 备注即可编辑，回车或点空白处保存，Esc 放弃；状态下拉与紧急程度下拉在行内改完立即生效（改状态后会自动换到对应分组）。
- 日期格不再显示系统小日历图标：点一下弹出白色卡片日历（可翻月，底部「清除 / 今天」），选完立即保存。
- 工具栏与单元格里的下拉都是卡片菜单（白底圆角），状态 / 紧急程度用颜色点和选中底色区分，不显示对钩，不会弹出系统原生下拉。
- 每组底部有「+ 新增记录」（手动新增入口）：点开后在组内展开一行，包含全部列（名称 / 状态 / 紧急程度 / 所属任务 / 开始日期 / 截止日期 / 备注；结束日期随状态自动生成，不在这里填）；没有单独的保存 / 取消按钮——填好名称后回车，或直接点页面空白处即自动保存，完全没填内容时点空白处则自动收起，Esc 放弃。顶部「新建待办」会从右侧滑出记录抽屉，按顺序填写名称、状态、任务详情、日期与备注后保存；没有数据时只保留右上角的「新建待办」按钮。
- 抽屉里的「待办状态」整行都可点：点击范围一直延伸到「待办名称」输入框的右边界，胶囊只是选中值的样子，点行的任意位置都会展开状态选项。
- 行尾的展开按钮可用同一个抽屉回看 / 修改整条记录；抽屉里的「待办周期」「剩余天数」是只读派生值，会随日期即时计算。
- 顶部可搜索，并按紧急程度筛选；支持批量删除，行尾「操作」列可删除单条，都会二次弹窗确认；表格右侧列较多时可横向滚动。
- 列宽可拖：把鼠标放到表头字段的右边缘，出现竖线后左右拖即可调整；默认宽度就是设计稿宽度。调过的列宽存在浏览器本地（localStorage），刷新、切换页面后保持，不会写进数据空间。
- 新增行没有任何内容时，点页面其它位置会自动收起；已经填了名称则点空白处（或回车）即自动保存，不再有单独的 ✓ / ✕ 按钮。
- 「我的工作台」对话上方的 Tab 里有「待办」（待办插件开启时，排在「回合」右侧）：默认「全部待办」，按 已逾期 / 今天截止 / 接下来 / 没有截止日期 / 已完成 分桶（今日与其它待办都在里面）；也可只看「未完成」或「已完成」。每行显示待办名称、紧急程度，以及第二行的截止日期、剩余天数（逾期会标红）和所属任务；点左侧圆圈即可标记完成 / 恢复，右上角「打开待办页」跳到完整表格。停在 Tab 上每 15 秒自动刷新，AI 在会话里写入后不用手动刷。
- 输入框左侧「+」→「计划」下面会按插件开关给出「待办」「任务」两个手动入口（对应插件关闭时入口直接隐藏，不会触发新增）：点开后弹出同一张确认卡片，手动入口的最后一个按钮是「提交」。待办分两页：第一页填待办自身字段（名称 / 状态 / 紧急程度 / 开始日期 / 截止日期 / 备注，开始 / 截止默认今天），第二页选「所属任务」并只读展示该任务的名称、状态、紧急程度与起止日期；选中任务后，任务有值的开始日期 / 截止日期 / 紧急程度会自动带到第一页（紧急程度仅在待办未设置时带出），仍可再改。任务没有所属任务，一页填完（名称 / 状态 / 紧急程度 / 开始日期 / 截止日期 / 备注）。填好「提交」直接落库，不经过模型；点「取消」或点卡片外面任意位置（包括切到别的 Tab）只会播放收起动画并放弃这次新增，不会写入待办 / 任务。
- 工作台里直接说「记一条待办：周五前提交测试报告」，AI 会调用 `todo_add`；写入前聊天区会弹出确认卡片，同样分两页（第一页待办字段，第二页选所属任务并带出任务的日期与紧急程度），点「确认新增」才落库；点「取消」或点卡片外面会收起卡片、不写任何数据。查进度用 `todo_list`，完成用 `todo_update`。停在该页时会定时刷新，AI 在会话里写入后不用手动刷新。

### 任务管理

「我的插件」→「待办与效率」→「任务管理」开启后，侧栏出现「任务管理」入口（`/tasks/`）。

- 数据落在当前数据空间的 `.lantern/local/tasks.json`；切换空间后看到各空间自己的任务。
- 顶部六张统计卡片：全部任务、任务池、进行中、已完成、已关闭、需要紧急（重要紧急 + 紧急不重要）。
- 列表字段：任务描述、任务状态、紧急程度、开始日期、截止日期、任务周期、待办数量、完成进度、备注。
- 新建任务的开始日期 / 截止日期默认是当天，可直接改。
- 「任务周期」由开始 / 截止日期算出；「待办数量」与「完成进度」按待办里的「所属任务」实时汇总（待办完成状态变化后自动刷新）。待办事项插件关闭时，这两列显示「待办事项未启用」。
- 状态 / 紧急程度在行内用卡片菜单改；日期点开卡片日历；点任务名称或用行尾展开按钮打开右侧抽屉，可改名称、日期与备注，并看到该任务下已关联的待办。
- 工作台里也可以让 AI 建任务：说「新建一个任务：…」会调用 `task_add`，同样先弹确认卡片（一页：名称 / 状态 / 紧急程度 / 开始 / 截止日期 / 备注），确认后才创建；点「取消」或点卡片外面不会写入。查询用 `task_list`、改字段用 `task_update`、删除用 `task_delete`。
- 删除任务不会删待办，只是解除关联（待办里的「所属任务」变为未关联）。
- 列宽同样可拖表头右边缘调整，与待办页一致；表头、行高、状态胶囊、行尾展开 / 删除按钮的样式也与待办页保持同一套。

### 插件开发

> 需在 Lantern Harness 源码仓库中运行（`pnpm dev` / 本地服务），并能读写项目源码。生成的新插件进入仓库代码，开发服会热更新。

1. `+` →「扩展插件」→「插件开发」（或输入 `/` 选择）：输入框上方出现「插件开发」胶囊，形态与「计划」一致，没有侧边抽屉。
2. 直接在主输入框描述插件需求（做什么、给谁用、希望从哪里进入）后发送：模型先只读评估，再用选择题给出确认项（形态 / 范围 / 命名与入口 / 默认开关）。
3. **确认之前不会改任何文件**；在提问卡片里选定选项并提交后，才按项目插件规范实现，新插件并入「扩展插件」。
4. 开发会话自动切到 harness 源码根（`pnpm dev` 时即仓库根）并设为「工作区内修改」：`src / lh-plugins / config / docs` 都能直接改，`node_modules`、`dist`、`.git` 仍禁写。该目录只是临时占用，**不会**在侧栏「工作区」里新增一条。在已有内容的会话里进入插件开发不会自动新建会话（避免出现重复会话、像输入被吞），需要独立上下文时可先手动「新会话」。
5. 胶囊保持激活时后续消息继续使用同一套固定提示词；点胶囊上的 × 退出（清除本会话的插件开发配置）。

### 生成类扩展（用例 / 提示词 / 知识库）

1. 用 `/` 或 `+` →「扩展插件」打开对应配置抽屉，确认后进入（或复用）空会话，标题保持「新对话」直至首次发送。
2. 抽屉内可增删改类型 / 分类（删除为行内二次确认）；确认后输入区上方显示「已启用 · 配置摘要」，可「改配置」或「取消」。
3. 在主输入框描述素材与要求后发送；结果经质检后写入对应目录，可在「用例管理 / 提示词管理 / 知识库管理」中查看。
4. 生成用例可另选：用例类型、输出格式（Markdown 表格 / Excel / CSV）、需求文档、用例模板、提示词、知识库文档。

> 类型 / 分类与磁盘目录：模板库按分类分子目录（如 `测试模板库/安全测试用例/`）；用例与知识库为**平铺**存储——用例类型体现在文件名，知识库分类写入文档 frontmatter，均不产生子目录。改名不会自动迁移已有文件。

### 知识库检索（@ 引用）

1. 插件库打开「知识库检索」。
2. 在 AI 工作台输入 `@`（可继续输入关键词过滤），↑↓ 选择，Enter 确认；文档会挂到输入框附件区并随消息发送。
3. 构建期写入文档列表，静态站同样可用（读 `/raw/...` 路径）；工作区文件需本地文件服务。
4. 未启用「知识库检索」时，`@` 只列工作区文件，并在菜单里提示启用后可引用 `知识库管理/`、`测试模板库/` 文档。

### 会话记忆

1. 插件页打开「会话记忆」后，工作台出现「记忆」Tab；存储为 `.lantern/local/memories/`。
2. 记忆轨：长期记忆 `MEMORY.md`、项目关键记忆 `KEY.md`（两者注入对话）、项目日志（可直写但不注入），存储层另有用户档案与每日日志。
3. 重要事实先进入「待确认记忆建议」：**采纳**才写入对应轨并注入，**拒绝**则丢弃；可在 Tab 内浏览、手动添加、归档或删除。
4. 「全局规则」页展示工作区 `AGENTS.md` 等规则文件；模型工具：`memory_search` / `memory_read` / `memory_suggest` / `memory_append`。
5. 旧版 `graph.json` 首次启动会尝试迁入用户档案 / 长期记忆。

`.lantern/` 已加入 `.gitignore`，**不会提交到 Git**。

## 权限与本地能力

访问权限三档（输入区左侧切换），离线或静态站下文件与命令类工具均不可用：

| 档位         | 行为                                                 |
| ------------ | ---------------------------------------------------- |
| 仅可查看     | 只提供读取与搜索，不提供写入工具，命令执行不可用     |
| 工作区内修改 | 可在工作区读写；命令执行的工作目录被强制限定在工作区 |
| 完全权限     | 放开工作区外路径与更大范围的命令执行                 |

> 工作区默认是**当前空间目录**。插件开发会把工作区切到 harness 源码根（`pnpm dev` 时即仓库根）：这是唯一允许把「空间上级目录」设为工作区的例外，且只临时占用、不会出现在「工作区」列表里；其它上级目录仍会被拒绝。读不到仓库源码时，先确认是否落在「工作区内修改」及以上。

本地工具（需本地服务）：文件读写与 `glob` / `grep` 搜索、`bash` / PowerShell（含持久会话与后台任务）、网页搜索与抓取、Office 转 PDF（需本机 LibreOffice）、`present` 交付清单、超大结果落盘（spill）、按需加载工作区 Skill；另外会自动加载工作区 `AGENTS.md` / `CLAUDE.md` 并注入当前时间。
