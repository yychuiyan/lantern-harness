# 操作手册

界面从左到右为：左侧导航（功能入口）→ 中间内容区（工作台 / 内容库）→ 底部「设置」。首次使用请先完成模型配置。

弹窗和右侧抽屉打开时会覆盖整页，包括左侧导航；遮罩期间不能切换菜单，关闭弹层后才恢复导航操作。

页面内的新增、保存、删除等操作统一使用顶部 Toast 反馈：浅色 / 深色主题都使用同一套中性卡片，只通过状态点区分结果；成功为绿色、失败为红色、普通进行中提示为灰色。调用方即使只写了“已新建 / 已保存 / 已删除”等文案，也会自动按成功状态显示；失败原因优先使用红色状态点并延长停留时间。

| 区域     | 内容                                                                                                                                                                                                                                                                                                                                           |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 左侧导航 | 新建空间默认有「我的工作台」「插件仓库」「帮助中心」；插件仓库为独立一级入口，提供扩展插件、MCP、技能三类管理，其余内容库与业务能力开启插件后才出现用例管理 / 知识库管理 / 需求文档库 / 测试模板库 / 报告管理 / 业务地图（可自行建分组）；「仪表盘」插件开启后入口出现在侧栏（新空间默认在最前面，已有空间按已保存的菜单顺序追加，可拖动调整） |
| 底部设置 | 通用设置、模型（BYOK）、内置插件目录（默认隐藏「规划中」项，可勾选显示）                                                                                                                                                                                                                                                                       |
| 帮助中心 | 版本日志 / 操作手册 / 安装手册，以及「问题与建议」外链；三页在大屏（≥1280px）下正文右侧带「本页目录」锚点导航（操作手册 / 安装手册按标题，版本日志按版本号），窄屏自动隐藏                                                                                                                                                                     |

## 模型配置（BYOK，自带密钥）

点击侧栏底部「设置」→「模型」→「+ 添加模型提供商」，填入任意 OpenAI 兼容接口：

| 预设     | Base URL                                            | 模型示例         |
| -------- | --------------------------------------------------- | ---------------- |
| DeepSeek | `https://api.deepseek.com/v1`                       | `deepseek-flash` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus`      |
| OpenAI   | `https://api.openai.com/v1`                         | `gpt-4o-mini`    |
| 自定义   | 任意 OpenAI 兼容端点                                | 任意模型名       |

- 可添加多个提供商；在输入区右侧「模型 / 推理等级」菜单中切换，打开菜单时会实时请求端点 `GET /models` 刷新候选模型。
- 推理等级：**Low**（响应更快，适合简单问答）／ **High**（默认，质量与速度均衡）／ **Max**（最深推理，适合复杂分析）。
- 通用设置中可指定「子代理模型」，默认跟随主会话模型。
- 通用设置中可开关「允许抓取私网地址」（默认禁止）：关闭时 `web_fetch` / 搜索结果会拦截 localhost 与私网 IP（含跳转后解析到私网）。
- 每个模型提供商可声明「上下文窗口 / 支持工具 / 支持视觉」：关工具则本回合不注入工具；关视觉则图片只作文字说明发给模型。

> 模型名以设置弹窗自动识别的下拉列表为准（来自 `GET /models` 的实时返回）。例如 DeepSeek 的 `deepseek-chat` / `deepseek-reasoner` 已于 2026-07 停用，当前可用型号为 `deepseek-flash`（V4.1 Flash）。

外接 MCP：在「我的插件 → MCP」添加（或手写当前空间 `.lantern/local/mcp.json`）stdio/HTTP 服务器后，对话里会出现 `mcp__服务器__工具` 形式的工具（见安装手册）。

> **安全提示**：Key 仅保存在本机（本地服务写入 `.lantern/local/app.config.json`，静态站回退浏览器 localStorage），不上传任何服务器，也不会进入仓库。请勿在公共电脑上使用；请勿把 Key 写入任何会被提交的文件。

## 平台版本与更新

「设置 → 通用」底部的「平台版本」显示当前版本，并提供检查与更新：

- **检查更新**：向 npm registry（跟随 `npm config get registry`，读不到时用官方源）查最新版本，结果缓存 30 分钟；检查失败只提示「无法检查更新」，不影响使用。
- **不会自动升级**：发现新版本只在侧栏版本号旁亮小圆点、在设置页显示「更新并重启」，**不会在后台自动安装**；升不升、什么时候升由你点按钮决定。
- **只能显式触发**：服务端更新接口要求带确认标记（`confirm: true`），只有页面上的「更新并重启」会带上；旧版本页面、脚本等顺手发出的请求一律被拒绝，不会把服务停掉。
- **有新版本**：侧栏版本号旁出现小圆点，点圆点直接打开该设置项；点「更新并重启」后服务会停掉、全局安装新版本、再用原端口和数据空间重启，页面轮询等待后显示「已更新到 vX」，可点「刷新页面」。
- **更新进行中**：按钮禁用并显示进度；期间页面请求短暂失败属正常现象，不会弹错误条。
- **更新失败**：显示错误与日志路径（`~/.config/lantern-harness/logs/server.log`），旧版本会自动恢复启动；也可以回终端执行 `lantern update`。
- **源码 / dev 模式**：只提示、不执行更新，请在仓库里 `git pull` 后重新 `pnpm build`；服务重启后若当前标签页还挂着旧构建，切页 / 回到前台时会自动刷新一次跟上当前服务，不用逐页手动刷。**npx 模式**：更新会转为全局安装并重启，之后不再走 npx 缓存。

## 我的工作台

侧栏进入「我的工作台」（`/workbench/`；打开站点根 `/` 也会默认落到这里）。空会话居中展示品牌与标志语「提灯的人不问路」，并隐藏会话标题与「对话 / 回合 / 记忆」Tab；发出首条消息后顶栏与 Tab 出现。

- **Tab 记忆**：在「对话 / 回合 / 待办 / 记忆」之间切换后，刷新或重新进入页面仍停在原 Tab；选择按当前数据空间记在浏览器本地。空会话没有 Tab 栏，自动回到「对话」。

### 会话与工作区

- 「新会话」创建空对话；无消息的空会话在切换走时会被丢弃。
- 会话可置顶、重命名、归档、软删除；永久删除仅对已归档会话开放。标题由首条消息经模型自动生成短标题。
- 顶部搜索框可按工作区 / 会话标题 / 消息内容检索。
- 会话按工作区文件夹组织；输入区可切换 / 添加本地工作区，模型读写文件即落在该工作区。
- 侧栏工作区行点一下展开 / 再点收起（同时把它设为当前文件工作区，其它工作区收起）；收起不会改当前工作区。切换会话时文件工作区跟着该会话的归属走，但同一条会话里手动点选 / 新增的工作区不会被列表刷新拉回去。展开的空工作区显示一行「该工作区还没有会话」，与嵌套会话标题左对齐。

### 对话 Tab

- 流式回复；思考与工具步骤在时间线中折叠展示，点击可展开全文。
- 每条助手消息显示用量与耗时（模型用时、工具用时、TTFT、TPS）；「+」→「会话统计」可查看整会话摘要。
- 生成中「发送」按钮变为「停止」；离开底部时会出现「回到底部」悬浮按钮。
- 有一体服务时，回合可在服务端继续跑，刷新 / 切页可重连；手动停止展示「已停止」。
- 上下文过长时自动摘要压缩（压缩阶段可中断）；也可用「+」→「压缩」手动压缩以上对话。

### 输入区

输入框下方工具栏：

| 位置 | 控件            | 说明                                                             |
| ---- | --------------- | ---------------------------------------------------------------- |
| 左   | `+`             | 添加面板：文件、目标、计划、扩展插件、（指令）压缩、会话统计     |
| 左   | 工作区          | 显示当前目录，可切换 / 添加工作区                                |
| 左   | 访问权限        | 仅可查看 / 工作区内修改 / 完全权限；圆点表示本地文件服务是否在线 |
| 右   | 模型 · 推理等级 | 切换提供商、模型与推理等级                                       |
| 右   | 发送 / 停止     | 生成中为停止，空闲为发送                                         |

- `+` →「文件」添加本地附件（文本、Excel、Word `.docx` / 旧版 `.doc` 转正文附件）；也可把本地文件**拖进输入框**，或直接粘贴图片 / 本地文件路径。`.doc` 需本地服务（`lantern web` / `pnpm dev`）才能解析。
- `@` 引用知识库 / 模板 / 工作区文档（可继续输入关键词过滤，↑↓ 选择，Enter 确认），引用的文档随消息发送。
- 输入末尾 `/` 唤起已启用的面板型插件；未启用会提示先到「我的插件」打开。
- Enter 发送；生成中 Cmd/Ctrl+Enter 按通用设置选择的「排队发送」或「插话发送」执行。

### 回合 Tab

- 按轮次列出用户 / 助手摘要，可展开查看完整正文（不含思考）。
- **从此处继续**：截断到该轮末，切回「对话」，填入「请从第 N 轮继续」并自动发送。待回复或生成中时按钮不可用。

### 记忆 Tab

需先启用扩展插件「会话记忆」。见下文「会话记忆」。

### 计划模式、目标与定时

- **计划模式**：`+` →「计划」进入。探查阶段模型只读不改，先给出方案（`submit_plan`），批准后才实施；输入区显示「计划模式·探查中 / 已批准」胶囊，可随时退出。相位与待批方案会写入会话，刷新或切回后仍在（跨刷新无法续接当时挂起的 tool 调用，批准只恢复「已批准」相位）。
- **目标**：`+` →「目标」设置本会话的长期任务目标；目标写入系统提示，模型可读写并按目标驱动多轮续跑。
- **定时提醒**：模型可创建定时任务，到点以系统通知与消息回到原会话。
- **子代理 / 工作流**：模型可按需派生子代理并行执行子任务（子代理模型见通用设置）；可用 list / status / await / abort / message 查看与中断。
- **分叉会话**：侧栏菜单「分叉会话」复制当前对话到新会话，与子代理 `fork_subagent` 无关。
- **持久终端**：模型可用 `bash_session_*` / `pwsh_session_*`（含 write / signal）跨调用保持 cwd；后台任务可用 `job_output` 的 `tail` 读末尾日志。

## 内容目录约定

磁盘目录与侧栏 / 文案一致，均为**中文**。文件即数据：放入对应目录并 push，构建后上架；本地服务下也可在界面里增删。

| 目录          | 用途                                                    |
| ------------- | ------------------------------------------------------- |
| `需求文档库/` | 需求文档（`.md` / `.txt` / `.docx` / `.xlsx` / `.csv`） |
| `用例管理/`   | 生成的测试用例                                          |
| `提示词管理/` | 旧版规则迁移与兼容备份；用户维护入口统一为技能页        |
| `技能管理/`   | 空间技能包、流程、资源和版本；运行时规则从这里读取      |
| `知识库管理/` | 规范 / 方法论 / 环境约定                                |
| `测试模板库/` | 用例与报告模板                                          |
| `报告管理/`   | 功能 / 接口 / 性能测试报告成品                          |
| `业务地图/`   | 各业务系统的功能、流程、证据和 AI 候选提案              |

> 目录**按插件开关懒建**：新建 / 首次选中的数据空间只有隐藏的 `.lantern/` 元数据，启用对应内容库插件后才出现上表目录并补入种子文件；旧版本留下的空目录（只有 `.gitkeep`）会自动收起，已有文件的目录不动。`提示词管理/` 只为旧版迁移与兼容保留，不再有页面、侧栏入口或插件卡片；日常请在「插件仓库 → 技能」维护。

> 待办、任务、工作汇报、测试统计、用例执行统计、项目管理的四个插件、人生管理的六张表、业务地图的数据也直接放在空间里，跟侧栏入口对应：`待办事项/待办.json`、`任务管理/任务.json`、`工作汇报/日报 · 周报 · 月报/`、`测试统计/测试统计.json`、`用例执行统计/用例执行统计.json`、`项目列表/项目列表.json`、`迭代管理/迭代管理.json`、`需求管理/需求管理.json`、`缺陷管理/缺陷管理.json`、`自动化项目/自动化项目.json`（挂载 / 生成的项目）、`自动化执行/自动化执行.json`（运行历史）、`业务地图/业务地图.json`、`KR待办/KR待办.json`、`KR任务/KR任务.json`、`Objective目标/Objective目标.json`、`OKR复盘/OKR复盘.json`、`年度计划/年度计划.json`、`人生阶段/人生阶段.json`；人生管理共用的计划类型 / 年度周期 / 人生周期目录配置落在 `.lantern/config/life/计划类型.json`、`.lantern/config/life/年度周期.json`、`.lantern/config/life/人生周期.json`（无侧栏入口、不单独建内容文件夹；首次读取人生管理时落盘种子；旧版 `计划类型/`、`年度周期/` 内容目录会在首次读取时自动迁入）。这些内容目录只在真的有数据时创建，没有数据就保持干净：打开开关、进入页面都不会预建空目录 / 空文件，第一次写入（新增记录、保存汇报文件）时才落盘。旧版放在 `.lantern/local/todos.json`、`tasks.json` 的数据读取时仍能直接看到，第一次写入时自动搬进 `待办事项/`、`任务管理/`；旧版四插件共用的 `项目管理/项目管理.json` 也会在首次读取或打开开关时自动拆到四个目录。

> 「空间管理」默认展示全部空间：右上角「+ 新增空间」新建并立即写入空间基础规则；每行的「编辑」可修改空间名称、规则要求与基础规则正文，保存后工作台立即生效。

> **池根**（放各空间文件夹的那一层）由本机配置记住：产品服务（`lantern web` / npx）用 `dataRoot`，本地 `pnpm dev` 用 `devDataRoot`（未单独配置时回退 `dataRoot`）。两边写成同一路径就共用同一份数据；不同路径则互不影响。用 `lantern init`（可加 `--scope=both|web|dev`）选择或更换；`lantern status` 可同时查看两个池根。空间管理里的「扫描文件夹」只扫**当前进程**所用池根下的目录。

> 旧版英文目录（`requirements/` / `cases/` / `prompts/` / `knowledge/` / `templates/`）在启动时**自动改名**为上述中文目录，无需手工迁移；若目标目录已存在则不覆盖。

### 整体拷贝 / 扫描纳入

把一份空间文件夹（带 `.lantern/space.json` 清单）整体拷进数据目录后，在「空间管理」点「扫描文件夹」，即可纳入列表：名称以目录名为准，清单里的 id 与已有空间撞车时自动换新。

「空间管理」里的「复制」是另一种做法：在数据目录内**逐文件复制**出一个新空间（含待办、任务、汇报、会话、记忆与配置），新空间直接出现在列表里、不需要再扫描。

- 复制会跳过 `node_modules` / `.git` / `.astro` / `dist` 与 `.DS_Store`；也会跳过可重建的派生缓存（`.lantern/local/session-query.sqlite` 及其 `-wal` / `-shm`、`.lantern/local/spill/`），避免拷到写了一半的文件。
- 复制品里的工作区注册表会被改指新目录，所以新空间的「工作区」停在自己身上，而不是被复制的那个空间。
- 有会话正在运行时不允许复制（与切换空间一致，先停止再操作）。
- 复制**不会**自动切过去；切到新空间时页面会重载，待办 / 任务等按新空间的数据重新加载。
- 切换前会先完成当前空间待写的配置；服务端同时校验配置所属空间。切换后才到达的旧请求会被拒绝，不会把上一空间的插件开关或菜单配置写进新空间。
- 浏览器本地存储里按空间 id 记的界面偏好（列宽、侧栏展开状态等）不会跟着复制，新空间用默认值。

同一目录里其它**不是空间**的文件夹会在扫描后列出来，勾选并确认才纳入：

- 纳入只把文件夹登记进列表，**不写入 `.lantern/space.json`，也不铺内容目录、不播种子**，文件夹内容保持原样。
- 不勾选直接「忽略」则什么都不做。
- 切换到这类空间时才会写运行时配置（`.lantern/config`、`.lantern/local`，插件开关与会话需要落地），内容目录与文件仍按原样保留。
- 命令行等价操作：`lantern space discover`（列出候选）→ `lantern space discover --adopt <文件夹名>`。

### 侧栏分组即文件夹

侧栏分组会落成空间根下的真实文件夹：分组名就是文件夹名，文件夹里的 `.group.json` 记录分组 id 与成员菜单（子文件夹即子分组）。把整个空间目录拷到另一台机器后，本地服务扫一遍目录即可还原分组，不依赖本机配置。**分组名和内容根重名时（例如分组也叫「用例管理」），文件夹会自动加后缀避让成 `用例管理 (分组)/`，但侧栏仍显示你取的名字**——展示名记在 `.group.json` 的 `name` 字段里，所以不会再出现「用例管理 (分组)」这种带后缀的菜单。

**组内的内容目录会一起搬进分组文件夹**：把「需求文档库」拖进「文档组」后，磁盘上是 `文档组/需求文档库/`；取消分组再搬回空间根。子分组同理（`父组/子组/用例管理/`）。这样只看文件夹结构就能看出哪份内容属于哪个分组。搬到目标位置时若已有同名文件，不会覆盖，只把冲突条目留在原处并给出提示。待办、任务、工作汇报、测试统计、用例执行统计这类数据目录也一样跟着分组走（`待办管理/待办事项/待办.json`、`待办管理/任务管理/任务.json`、`待办管理/工作汇报/日报/…`、`质量数据/测试统计/测试统计.json`、`质量数据/用例执行统计/用例执行统计.json`）。

```text
任务空间/
├── 文档组/
│   ├── .group.json          # {"id":"ng_xxx","items":["requirements"]}
│   └── 需求文档库/
├── 用例管理/                # 未分组的内容仍在空间根
└── 技能管理/
```

- 只认带 `.group.json` 的目录，空间里其它随手建的文件夹不会被当成菜单分组。
- 内容目录按「分组内优先、其次空间根」解析，所以把整份空间拷过来后（配置可能还没生成）也能直接读。
- 每个菜单项都带图标，可在三点菜单的「选择图标」里从内置图标中更换；图标不随分组变化而消失。
- 分组顺序可调：分组行三点菜单里的「排序」——顶层分组打开侧栏整体顺序（分组之间可拖动），子分组打开所属父组的列表（菜单与子分组各一段，分别拖动）；子分组顺序单独记录，刷新、切换空间后保持。
- 取消分组时，组内内容目录先搬回空间根（分组内菜单的「移出分组」只动这一项）；目录里还有用户放的其它文件时，会保留目录、只移除分组关系。旧版本留下的「清单已删但数据没搬走」的残留文件夹，会在下次读取分组时把数据搬回空间根并清掉空目录。
- 首次识别到内容目录（有文件，或已被分组引用）时，自动打开对应的管理插件（用例 / 知识库）；旧提示词目录只触发技能迁移，不再显示提示词管理插件。

```text
用例管理/
  # 平铺存放（不再按用例类型分子目录）
测试模板库/
  功能测试用例/  接口测试用例/  性能测试用例/  自动化测试用例/
  功能测试报告/  接口测试报告/  性能测试报告/
知识库管理/
  # 平铺存放；分类写在文档 frontmatter 的 category（测试规范 / 方法论 / 环境约定）
```

### 待办事项

「我的插件」→「待办与效率」→「待办事项」开启后，侧栏出现「待办事项」入口（`/todos/`）。

- 数据落在当前数据空间的 `待办事项/待办.json`（放进侧栏分组后跟着走，如 `待办管理/待办事项/待办.json`），随空间走、不进 git；切换空间后看到的是各空间自己的待办。旧版的 `.lantern/local/todos.json` 会在首次读写时自动搬过来。
- 字段：待办名称、待办状态（待开始 / 进行中 / 已完成 / 已延期 / 已取消）、紧急程度（重要紧急 / 紧急不重要 / 重要不紧急 / 不重要不紧急；空值显示「未选择」）、所属任务、开始日期、截止日期、结束日期、备注。
- **结束日期是只读派生值**：状态改为「已完成 / 已取消」时自动记为当天（再改其他字段不会刷新）；状态改回「待开始 / 进行中 / 已延期」时清空，界面上显示「待办未完成」。表格行内、抽屉、AI 工具（`todo_update`）改状态都按同一规则处理。
- **按起止日期自动推状态**：开始日期在未来 →「待开始」；开始日期是今天或更早且未过截止 →「进行中」；截止已过 →「已延期」。读取 / 写入与改日期时都会落库，页面与 AI 读到同一个状态。**在行内或抽屉里手动选过状态后会上锁**，之后改日期不再自动推「待开始 / 进行中」；但只要剩余已逾期（截止早于今天），未结束条目仍会强制标成「已延期」并清掉手锁（避免把截止改回未过期后仍粘在「已延期」）。已完成 / 已取消不受日期推送影响。
- 新建待办（抽屉与「+ 新增记录」）的**开始日期 / 截止日期默认是当天**，未手选状态时默认落在「进行中」，可直接改。
- 「所属任务」从「任务管理」里选（需同时开启该插件），选中后写回任务 id 与任务名称；**已关闭 / 已取消的任务不出现在选项里**。待办关联任务时，任务会从「任务池 / 已完成」被拉回「进行中」（已关闭 / 已取消的不动）；打开待办页时也会对「仍有未完成待办」的已关联任务做同样处理。任务管理开启时，旧数据里只存了任务名的待办会按名称自动补上关联，任务管理关闭时该列显示「任务管理插件未启用」，原任务名不会丢。
- 「待办周期」与「剩余天数」由日期自动算出（含首尾）；未完成且过了截止日期会显示「已延期」，状态也会自动标成「已延期」。
- 表格按飞书多维表格的方式展示：默认按「待办状态」分组（进行中 / 待开始 / 已延期 / 已完成 / 已取消）；分组头整行可点折叠，左侧为箭头 + 状态胶囊 + 紧邻「N 条记录」。顶部的分组下拉可切换为「按紧急程度分组」或「不分组」。**组内与不分组时按修改时间倒序**（最近改过的在前）。**分组方式会记住**：刷新或重新进入页面仍停在上次选的分组，选择按当前数据空间记在浏览器本地。
- 单元格直接改：点名称 / 所属任务 / 日期 / 备注即可编辑，回车或点空白处保存，Esc 放弃；状态下拉与紧急程度下拉在行内改完立即生效（改状态后会自动换到对应分组）。
- 日期格不再显示系统小日历图标：点一下弹出白色卡片日历（可翻月，底部「清除 / 今天」），选完立即保存。
- 工具栏与单元格里的下拉都是卡片菜单（白底圆角），状态 / 紧急程度用颜色点和选中底色区分，不显示对钩，不会弹出系统原生下拉。
- 每组底部有「+ 新增记录」（手动新增入口）：点开后在组内展开一行，包含全部列（名称 / 状态 / 紧急程度 / 所属任务 / 开始日期 / 截止日期 / 备注；结束日期随状态自动生成，不在这里填）；没有单独的保存 / 取消按钮——填好名称后回车，或直接点页面空白处即自动保存，完全没填内容时点空白处则自动收起，Esc 放弃。顶部「新建待办」会从右侧滑出记录抽屉，按顺序填写名称、状态、任务详情、日期与备注后保存；没有数据时只保留右上角的「新建待办」按钮。
- 抽屉里的「待办状态」整行都可点：点击范围一直延伸到「待办名称」输入框的右边界，胶囊只是选中值的样子，点行的任意位置都会展开状态选项。
- 行尾的展开按钮可用同一个抽屉回看 / 修改整条记录；抽屉里的「待办周期」「剩余天数」是只读派生值，会随日期即时计算。
- 顶部可搜索，并按紧急程度筛选；支持批量删除，行尾「操作」列可删除单条，都会二次弹窗确认；表格右侧列较多时可横向滚动。**搜索词与紧急程度筛选会记住**（分组方式同样），刷新或重新进入页面仍是上次的样子，按当前数据空间存在浏览器本地。
- 列宽可拖：把鼠标放到表头字段的右边缘，出现竖线后左右拖即可调整；默认宽度就是设计稿宽度。调过的列宽存在浏览器本地（localStorage），刷新、切换页面后保持，不会写进数据空间。勾选列、行号列与「待办名称」贴左固定，「操作」列贴右固定；横向滚出去之后固定列边缘才出现一条细竖线做区分，滚回左端即收起。横向滚动位置同样会被记住。列表含只读「创建日期 / 修改日期」（本地时分秒）；顶栏「字段」可勾选显示 / 隐藏列（勾选、序号、名称、操作始终保留；含创建 / 修改日期），偏好按空间记在浏览器本地。编辑抽屉底部也只读展示这两项。表格里状态 / 紧急程度等彩色胶囊按文案定宽，不随列宽拉长。
- 新增行没有任何内容时，点页面其它位置会自动收起；已经填了名称则点空白处（或回车）即自动保存，不再有单独的 ✓ / ✕ 按钮。
- 「我的工作台」对话上方的 Tab 里有「待办」（待办插件开启时，排在「回合」右侧）：默认「全部待办」，按 已逾期 / 今天截止 / 接下来 / 没有截止日期 / 已完成 分桶（今日与其它待办都在里面）；也可只看「未完成」或「已完成」。每行显示待办名称、紧急程度，以及第二行的截止日期、剩余天数（逾期会标红）和所属任务；点左侧圆圈即可标记完成 / 恢复，右上角「打开待办页」跳到完整表格。停在 Tab 上每 15 秒自动刷新，AI 在会话里写入后不用手动刷。
- 输入框左侧「+」→「计划」下面会按插件开关给出「待办」「任务」两个手动入口（对应插件关闭时入口直接隐藏，不会触发新增）：点开后弹出同一张确认卡片，手动入口的最后一个按钮是「提交」。待办分两页：第一页填待办自身字段（名称 / 状态 / 紧急程度 / 开始日期 / 截止日期 / 备注，开始 / 截止默认今天），第二页选「所属任务」并只读展示该任务的名称、状态、紧急程度与起止日期；选中任务后，任务有值的开始日期 / 截止日期 / 紧急程度会自动带到第一页（紧急程度仅在待办未设置时带出），仍可再改。任务没有所属任务，一页填完（名称 / 状态 / 紧急程度 / 开始日期 / 截止日期 / 备注）。填好「提交」直接落库，不经过模型；点「取消」或点卡片外面任意位置（包括切到别的 Tab）只会播放收起动画并放弃这次新增，不会写入待办 / 任务。
- 工作台里直接说「记一条待办：周五前提交测试报告」，AI 会调用 `todo_add`；写入前聊天区会弹出**待办快卡**（与「+ → 待办」的完整表单不同）：只需要确认 / 修改待办名称，其余字段按固定规则自动填好——状态「进行中」、开始与截止日期默认当天，日期是**可改的区间**（点开始 / 截止任一日期就能打开日历，改起点晚于截止时截止会跟着挪，反之亦然；AI 明确给出日期时按给出的，例如「周五前」默认开始到截止都是那天）、所属任务默认「日常待办」，这一行也是下拉，可以换成任务管理里已有的任务；任务管理里没有「日常待办」时，选项里显示「日常待办（确认后自动创建）」，点「确认新增」后自动创建（状态进行中、紧急程度重要不紧急、开始日期当年第一天、截止日期当年最后一天；任务管理插件关闭时不关联任务）。紧急程度跟随所属任务，快卡里不再单独填。点「取消」或点卡片外面会收起卡片、不写任何数据，也不会留下一张空任务。快卡只在用户**明确要求记录待办**（「记一下 / 加个待办 / 帮我跟进 / 提醒我周五前完成」）时出现；只是聊天里提到一件事、行程或计划时 AI 不会建待办，也不会弹卡。如果 AI 已经明确识别出要归到哪个任务（例如你说「加到登录模块这个任务下」），会按该任务关联，不再套「日常待办」。查进度用 `todo_list`，完成用 `todo_update`。停在该页时会定时刷新，AI 在会话里写入后不用手动刷新。
- 待办表格里「所属任务」在「紧急程度」左侧：关联了任务时紧急程度显示为任务的紧急程度（单元格只读，换任务会自动跟着变，要改就去任务管理改那个任务）；没有关联任务时仍可在单元格里直接选。按紧急程度筛选 / 分组也按任务带出的紧急程度计算。

### 任务管理

「我的插件」→「待办与效率」→「任务管理」开启后，侧栏出现「任务管理」入口（`/tasks/`）。

- 数据落在当前数据空间的 `任务管理/任务.json`（放进侧栏分组后跟着走，如 `待办管理/任务管理/任务.json`）；切换空间后看到各空间自己的任务。旧版的 `.lantern/local/tasks.json` 会在首次读写时自动搬过来。
- 顶部七张统计卡片：全部任务、任务池、进行中、已完成、已关闭、已取消、需要紧急（重要紧急 + 紧急不重要）。
- **状态 Tab 记忆**：状态栏「全部 / 任务池 / 进行中 / 已完成 / 已关闭 / 已取消」切到哪个，刷新或重新进入页面仍停在哪个；选择按当前数据空间记在浏览器本地。
- **筛选与搜索记忆**：优先级筛选和顶部搜索词也会记住，刷新或重新进入页面仍按上次的条件过滤。
- 列表字段：任务描述、任务状态、紧急程度、开始日期、截止日期、任务周期、待办数量、完成进度、备注。
- 列表默认按修改日期倒序排列（最近改过的任务排最前，同一天再按创建日期倒序）；列表含只读「创建日期 / 修改日期」，顶栏「字段」可显隐；编辑抽屉底部也只读展示。
- 新建任务的开始日期 / 截止日期默认是当天，可直接改。
- 「任务周期」由开始 / 截止日期算出；「待办数量」与「完成进度」按待办里的「所属任务」实时汇总（待办完成状态变化后自动刷新）。待办事项插件关闭时，这两列显示「待办事项未启用」。
- 状态 / 紧急程度在行内用卡片菜单改；日期点开卡片日历；点任务名称或用行尾展开按钮打开右侧抽屉，可改名称、日期与备注，并看到该任务下已关联的待办。
- 工作台里也可以让 AI 建任务：说「新建一个任务：…」会调用 `task_add`，同样直接弹确认卡片（一页：名称 / 状态 / 紧急程度 / 开始 / 截止日期 / 备注），确认后才创建；没有给出任务名称时卡片以空白形式打开。AI 不会先用提问卡片逐项追问字段；点「取消」或点卡片外面不会写入。查询用 `task_list`、改字段用 `task_update`、删除用 `task_delete`。
- 删除任务不会删待办，只是解除关联（待办里的「所属任务」变为未关联）。
- 列宽同样可拖表头右边缘调整，与待办页一致；表头、行高、状态胶囊、行尾展开 / 删除按钮的样式也与待办页保持同一套。顶栏「字段」可勾选显示 / 隐藏列（任务描述与操作始终保留；含创建 / 修改日期），偏好按空间记在浏览器本地。表格里状态 / 紧急程度等彩色胶囊按文案定宽，不随列宽拉长。

### 人生管理

「我的插件」→「人生管理」→「人生管理」开启后，侧栏出现六个入口（交互样式对齐「待办事项」表格）：

| 入口          | 路径                | 数据文件                           |
| ------------- | ------------------- | ---------------------------------- |
| KR待办        | `/life/kr-todos/`   | `KR待办/KR待办.json`               |
| KR任务列表    | `/life/kr-tasks/`   | `KR任务/KR任务.json`               |
| Objective目标 | `/life/objectives/` | `Objective目标/Objective目标.json` |
| OKR复盘       | `/life/reviews/`    | `OKR复盘/OKR复盘.json`             |
| 年度计划      | `/life/year-plans/` | `年度计划/年度计划.json`           |
| 人生阶段      | `/life/stages/`     | `人生阶段/人生阶段.json`           |

计划类型 / 年度周期 / 人生周期目录配置（不单独做侧栏入口、不占内容文件夹）：`.lantern/config/life/计划类型.json`、`.lantern/config/life/年度周期.json`、`.lantern/config/life/人生周期.json`。计划类型人生阶段 / 年度计划 / KR 任务共用，年度周期年度计划与 Objective 共用，人生周期仅人生阶段使用；下拉里可搜索、回车新增，选项右侧改名 / 删除。旧版内容目录首次读取时自动迁入配置目录；人生阶段上旧的「年龄区间」自由文本会吸收进人生周期目录。

- 六个入口共用一个插件开关；数据与「待办事项 / 任务管理」互不关联。目录只在首次写入时创建，可被侧栏分组装进文件夹。
- **关联**：人生阶段可新增多条，字段含阶段名称、**人生周期**（目录下拉，可写「第一辈子(29-34)」这类名称，支持增删改查）、计划类型与进度，并可按人生周期 / 计划类型分组；Objective 可选「年度计划」，选定后同步写入该计划的「关联 Objective」（年度计划侧点击弹出多行框展示胶囊，可点 × 移除，超出高度可滚动；不做下拉勾选）；KR 任务挂 Objective；KR 待办挂 KR 任务；OKR 复盘挂 Objective。删 Objective 会清空下游引用；删年度计划会清空目标上的所属计划；删 KR 任务会清空其下待办的所属任务（待办本身保留）；删人生周期会清空阶段上的周期引用。
- **计划类型**：可在下拉里增删改（搜索框回车新增，选项右侧改名 / 删除）；改名与删除走统一弹窗组件（不用浏览器原生框）；列表按修改时间倒序；新增记录默认空，触发器整格显示「未选择」（普通单选框样式，整格可点；选中后变为目录色胶囊）；删类型会清空引用它的记录上的类型字段。首次打开会种子四条：学习成长 / 工作管理 / 家庭生活 / 副业赚钱。
- **年度周期**：交互同计划类型（搜索、回车新增、选项右侧改名 / 删除）；记录存目录 id、界面显示名称；新增默认空，触发器整格显示「未选择」；删周期会清空年度计划与 Objective 上的引用。首次打开会从已有记录吸收旧文案，没有则种子「当前年」。
- **派生**：KR 待办「待办周期」= 起止日期含首尾天数；KR 任务「待办数量 / 待办情况 / 完成度」由下属待办汇总；Objective / OKR 复盘「关键结果 / 完成度」由关联 KR 任务汇总（复盘未关联 Objective 时完成度显示「—」，不误显 0%）。人生阶段「进度」为可编辑落盘字段，与派生完成度区分。**创建日期 / 修改日期**落盘并在六表可显示（只读，字段配置里可隐藏；默认显示）。
- **空态文案**：目录 / 枚举（计划类型、年度周期、人生周期、季度周期、重要紧急程度等）空值整格「未选择」；外键关联（所属任务、Objective）空值整格「未关联」；分组桶无年度时统一「未设置年度」。
- **状态下拉**（不可搜索）：KR 待办为待开始 / 进行中 / 已延期 / 已停滞 / 已完成 / 已关闭；KR 任务为任务池 / 进行中 / 未完成 / 已完成 / 已关闭；年度计划为进行中 / 未完成 / 已完成。KR 任务 / KR 待办「重要紧急程度」四档（重要紧急 → 紧急不重要 → 重要不紧急 → 不重要不紧急）同样不可搜索，下拉不提供「未设置」，空值整格显示「未选择」（普通单选框样式），新建默认空。Objective「季度周期」空值同款。有状态的列表默认按状态排序（进行中靠前、未完成居中、已完成沉底），同状态再按创建时间升序。
- **其它下拉可搜索**：所属任务 / 所属目标 / 任务类型（同计划类型目录）/ **季度周期**（Objective 字段；KR 任务 / 待办 / OKR 复盘表头为「季度周期」，只读展示关联 Objective）/ 计划类型 / **年度周期**（年度计划、Objective 选目录 id，展示名称；KR 任务 / 待办 / OKR 复盘表头为「年度周期」，只读展示关联 Objective）等。触发器与菜单项超长时省略号截断，悬停用 `OverflowHint` 气泡看全文。Objective 已绑年度计划后再改「年度周期」且与该计划不一致时，会自动清空年度计划关联。
- **字段显隐**：六张表顶栏「字段」可勾选显示 / 隐藏列（勾选框、标题、填充列、操作列始终保留；含创建日期 / 修改日期），偏好按表记在浏览器本地；列宽存储键已升到 v11。KR 任务列表不含「AI 点评」列。表格里状态 / 优先级 / 计划类型等彩色胶囊按文案定宽，不随列宽拉长。
- 新建 KR 待办的开始 / 截止日期默认当天，备注可在行内一并填写；新建 OKR 复盘时「经验收获」预填三段提纲（做得好 / 不够好 / 下次更好），可改写；标题为空时选 Objective 会建议「目标名 复盘」；年度周期 / 季度周期 / 完成度只读跟随所属目标。六表均支持：**分组**（人生阶段按人生周期 / 计划类型；其余按状态 / 年度等，可切换「不分组」）、分组方式按表记在浏览器本地。六张表无状态时默认按**创建时间升序**；有状态的表（年度计划 / KR 任务 / KR 待办）先按状态（进行中 → 未完成 → 已完成等），同状态再按创建时间升序。六张表均支持：**多选批量删除**（默认显示组内序号，与分组展开箭头对齐；悬停或已有勾选时序号列换成复选框）、**行内新增**（对齐待办事项：组底 / 表底「+ 新增记录」或顶栏新建弹出输入行，回车 / 点空白保存，Esc 取消；**右侧抽屉只用于编辑已有记录**）、搜索、**列宽拖拽**（鼠标放到列名右边缘出现竖线后左右拖，与待办事项相同；按表记在浏览器本地）与删除确认；无手动刷新按钮（后台静默轮询）。KR 待办 / KR 任务顶部的状态筛选同样按表记住。分组头对齐飞书多维表：整行可点展开 / 收起（箭头旋转、内容行淡入）；左侧为箭头 + 浅色圆角胶囊 + 紧邻「N 条记录」，嵌套子组仅缩进、不套描边卡片；按状态 / 重要紧急程度等**单层**分组时**空组也保留**（组底可新增）；**嵌套分组**（Objective「年度 → 季度周期」、KR 任务「年度 → 状态 / 重要紧急程度 / 计划类型」、KR 待办「年度 → 状态」）**只展示有数据的子组**（空子组不占行）。**列表完全为空时不显示「+ 新增记录」**，用顶栏新建。六表**默认不分组**（真正平铺，不显示「全部目标 / 全部计划」这类伪分组头）；选了分组方式后按所选展示，嵌套时一级 / 二级同款扁平头、二级仅多一层左边距。KR 任务 / KR 待办表头相关列用竖线分簇（单行字段名，非双行成组框）；状态筛选用下拉，顶栏左侧显示状态条数分布。表头与列宽拖拽仍对齐「待办事项」。抽屉内下拉菜单宽度跟随字段触发器。只读完成度列用细进度条 + 百分比；人生阶段进度为「色条 + 滑块」合一控件。单元格过长用溢出气泡，不用悬停 `title`。

### 项目管理

「我的插件」→「项目管理」下有四个独立插件：**项目列表**、**迭代管理**、**需求管理**、**缺陷管理**，新建空间默认全部关闭。后三个依赖「项目列表」：开启任一子项会自动打开「项目列表」，关闭「项目列表」会连带关闭另外三个。

- 四类数据各自放在当前空间对应的目录里：`项目列表/项目列表.json`、`迭代管理/迭代管理.json`、`需求管理/需求管理.json`、`缺陷管理/缺陷管理.json`，文件里是 `{ version, items }`（需求 / 缺陷另带 `seq`）。目录固定挂在空间根，不随侧栏分组移动；**只有真的有数据时才创建**，没有数据不会铺空目录。切换空间后看到各空间自己的数据。页面每 8 秒静默刷新一次。旧版四插件共用的 `项目管理/项目管理.json` 会在首次读取（或打开开关）时自动按实体拆到四个目录，拆完删除旧文件。
- 状态枚举沿用 luckytask：项目 `规划中 / 进行中 / 已归档`；迭代 `规划中 / 进行中 / 已完成`；需求 `待评估 / 待开发 / 开发中 / 测试中 / 已完成 / 已取消`（优先级 `紧急 / 高 / 中 / 低`）；缺陷 `待确认 / 待修复 / 修复完成 / 待验证 / 验证通过 / 已取消`（严重程度 `致命 / 严重 / 一般 / 轻微`）。
- **缺陷状态流转**：`待确认 → 待修复 → 修复完成 → 待验证 → 验证通过`，任何阶段都可以改「已取消」。AI 改完并自测通过后**只推进到「待验证」**；「验证通过 / 已取消」由你验证后再定。项目详情页的「缺陷完成 %」= （验证通过 + 已取消）÷ 缺陷总数。旧数据里保存的「修复中」读取时按「修复完成」、「已关闭」按「验证通过」显示，不用手工改文件。
- **级联规则**：删项目会连带删掉它的迭代、需求与缺陷（确认弹窗里有说明）；删迭代只把需求 / 缺陷的「所属迭代」置空；删需求只把缺陷的「关联需求」置空。迭代、需求、缺陷本身都保留。把迭代改挂到别的项目时，原项目下关联它的需求 / 缺陷会解除迭代关联；把需求改挂到别的项目时，原项目下关联它的缺陷会解除需求关联。
- **编号**：需求 `REQ-001`、缺陷 `BUG-001` 由服务端按顺序分配；删掉某条后编号自动顺延（后面的整体前移），不留空洞。编号只是展示用的序号，记录之间靠内部 id 关联，顺延不影响已建的关联关系。
- **筛选记忆**：四个看板的状态 / 项目 / 迭代 / 优先级 / 严重程度筛选与搜索词都按当前数据空间记在浏览器本地，刷新、重新进入页面或切回同一空间时保持上次的筛选；项目或迭代被删掉后，失效的筛选值会自动回到「全部」。
- **项目列表**（`/pm/projects/`）：卡片显示项目名首字、状态徽标、描述与「N 迭代 · N 需求 · N 缺陷」，右下角显示需求完成度；顶部可按状态筛选、搜索，卡片三点菜单提供「编辑 / 归档（或取消归档）/ 删除」。**点卡片（或卡片上的箭头）进入项目详情二级页** `/pm/projects/detail/?id=<项目 id>`：页头是返回按钮 + 项目名 / 描述 / 状态，下面用「迭代 / 需求 / 缺陷」三个页签切换当前项目的数据，可直接新建、改状态、编辑与删除；关闭「项目列表」插件后详情页同样不可用。
- **迭代管理**（`/pm/iterations/`）：按项目与状态下拉筛选，卡片显示「项目 · 开始 → 截止」、时间进度条与百分比；未完成且过了截止日期会标出逾期天数，未到期显示还剩几天。行内可「开始 / 完成」、编辑或删除；结束日期不能早于开始日期。列表列宽可拖表头右边缘调整，勾选相关列与操作列可固定，列宽与横向滚动位置按空间记住。
- **需求管理**（`/pm/requirements/`）：表格列 ID / 需求描述 / 优先级 / 需求状态 / 所属项目 / 所属迭代 / **创建日期 / 修改日期**（只读，本地时分秒）；顶部用状态胶囊（全部 / 待评估 / 待开发 / 开发中 / 测试中 / 已完成 / 已取消）筛选，状态下拉可在行内直接改。右侧抽屉可改所属项目、迭代（按项目联动）、需求描述（多行）、优先级、状态、备注与附件；编辑已有记录时抽屉底部只读展示创建 / 修改日期。附件支持上传文件 / 图片、拖拽或直接粘贴截图（可多张），抽屉里显示缩略图 / 文件名，点 X 单个移除，切换项目时会清空不属于新项目的迭代。分页与「测试统计」一致（每页条数可选，首页 / 末页）。表头可拖列宽，ID / 需求描述贴左固定、操作贴右固定，列宽与横向滚动位置按空间记住。顶栏「字段」可勾选显示 / 隐藏列（ID、需求描述、操作始终保留；优先级 / 状态 / 项目 / 迭代 / 创建与修改日期可关），偏好按空间记在浏览器本地。
- **缺陷管理**（`/pm/bugs/`）：表格列 ID / 缺陷标题 / 严重程度 / 缺陷状态 / 所属项目 / 所属迭代 / **创建日期 / 修改日期**（只读）；**默认按创建时间倒序排列**（新建的在最前，所以编号通常是倒着看的），顶部用状态胶囊筛选，另可按项目、迭代、严重程度筛选与搜索；状态可行内改。抽屉只填缺陷描述（第一行自动作为列表标题）、附件与备注，另可关联同一项目的需求；编辑已有记录时抽屉底部只读展示创建 / 修改日期。附件支持上传文件 / 图片、拖拽或直接粘贴截图（可多选），落到当前空间的 `缺陷管理/附件/`（归进侧栏分组后跟着走），可单个移除，删除缺陷时一并清理。点缩略图 / 文件名在页内放大预览（开合有淡入淡出）；**Esc 先关预览，再按一次才关抽屉**。新建未提交就关抽屉时，已填内容会按空间暂存在浏览器里，再点「新建缺陷」可接着填（有草稿时不清理已上传附件）；创建成功后清空这份草稿。分页与「测试统计」一致（每页条数可选，首页 / 末页）。表头可拖列宽，ID / 缺陷标题贴左固定、操作贴右固定，列宽与横向滚动位置按空间记住。顶栏「字段」可勾选显示 / 隐藏列（ID、缺陷标题、操作始终保留；严重程度 / 状态 / 项目 / 迭代 / 创建与修改日期可关），偏好按空间记在浏览器本地。
- **AI 工具**：项目 / 迭代 / 需求 / 缺陷各有一组 `list / add / update / delete`（共 16 个，名称为 `pm_project_*` 等）。可以让 AI「把登录需求挂到 v1.0 迭代」「把这条缺陷改成待验证」；写操作直接落库、不弹确认卡片，执行前 AI 会用 `list` 拿真实 id。计划模式下只允许查询，写入会被拦截。项目 / 迭代 / 需求也支持直接传名称，系统先精确、再忽略大小写匹配。

### 工作汇报

「我的插件」→「待办与效率」→「工作汇报」开启后，侧栏出现「工作汇报」入口（`/reports/`），插件自动使用工作汇报技能并管理当前空间的汇报目录。

- **打开插件**：准备「工作汇报」关联技能（已存在时不覆盖，保留用户改过的内容）。`工作汇报/日报 · 周报 · 月报` 目录**不预建**，等真正写入汇报文件时才出现。
- **工作台注入**：插件开启期间，发送消息时会把**当前关联的那份技能**追加到系统提示词里，用于把零散记录整理成日报 / 周报 / 月报等。工作台在进入页面时读取一次，所以换完技能后「去工作台写汇报」或刷新页面即生效。
- **关闭插件**：侧栏入口隐藏，工作台不再注入；**技能保留**（改过的内容不会丢），已生成的汇报文件与目录也保留。重新打开还是原来那份，不会按模板覆盖。
- **自动技能**：页面顶栏不再显示技能选择器。插件开启时自动准备并使用「工作汇报」技能；如需修改规则，到「插件仓库 → 技能」编辑。
- **汇报列表**：侧栏「工作汇报」页按「日报 / 周报 / 月报」三个 Tab 展示各自目录里的文件。单击卡片选中，双击用系统默认程序打开；没有汇报时只显示一句「保存到…后会自动出现在这里」。文件就是数据：手工放进目录，或让 AI 按关联技能约定存盘，刷新即可看到。
- **删除汇报**：卡片右侧垃圾桶可删单篇；顶栏「全选本页」+「批量删除」可一次删多篇（也可单击卡片勾选）。删除前会二次确认，确认后从当前类型目录里移除对应文件（不可恢复）；切 Tab 会清空勾选。
- **Tab 记忆**：切换成周报后刷新、关掉页面再进来，仍停在周报（月报同理）；选择按当前数据空间记在浏览器本地，换空间后各记各的。
- **去工作台写汇报**：点页面右上角「去工作台写汇报」，会把当前 Tab 带进工作台并挂上「生成日报 / 生成周报 / 生成月报」胶囊；直接发送即按插件默认技能写一份，点胶囊上的 × 可取消。
- **本期工作数据**：发送汇报胶囊时，会按区间把当前空间已开启的待办、任务、测试统计与用例执行统计拼进消息。区间口径、累计执行基线和日报 / 周报 / 月报边界沿用既有规则；空间里已有的自定义技能正文不会被种子覆盖。
- **修改技能**：到「插件仓库 → 技能」找到工作汇报技能，编辑规则、流程或资源；也可在技能详情里查看版本并恢复。改完重新进入工作台生效。
- 开关、关联技能与汇报目录都跟当前数据空间走，切换空间后各用各的。

### 报告管理

「我的插件」→「测试技能」→「报告管理」开启后，侧栏出现「报告管理」入口（`/test-reports/`）。

- **目录**：当前空间 `报告管理/{功能,接口,性能}测试报告/`（启用时补三类空目录）。
- **自动技能**：页面不再显示技能关联框。插件开启时准备「功能测试报告 / 接口测试报告 / 性能测试报告」三个技能，并严格按当前报告类型自动使用。
- **在会话中打开**：文件行蓝色按钮新建一条「新对话」并进入工作台（报告不做会话关联）；作曲区只挂报告文件 chip，对应报告技能自动注入本轮系统提示。
- 关闭插件后入口隐藏，磁盘报告与技能保留。

### 测试统计

「我的插件」→「测试统计」→「测试统计」开启后，侧栏出现「测试统计」入口（`/test-stats/`）。

- 数据落在当前数据空间的 `测试统计/测试统计.json`（放进侧栏分组后跟着走，如 `质量数据/测试统计/测试统计.json`）；切换空间后看到各空间自己的记录。**打开开关或进入页面不会预建目录 / 空文件**，第一次添加记录（含空占位行）才铺出 `测试统计/` 与这份 JSON。
- 字段只有三个：**统计日期**（点一下弹卡片日历）、**测试统计维度**（单选彩色胶囊：功能测试用例 / 自动化测试用例 / 接口测试用例 / 测试报告 / 缺陷统计 / 自动化缺陷统计 / 测试计划）、**统计数量**。
- 维度下拉带「查找或创建选项」：输入后回车或点「创建「…」」即可新增维度，新维度会存进这份数据里，下次直接可选；每条记录只对应一个维度。
- **下拉里的维度按创建时间倒序排列，最新创建的在最上面**（刚新建的维度直接出现在第一条）；创建时间会记进数据文件（`dimensionCreatedAt`），即使碰到某个维度的记录被删光，它的位置也不会乱跳。旧数据第一次读取时会按记录创建时间补出这份时间并写回（没用过又没时间的排在最后）。
- **维度可以改、可以删**：在维度下拉里把鼠标移到某个选项上，右侧会出现铅笔（重命名）与垃圾桶（删除）——
  - 重命名：改成新名称并**保留原来的创建时间位置**，引用该维度的记录会一起改名（提示「同步了 N 条记录」）；改成已存在的名称时两边合并成一个。
  - 删除：只允许删**没有任何记录在用**的维度（还在用会提示「还有 N 条记录在用…先改掉再删除」），避免记录指向一个不存在的维度。
- 维度名称较长、列宽放不下时单元格里显示省略号，**鼠标悬停弹出气泡显示完整维度名**（没被截断就不弹）；下拉里的维度同样单行截断 + 悬停预览。
- 点右上角「+ 添加记录」会**立即生成一行并写入 JSON**（还没选维度的空行也算一条占位记录，刷新页面不会消失）；选好维度后它自动变成正式记录。可以连点追加多行，**列表按日期从新到旧排列**（最新的记录在最上面，同一天按创建时间倒序）。
- 单元格改完即自动保存（数量停止输入约 0.6 秒、失焦或回车落库），没有保存 / 取消按钮，行尾只有删除；删除占位行同样会把它从 JSON 里去掉。
- 顶部汇总显示记录数、覆盖维度数与数量合计，并支持按日期 / 维度 / 数量搜索；支持勾选后「批量删除」（二次确认），行尾也可删除单条。搜索词会记住（刷新 / 重新进入页面仍按上次的关键词过滤）。列表默认每页 20 条，可切换每页条数；列宽可拖表头右边缘调整，存在浏览器本地。列表另有只读「创建日期 / 修改日期」；顶栏「字段」可勾选显示 / 隐藏「测试统计维度」「统计数量」「创建日期」「修改日期」（勾选、统计日期、操作始终保留），偏好按空间记在浏览器本地。

### 用例执行统计

「我的插件」→「测试统计」→「用例执行统计」开启后，侧栏出现「用例执行统计」入口（`/case-exec/`）。

- 数据落在当前数据空间的 `用例执行统计/用例执行统计.json`（放进侧栏分组后跟着走）；切换空间后看到各空间自己的记录。**打开开关或进入页面不会预建目录 / 空文件**，第一次添加记录（含空占位行）才铺出 `用例执行统计/` 与这份 JSON。
- 每个项目一张**卡片**：卡头第一行是「勾选框 + 折叠箭头 + 项目名称 + 开始～结束日期」，右侧常驻「N 条统计」「添加统计」「删除整组」；卡头第二行是进度：左边「基线 N · 已执行 X / N」，右边百分比，下面一条全宽进度条（≥80% 蓝 / ≥40% 橙 / <40% 灰）。卡内是**统计日期小表**（统计日期 / 用例总数 / 待执行用例 / 已执行用例 / 当前剩余用例 / 执行比例 / 删除），点卡头可折叠整块表，展开 / 收起带高度 + 淡入淡出过渡（约 200ms）。
- 卡内只填用例总数、待执行用例，**「已执行用例」是只读派生列**（= 用例总数 − 待执行用例），**当前剩余用例**与**执行比例**随之更新（剩余 = 用例总数 − 已执行用例）。只有总数与待执行的老记录打开页面也是对的，不需要逐条补填；只填了总数、待执行还是 0 时按「还没开始」显示 0%，不会误判成全部执行完。
- **一个项目只有一个周期**：在卡头改进度周期（开始 / 结束日期）会**写穿该项目的全部统计记录**，不用逐条改；老数据里周期不一致时，卡头显示最新一条写了日期的记录，第一次改周期后整组就收敛了。结束日期早于开始日期时会提示并且不保存。
- **执行比例按项目累计算**：分母是该项目的**基线**——这个项目**第一条记录**（统计日期最早，同一天取创建时间更早的）的用例总数，而不是本行的用例总数。同一项目每天新增一行时，新行的用例总数往往只是上一轮的剩余量，拿它当分母会把「累计做完了多少」算错。分子是「基线 − 本行当前剩余用例」，所以同一项目越新的行比例越高，比例保留两位小数、最多 100%，剩余超过基线时按 0% 显示。没填项目名称 / 用例总数为 0 的记录当不了基线，读数回落到这一行自己的总数。
- **卡头进度**按「基线 − 该项目最新一条的剩余」算累计已执行，与卡内最新一行同一口径。刚点「添加统计」加出来的行还没填用例总数时不算进度数据点，不会把执行率误抬到 100%。
- 「执行比例」列上行是「百分比 + 已执行 x / 基线」（这里的已执行是**累计值**，与百分比同一口径，右端与下面的进度条右端对齐），下行是全宽细条，按完成度分档着色：≥80% 蓝、≥40% 橙、<40% 灰，一列扫下来就知道哪个项目落后。
- 项目名称是彩色胶囊单选，同样支持「查找或创建选项」：输入新项目回车即创建，之后可直接复用。**下拉里的项目名称按创建时间倒序排列，最新创建的在最上面**（刚新建的项目直接出现在第一条）；创建时间会记进数据文件（`projectCreatedAt`），即使某个项目的记录都删掉了，它的位置也不会乱跳。旧数据第一次读取时会按记录创建时间补出这份时间并写回。
- 下拉里的项目名称**单行显示**：名称太长时截断成省略号，鼠标悬停弹出气泡预览完整名称（与表格单元格同一套）。
- **项目名称可以改、可以删**：在项目名称下拉里把鼠标移到某个选项上，右侧会出现铅笔（重命名）与垃圾桶（删除）——
  - 重命名：改成新名称并**保留原来的创建时间位置**，引用该项目的记录会一起改名（提示「同步了 N 条记录」）；改成已存在的名称时两边合并成一个。
  - 删除：只允许删**没有任何记录在用**的名称（还在用会提示「还有 N 条记录在用…先改掉再删除」），避免记录指向一个不存在的项目。
  - 别名 / 大小写不同的名称需要合并时，先重命名成同一个名称即可。
- 项目名称过长时卡头里同样显示省略号，悬停弹出气泡预览完整名称。
- 点右上角「+ 添加项目」会**立即生成一张空卡片并写入 JSON**（还没选项目名称的占位卡片刷新页面不会消失）；选好项目后它自动变成正式卡片，再用卡头的「添加统计」按天补记录（统计日期默认当天、周期自动沿用整组）。也可以直接用卡头下拉切到已有项目，等同把这一组并过去。
- **卡片与折叠**：卡片按最新统计日期从新到旧排列（最新的项目在最上面），卡内行同样按统计日期倒序；**点卡头任意空白处（或左侧箭头）折叠 / 展开整张卡片**，刚进入页面时默认全部展开，折叠只在本次页面停留期间有效（刷新或重新进入会恢复展开）。
- 单元格改完即自动保存（数字停止输入约 0.6 秒、失焦或回车落库），没有保存 / 取消按钮，行尾只有删除（删掉该行会一并删掉 JSON 里的记录）；卡头的「删除整组」会删掉该项目的全部统计记录（二次确认，项目名称仍保留在下拉里，需要的话在项目下拉里再删）。
- 顶部汇总显示记录数、项目数、已执行 / 基线用例数与整体执行率；**整体执行率与卡头同一口径**：Σ各项目（基线 − 该项目最新一条的剩余）÷ Σ各项目基线，每个项目的基线只算一次、不累加每轮的用例总数，也不会因为某轮把用例总数重填成更大的值而超过 100%。工具条支持「全选本页」与批量删除（二次确认），也支持按项目 / 统计日期搜索（项目名命中保留整卡，只命中行时只显示命中的行，基线仍按整组算），行尾还可删除单条。搜索词会记住（刷新 / 重新进入页面仍按上次的关键词过滤）。分页按**项目**计数（默认每页 20 个项目，可切换每页条数），卡片本身不再有整页横向滚动，窄屏时只有卡内小表横向滚动。卡内小表另有只读「创建日期 / 修改日期」；顶栏「字段」可勾选显示 / 隐藏卡内小表列（勾选、统计日期、操作始终保留；用例总数 / 待执行 / 已执行 / 剩余 / 执行比例 / 创建与修改日期可关），偏好按空间记在浏览器本地。

### 自动化测试

「我的插件」→「测试技能」→「自动化测试」开启后，侧栏出现两个入口：「自动化项目」（`/test-automation/projects/`）管理挂载 / 生成的项目，「自动化执行」（`/test-automation/`）跑用例、看日志与报告。项目页点「进入项目」会跳到执行页并带上该项目，也可以「在会话中打开」按项目目录接着聊。站点根 `/` 仍默认进「我的工作台」；自动化测试需从侧栏进入。

- **项目页**（`/test-automation/projects/`）：卡片流显示项目名、真实目录、框架、来源和最近运行状态。顶部是项目数 + 搜索 +「新建项目」。卡片底部提供进入项目、项目配置和更多菜单；技能由插件自动选择，不再显示项目级技能状态或选择入口。
- 「新建项目」是一个弹窗，先选方式（点卡片直接带进对应流程，也能在弹窗里切换）：
  - **挂载本地项目**：只有一步——「浏览…」调系统原生选目录，也可以直接粘贴 / 输入绝对路径（系统不允许弹窗时照样能挂载），确认后识别框架并挂载；同一个目录重复挂载会切到已有记录。
  - **创建全新项目**：选技术栈 → 填项目名与父目录 → 勾选可选内容 → **检查**（平台体检 + AI 审骨架）→ 看预览的文件清单 → 生成并自动挂载。预览按骨架的目录结构分组展示（`pages/`、`utils/`、`fixtures/`、`tests/smoke/` 这样一层层折起来，目录行右侧汇总「N 个 · 体积」，点目录可收起 / 展开，右上「全部展开」一键还原），不是平铺清单。目标目录必须不存在或为空，已有文件一律不覆盖；写盘后还会按插件口径复核一次，认不出来就整套回滚，不留半成品。
  - **检查这一步看什么**：左栏是实时日志（读骨架 → 结构检查 → 渲染检查 → 目标目录 → 读技能 → AI 分析），每条带时间与阶段，AI 流式输出会边写边滚，底部可展开「AI 原始输出」；右栏上半是平台确定性检查，下半是 AI 按「自动化项目创建」技能给的建议。**只有 AI 建议能勾选**，每条下面列出会动到的文件；补丁只应用到本次生成用的骨架副本。没配模型或没读到关联技能时只跑平台检查。
  - AI 建议的补丁只有四种原子操作：`addFile`（新增文件，可带 `when` 选项条件）、`replaceFile`（整文件替换，必须命中已有文件）、`removeFile`、`setOptions`（增删选项）。模型只输出这些，不直接产出整份骨架。
  - **完成页**（生成成功后）不再让你复制命令：直接给「运行环境」面板，两行步骤是 `npm/pnpm/yarn install` 与对应的 `playwright install chromium`（按项目锁文件自动选包管理器），点「一键安装依赖」串行跑完两步，实时日志滚动、显示已用时，可随时「停止安装」；跑完会按插件自己的识别口径复核一遍，只要运行环境没就绪就标失败并给出原因，可「重试安装」。安装进程在服务端，关掉弹窗也不会中断，回到项目卡片还能看到进度。完成页还有「查看生成过程」。
  - **生成过程留档**：每次生成的检查日志（含阶段与时间）、平台体检与 AI 建议（标出哪几条真的应用了、每条会动哪些文件）、模型原始输出、最终文件清单，会随项目一起写入 `<空间>/自动化执行/<项目名>/生成记录/生成过程.json`（同一项目只留最近一次，重新生成即覆盖）。项目卡片菜单与完成页的「查看生成过程」用弹窗分四个 Tab 回看：过程日志 / 检查与建议 / 文件清单（按骨架目录树折叠）/ 运行环境（安装记录，可当场重装）。手动挂载的项目没有这份记录，菜单里不显示入口。
- 执行页右上角也保留「挂载项目」：在卡片里展开目录面板（不是弹窗，按钮带箭头，再点一次收起），用来快速补挂；没挂载任何项目时面板常驻在空状态下方。首期支持：
  - **Playwright**（`playwright.config.*` 或依赖 `@playwright/test`）
  - **pytest**（`pytest.ini` / `pyproject.toml` / `conftest.py` / 依赖 `pytest`；按依赖自动区分接口与 UI，`requests` / `httpx` 为接口自动化，`selenium` / `playwright` 为 UI 自动化）
  - **Selenium**（Java 的 `pom.xml` / `build.gradle(.kts)` 含 selenium 依赖，或 Node 依赖 `selenium-webdriver` / `webdriverio`）
- **新建项目**（企业级骨架）：见上面项目页的「创建全新项目」，选框架 → 填项目名与父目录（「浏览…」调系统选目录，也可直接粘贴路径）→ 勾选可选内容 → 看预览的文件清单 → 生成并自动挂载。生成的是根级分层：
  - `pages/`（页面对象，`BasePage` 提供导航 / 表格等待 / toast 与 URL 断言，不用 `networkidle`）、`utils/`（`config` 环境变量、`env-loader` 多环境、`logger`、`data-generator` 造数、`api-auth` 接口登录）、`fixtures/test.ts`（注入 `loginPage` / `api` / `trackCleanup`，清理按逆序执行且单条失败不影响其它）、`data/`；
  - 用例只在 `tests/` 下按级别分：`tests/smoke/`（@smoke，P0 主流程）、`tests/regression/`（@regression，P1）、`tests/edge/`（@edge，P2/P3 与边界）、`tests/iteration/`（每个迭代一个文件，`npm run test:iteration`）；
  - **文件夹是归属维度，标签是分级维度**，执行靠 `--grep` 全程生效：`test:smoke` / `test:regression`（同时含 `@smoke`）/ `test:edge` / `test:no-flaky`（`--grep-invert @flaky`）/ `test:last-failed`；
  - 平台出码按用例优先级映射标签：`P0 → @smoke`、`P1 → @regression`、`P2/P3 → @edge`（不双写 `@p0`）；页面对象写根级 `pages/`，spec 里用相对 import（`../pages/LoginPage`）。
  - 可选内容（默认勾登录态 / CI / lint）：`authState`（管理员 + 普通用户两份登录态，先试接口登录、失败退回 UI；生成后**真实挂到 project 上**——`chromium` 默认用 admin 身份，打了 `@user` 的用例只在 `chromium-user` 里跑 user 身份，登录类用例自己用 `test.use({ storageState: { cookies: [], origins: [] } })` 回到匿名；没配 `ADMIN_*` / `USER_*` 时不挂，避免读到不存在的 `.auth` 文件）、`ci`（`.github/workflows/playwright.yml` 门禁 format / lint / typecheck → 冒烟 2 分片 → blob 合并出 HTML；`regression.yml` 每日 02:00 跑 4 分片；Node 版本取 `.nvmrc`，有 `package-lock.json` 用 `npm ci`、没有退回 `npm install` 并告警；勾了 Allure 时结果也作为 artifact 上传；另带 `dependabot.yml` 与 PR 模板）、`lint`（ESLint + Prettier）、`husky`（commitlint + lint-staged + pre-push 跑 `tsc --noEmit`；没勾 lint 时 pre-commit 改跑 typecheck；`prepare` 带 `|| true`，目录还不是 git 仓库时 `npm install` 不会因此失败）、`allure`（`reports/allure-results` + `report:allure`，需本机装 Allure CLI）、`docker`（`Dockerfile` + `.dockerignore` + `Jenkinsfile`，参数化 LEVEL / TEST_ENV，CI 下测试失败也先合并 HTML 再归档）、`webServer`（本地自拉起被测系统，命令取 `WEB_SERVER_COMMAND`；CI 下不启动，直接打已部署环境）。
  - **Node 版本有约束**：根目录生成 `.nvmrc`（`package.json` 的 `engines.node` 同步），CI / 本地都按它对齐。
  - **多环境是默认能力**（不是选项）：`ENV` + `.env.<ENV>`（样板 `.env.test.example` / `.env.uat.example`），加载顺序 `.env.<ENV>` → `.env`（不覆盖已有值）；`ENV=prod` 时必须显式 `ALLOW_PROD=true` 才允许跑，避免误打到生产。账号一律走 `ADMIN_USERNAME` / `ADMIN_PASSWORD` / `USER_USERNAME` / `USER_PASSWORD`，不落仓库（不再生成空密码的 `data/test-users.json`）。
  - 建完自动把「自动化生成与执行」技能关联到该项目（缺失时先准备默认技能），不用再手选。
  - 生成后自己跑 `npm install` 与 `npx playwright install chromium`（插件不代装依赖 / 浏览器内核），**装完把 `package-lock.json` 一起提交**——CI 与 Dockerfile 有锁文件才走 `npm ci` 精确还原。
  - **骨架可改**：骨架就是空间里的一份 JSON——`.lantern/config/uiauto/skeleton/playwright-ts.json`。向导里的选项、生成出来的文件都以它为准，改完刷新页面即生效（新空间缺文件时按内置种子补一份）。新建项目的结构只由这份骨架决定，技能不会自己改它：「自动化生成与执行」只影响生成用例，「自动化项目创建」只影响检查步骤里 AI 给出的建议。种子指纹记在 `.lantern/local/uiauto-skeletons.json`：没人改过会随版本升级，改过则保持原样。
- **项目配置**：卡片底部的滑杆按钮打开一个弹窗，左侧三个 Tab，一个入口管完单个项目的日常设置（「更多」菜单里不再重复这一项）。切 Tab 不会卸载面板，所以未保存的环境改动、正在跑的安装日志都还在。
- **基本信息**：改项目名（只改展示名，目录与历史链接不变），查看真实目录、框架、来源、用例文件数和最近运行时间。底部收着「骨架同步（高级）」折叠区。
  - **骨架同步（高级）**：选技术栈、勾选附带内容、可选填写入 `.env.example` 的地址，点一次「同步骨架文件」就按空间骨架重渲染模板：缺的补上、旧模板更新，同名文件先备份到 `<空间>/.lantern/local/uiauto-scaffold/backup/` 再覆盖。结果行显示「新增 X · 更新 Y · 未变 Z」与备份目录；**不跑检查、不生成过程留档**——要检查和预览请走「新建项目」的向导。

  - 「其它变量」会**按文件里的注释块再分小节**：某个自定义 key 上面紧挨着的 `# 注释`（如 `# SIP 自动应答（UDP）`、`# 签入、内部呼叫`）会显示成小节标题，所以从别的项目搬过来的业务分组不会被压成一长条；连续几条 key 共用一个小节。
  - 变量多时不用一条条敲：「添加变量」右侧的「批量粘贴」可以直接贴一整段 `.env` 片段（带 `# 注释` 也行），面板先显示识别到多少个变量，确认后写入当前环境文件——文件里已有的 key 只覆盖值（保留原行与行尾注释），新 key 连它上面的注释按粘贴顺序追加到文件末尾。

  - 保存**只改你动过的 key**：注释、空行、`export KEY=` 写法与别的变量一个字符都不动；文件里缺的已知 key 追加到末尾。值里有空格或 `#` 时自动加引号，读回来还是原值。`.env.<ENV>` 文件里的 `ENV` 固定成环境名（界面只读），避免文件和选择器打架。
  - 密钥（`PASSWORD` / `TOKEN` / `SECRET` / `API_KEY` / 名字里带这些的自定义变量）保存后只显示「已设置（留空不改）」，接口响应里没有明文；留空保存等于保留原值。
  - 保存前校验：`BASE_URL` 必须以 `http://` 或 `https://` 开头（结尾带 `/` 只提示）；管理员 / 普通用户账号与密码要成对填写；`prod` 环境必须 `ALLOW_PROD=true`，否则不允许保存（项目里的 env-loader 也会直接拒绝运行）。
  - 文件是唯一真相，加载顺序仍是 `.env.<ENV>` → `.env`（不覆盖已有值）；`.env` / `.env.*` 已在骨架的 `.gitignore` 里，面板底部会显示当前文件的真实路径与「还没创建」状态。
  - 执行页运行条在「运行任务」右侧也有「环境」下拉（默认取项目记录的默认环境，「沿用文件 ENV」表示不覆盖文件里的值）：选中的环境作为 `ENV` 传给子进程，只对 Playwright 生效；选择会写回项目记录，下次进来还是这套。任务命令里写死了别的 `ENV`（如 `cross-env ENV=uat`）而面板选的是 dev 时，下拉下方直接提示冲突，因为 shell 里后设的值会盖掉选择器。
  - 切换环境后 `.auth/admin.json` / `.auth/user.json` 里的旧 cookie 通常已失效：面板显示登录态文件数量，点「清理登录态」二次确认后只删这两个文件，不动目录。

  - Playwright / Node：`package.json` 的 `scripts`，筛 `test`、`test:*`、`e2e*`、`smoke*` 这类名字（`lint` / `format` / `--ui` / `--debug` 这类打开界面或会导致挂住的跳过），显示成 `npm run test:smoke`（pnpm / yarn 自动换），执行时透传 `--reporter=list,json,html` 以拿到 JSON 汇总
  - pytest：`Makefile` 里带 `## 说明` 的测试目标（`make smoke`）+ `pyproject.toml` / `pytest.ini` 的 markers（`pytest -m smoke`），解释器按 `.venv` → `uv` / `poetry` → `python3` 自动选
  - Selenium：`pom.xml` 的 `<profiles>`（`mvn test -Psmoke`）；Node 项目退回 `package.json` 脚本
  - 下拉里的任务名统一显示成「**名称（命令）**」，例如 `smoke（make smoke）`、`test:smoke（npm run test:smoke）`；自定义命令没填名称就直接显示命令
  - 下拉右侧的「**配置**」按钮打开运行配置弹窗，命令再多也只在弹窗里滚动，不会把卡片撑高：

    - 上半「自定义命令」：自己写「名称 + 命令」（比如 `uv run pytest -m "smoke or regression"`），在项目目录下**用 shell 执行**，支持引号与 `&&`，可删除；名称可以不填，不填时下拉里直接显示命令
    - 下半「自动发现」：挂载时扫出来的任务，每行显示短名 + 完整命令 + 来源说明（过长自动省略号），可以**修改**（改名 / 改命令，改完标「已改」，命令按原样执行、不再追加框架参数）或**删除**；改动只存差异（`taskOverrides` / `hiddenTasks`），项目配置变了也不串。右上角「**重新扫描**」会立刻重扫项目配置（比如刚在 `package.json` 里补了脚本），有改动时旁边还有「恢复默认」一键清空；删掉（忽略）的任务不留在下拉里，而是排到自动发现列表最后，可逐条「恢复」或「全部恢复」

- **生成**（AI 写脚本）：切到「生成」Tab 后整页铺满（隐藏页面标题、去掉卡片外边距与描边）。布局是左右两栏：左边「需求 / 步骤计划」占满整列全高（300–560px，可拖分隔条调宽）；「需求 / 步骤」标题右侧是一条运行配置摘要（如「无头 · localhost:5173」；可切语言时前缀语言名；相对项目探测值改过时标黄），点开弹层统一改目标语言、浏览器（有头 / 无头）、起始地址与登录态；动作条只留「生成步骤 / 生成代码」与「开始探索」。右边上半是单轨阶段页「过程 → 代码 → 试跑 → 变更」，下半是可拖高 / 收起的「控制台 / 网络」面板（拖到贴底或点中间箭头可收到只剩 Tab 行；点 Tab 会自动展开）。**过程**页直接显示摘要（不再内切摘要 Tab）：按时间线排「步骤说明」→「过程日志」（对齐会话「思考」：默认收起，折叠态一行预览最新动作；截图不进日志）→「探索小结」；顶栏「清空过程」会把这三块一起清掉并落盘；新日志默认贴底跟随，手动往上翻后暂停自动滚、滚回底部再恢复。下半「控制台 / 网络」：工具栏左 Tab、正中箭头一点展开 / 收起，顶边可拖改高度（收起后上拖也能拉开）。运行配置里有「过程截图」开关（默认关）：关掉时不给模型截图工具、工具层也会硬跳过截图、并在 system 提示里追加「不要截图」，右侧也不出图；打开后过程页旁「最近截图」窄栏（约 136px）在模型调用截图工具后更新，点一下页内放大，悬停可点 X 删除，最右侧细条可展开 / 收起整列。**代码**：文件清单与预览、写入。**试跑**：整页验收（状态、日志、草稿 / trace、试跑 / 调试）；尚无步骤 IR 时显示空态说明。**变更**：写入后的 diff。出码成功自动切到「代码」，试跑时切到「试跑」，写入成功切到「变更」。

  - **先出计划、再探索**：需求框高度可拖（输入框下方的小把手，72–420px，按空间记住）。输入需求点左边的「生成步骤」，模型只做测试设计，产出一份「动作 + 目标描述」的计划（不含定位器），可以手动上移 / 下移 / 删除 / 新增 / 改描述（改动 400ms 防抖保存）。**没有步骤时「开始探索」不可点**，避免模型跳过计划直接乱点。
  - **探索时才绑定定位器**：模型真的开一个浏览器把流程点一遍（默认有头，可以围观；也可以切无头），按无障碍快照里的临时 `ref` 操作，每步用 `locator_probe` 把 `ref` 换成定位器并校验「唯一 + 指的就是刚才点的元素」，带 `stepId` 时结果直接回填到左侧对应步骤（状态变「已绑定」并显示 `role=button name="登录"` 这样的摘要；没绑上会写原因）。随后由同一份步骤 JSON 渲染 TS（`@playwright/test`）或 pytest（`playwright.sync_api`）脚本，两种语言共用步骤，换语言只重新出码、不重跑模型。
  - 定位器优先级按官方建议：`data-testid` → `getByRole` → `getByLabel` / `getByPlaceholder` → `getByText` → 稳定属性 → 短 CSS；只能靠长 CSS 或第 N 个同名元素时提示「低置信度」，不承诺全自动自愈。
  - 账号等敏感值写成 `${ENV_NAME}`，出码变成 `process.env.NAME` / `os.environ.get("NAME")`，不会把凭据写进脚本；活动日志里填写 / 选择的值会打码，只保留 `${ENV}` 占位。

  - **草稿工作区**：试跑写在项目内 `.lantern-ai/<会话>/`（目录自带 `.gitignore`，内容为 `*`），结构是 `playwright.config.ts`（继承项目配置，只把 `testDir` 指向 `./draft`）、`draft/<标题>.spec.ts`、`results/`。**跑完不删**：失败现场可以「打开草稿」「打开目录」、看 trace，也可以「调试运行」（`--headed --trace=on`）或「Playwright UI」（长驻进程，面板里给地址，可「结束 UI」；离开页面 / 服务退出会自动结束）。「清理草稿」手动清，超过 7 天的草稿在下次建会话时顺手清掉。
  - 流程分三步、不自动串起来：**生成步骤 → 开始探索 → 生成代码 → 试跑**。探索只负责在浏览器里把流程点一遍并产出步骤；结束后按步骤出码（左栏「生成代码」可手动重出），**不会自动试跑**。试跑在右栏「试跑」阶段页发起：失败时让模型只改步骤（定位器 / 等待 / 断言），最多 3 轮；没配模型就只跑一次、保留日志。页面行为本身不符合需求时保留失败并提示疑似缺陷，不会为了跑绿改断言。试跑页显示状态、耗时、草稿 / trace 路径与调试按钮。
  - 确认路径后再「写入项目」：一条用例会同时产出**整组文件**——主用例（spec）、按页面拆出的 page object（新骨架落根级 `pages/<Page>.ts`，老项目回退 `tests/pages/<Page>.ts`；Python 为 `<pagesDir>/<page>_page.py`）、项目有登录态时再加一个 `<fixturesDir>/auth-state.ts` 常量文件（落点按项目实际目录判定：根上有 `pages/` 就用根级，否则用 `tests/` 下那套）。右栏「代码」阶段左侧是文件清单（标出「用例 / 页面 / 登录态」），右侧预览与可编辑的写入路径，按钮明确写「写入 N 个文件」；路径都在项目目录内、写入前整批预检。**目标文件已存在时默认合并，不整文件覆盖**：spec 只在原有文件末尾追加这个新用例（缺的 `import` 补到 import 区，`test.use` / `BASE_URL` 不重复），page object 只在类里补缺失的方法，登录态文件已有 `STORAGE_STATE` 就不动；合并写不进去（例如文件名撞上别的类）才按冲突处理，整批不写，此时勾选「整文件覆盖」再重试。写盘中途失败会按 before 回滚已写过的文件，不留半套。写入时记录 before / after，右栏「变更」阶段立刻出精确到行的 diff（新增绿 / 删除红 / 3 行上下文，追加的条目标「追加」），并能「打开文件」「打开目录」；下面还有一段只读的「项目工作区其它改动」（`git status`，过滤 `node_modules` / `.lantern-ai` 等噪音）。
  - 写入后点「**按项目配置验收**」：用项目自己的 Playwright / pytest 命令跑正式文件（不再走草稿配置）。若文件被项目 `testMatch` 排除，会明确提示「没被项目配置识别为用例」，而不是笼统判失败。
  - **关联技能**：打开「自动化测试」开关时（以及每次打开「自动化执行」页时补一次），会准备「自动化生成与执行」和「自动化项目创建」两份空间技能，已有内容不覆盖；骨架种子仍写到 `.lantern/config/uiauto/skeleton/playwright-ts.json`。旧版 `Playwright提示词.md` 只作为迁移来源，正文会进入技能包。
  - **自动化生成与执行**分「项目骨架 / 规划阶段 / 探索阶段 / 生成代码」四段，支持按框架使用 `### playwright` / `### pytest` / `### selenium` 子段。日常规则在「插件仓库 → 技能」维护；插件种子升级时同步技能正文并提升版本，用户改过的内容保持原样。
- **自动化项目创建**是骨架评审协议：读取完整文件清单、骨架节选、平台检查结论和本次项目信息，只输出 `{"findings":[...],"notes":""}` 及可选补丁。插件自动使用这份技能，不再由页面挂载。
- **新增技能规则**：在「插件仓库 → 技能」修改或导入技能；业务页面不再提供手动选择器，运行时按插件和业务类型自动解析。
  - **平台约定**：日常在「插件仓库 → 技能」编辑业务规则和流程。运行正文位于技能包，旧规则文件只保留迁移备份；插件种子用于缺失初始化和升级，用户修改不覆盖，升级会提升技能版本。
  - 项目里已有 `auth-admin.json` / `auth-user.json` 会自动当登录态复用（填 `-` 表示不用）。需要验证码 / 2FA 时点「手动登录」：模型会在下一个工具调用前停住，你在已经弹出的浏览器窗口里把登录做完，再点「我已登录，继续」放行；这个按钮只在探索阶段、有头浏览器时出现（规划阶段没有浏览器窗口，不显示）。
  - **登录墙（脚本编排）**：点「确认并探索」时，若项目有登录能力，**必须先拿到 token，再开有头业务浏览器**（避免先跳登录页再二次注入）——① 有 `tests/auth.setup.*` / Playwright `setup` 工程：先跑登录用例；② 否则已配 `LOGIN_API_*`：平台调接口写 `.auth/admin.json`。预获取失败**不会**打开业务浏览器，直接弹三选一。探索中再撞墙会再试自动链；同一轮注入后仍撞墙则只弹窗。登录墙偏好只影响弹窗建议高亮。
  - **脚本编排（当前入口）**：「生成」Tab 进编排列表 → 详情。详情为**左步骤 + 中阶段轨（对话 → 代码）**：步骤卡片偏紧凑；阶段轨是带序号的分段控件；顶栏除绑定进度外，出码 / 试跑结果也会用小徽章提示。会话里规划拆步骤；左侧主按钮只管探索（「确认并探索 / 重新探索」）。**出码在会话里说**：发送「生成代码」或「重新出码」（平台拦截，不经模型手写代码），代码页文件栏也可点「重新出码」。**代码页可直接编辑**正文与路径（相对出码有改动时左侧有圆点，撤销回原文圆点消失；手改会写入会话草稿与记录，「重新出码」会覆盖）。文件清单支持**多选**：可「写入选中」落到项目真实路径（默认与已有文件合并，勾选「整文件覆盖」则整文件替换；已写入的标「已写入」），也可对已写入项「从项目移除」（按本会话变更账本：新建的删除、合并/覆盖的还原写入前内容；无账本的不删）。**底栏运行仍是草稿试跑**，用当前编辑内容：在**项目目录**里调用项目自带的 Playwright / pytest，但 `testDir` 指向本会话 `.lantern-ai/<会话>/draft/`（继承项目配置，不是正式 `tests/`）；日志用 list 输出，完整 stdout 另存 `results/last-run.log`。探索成功后浏览器关闭，不自动出码；出码成功自动切到「代码」。底部日志栏左侧是运行按钮，中间箭头展开 / 收起，顶部分隔条可拖改高度（拖到很矮会自动收起），高度按本机记忆；开始运行会自动展开日志。草稿落在**项目目录** `.lantern-ai/<会话>/`（自带 `.gitignore`），栏上「打开目录」打开该会话草稿文件夹；需要时再「打开用例」看单个 spec。用编辑器打开单文件时会顺带带上项目目录，避免看起来像孤立文件。阶段解锁：对话始终可进；有步骤 IR 后可进代码。探索中阶段锁在「对话」、步骤只读。
  - 重新点「生成步骤」或「开始探索」等于开新一轮：服务端会清掉上一轮的步骤 IR、试跑结果、控制台与网络快照，代码页 / 试跑 / 控制台 / 网络面板同步清空，不会把上一条用例的脚本当成这次的产出。步骤说明与探索活动日志会保留并跟着会话存；本轮控制台 / 网络在关浏览器后仍可回看，直到开下一轮或会话超过 7 天被清掉。
- 步骤计划里只写测试动作，不会生成「截图」步骤；探索时的截图只作为过程记录。步骤 IR 允许 `screenshot` 动作，但关联技能会明确要求不要用它生成脚本步骤。
  - **不合法的步骤会被静默丢掉**：动作不在枚举里，或 `click` / `fill` / `select` / `press` / `hover` / `expect` 没带定位器时，这一步直接不落盘、也不报错。提交步骤的返回里 `stepCount` 报的是**实际保留**条数（被丢掉的会在提示里说明），提交后模型会自己核对，避免出码少步骤。
  - 依赖项目自己装好的 Playwright（或 pytest-playwright），Harness 不额外下载浏览器；草稿放在被挂载项目的 `.lantern-ai/`。
- 数据按项目分目录：`自动化项目/自动化项目.json` 记挂载 / 生成的项目，`自动化执行/自动化执行.json` 记运行历史；每个项目的报告 / 结果 / 原始日志 / 生成记录各在自己的目录里（`自动化执行/<项目名>/报告/`、`结果/`、`日志/`、`生成记录/生成过程.json`），同名项目会自动加后缀；切换空间各用各的。这些目录只在实际写入时才创建，打开插件或进入页面不会预建空目录 / 空文件。
- 工作台输入栏会自动认项目：当前工作区正好是某个自动化项目的目录时，工作区名称旁多一个「自动化项目」入口，可以直接一键安装依赖、查看生成过程，或跳到自动化项目页；别的工作区不显示这个入口。
- 旧版本的 `UI自动化/` 目录与平铺的 `报告/ 结果/ 日志/` 在首次读取时自动改名 / 搬迁到新结构，不需要重新打开插件开关，历史报告链接也不会失效。老数据没有框架字段时按 Playwright 处理。
- 首次运行前请先在项目目录装好依赖 / 解释器：Playwright 项目可以直接用「一键安装依赖」（`npm/pnpm/yarn install` + `playwright install chromium`，服务端串行执行、有日志），其余技术栈（pytest / Selenium）仍需自己装 `pip install` / `mvn`，环境未就绪时卡片上会直接给提示。

### 需求分析

「我的插件」→「生成能力」→「需求分析」开启后，侧栏出现「需求分析」入口（`/requirement-analysis/`）。

- **数据位置**：落在当前数据空间的 `需求分析/需求分析.json`（`{ version, docs, seq, storySeq }`），第一次写入才建目录 / 文件；切换空间各用各的。`需求分析/` 与「项目管理」的那几个目录一样，不会被侧栏当成同名分组目录搬走。
- **来源只读**：「新建分析」与工作台左栏的来源下拉列「需求文档库」里可拆解的文档（`.md` / `.txt` / `.docx` / `.xlsx` 等；不支持的格式置灰说明）；**不会改原文档**。下拉可拆解的排前面，同档按**上传/创建日期新→旧**排序（与文档库「创建日期」同一口径）。
- **历史分析**：详情顶栏「返回列表」右侧用下拉切换已有分析（可搜索；选项第二行显示状态 / 条目数 / 故事数）；同一份来源文档重复选一次会复用已有记录（不会每次新建一份），换一份来源文档才会新建。列表页仍按更新时间倒序浏览全部记录。
- **分步执行**：左栏按顺序点——**拆解需求** → **生成用户故事** →（可选）**生成测试点**。拆解不会自动生成故事。若「用户故事审查」插件开着，**生成用户故事成功后会自动初审**（切到「审查结果」Tab）；左栏不再单独放审查按钮。
- **拆解需求**：需求条目**跟需求文档结构**走，按表头特征播种父级（不是猜文档类型）：① Ideal 行表（`大模块/大类` + `小模块/功能点` + `优化/问题内容/需求描述` 等列名别名）；② 功能规格竖表（`功能名称` + `功能描述`，可兼编号）；③ 需求清单横表（`模块` + `需求内容/需求点`；**不会**把「字段名称 / 字段类型」定义表当成需求）；都没有时再按 Markdown / Word 的 `##`/`###` 章节，最后才用 `【短名】`。表解析出 ≥3 条时优先用表。模型只在父级下补「查询 / 修改」子点与原文摘录，禁止另造文档没有的条目标题；本步不写用户故事。生成用户故事 / 审查 / 测试点仍吃结构化 RO，不必随表头改口径。
- **生成用户故事**：须先**拆解成功**（状态为已拆解）；拆解失败或中断时按钮不可用。**按已整理的查/改需求点**分批生成并挂全 `sourceRefs`（可多点并一条故事，但不得漏 id）；同一点击内再对照原始需求做一次二次卡控补漏。成功后若审查插件开着会自动审查。一条只做一件事；服务端分配 `US-001` 递增编号。生成失败会清空本轮故事，此时不自动审查、不可生成测试点。
- **生成测试点**：须已有成功生成的用户故事；故事为空或仍为「待拆解」时按钮不可用。
- **Tab 顺序**：需求条目 → 用户故事 → 审查结果 → 测试点（默认停在需求条目）。
- **需求条目 Tab**：可展开卡片查看需求点、原文和覆盖故事；可变更需求点、修改原文或删除。拆解需求时会读取「原文结构提取」技能，模型只分组，句子必须来自来源；页签右侧可导出原文 XMind / Markdown。
- **用户故事**：按关联需求点的文档序排列；卡片上来源显示 `RO-id + 标题`（可点到对应子点并展开原文）；字段不全显示「待补全」提示，不刷进审查主清单。
- **用例「引用需求点」**：填真实 `RO-…` id，格式「编号 + 标题/原文」；有测试点清单时在 RO 之后加「；TP-xxx」，用来确定条目内的先后。入库时会去掉误填的 `US-…` / 测试点分组前缀；用于排序与追溯，不影响覆盖判定。
- **长文档分批**：拆解需求仍按 `^##` 章节切段（单批不超过 12k 字）。生成用户故事以需求点批次为主（按父级 / 每批约 12 个子点），原文二次卡控时才按章节切段对照。
- **审查（待确认）**：生成用户故事成功后**自动初审**（一次全量挖待确认）。之后在「审查结果」页点「重新审查」只刷新上轮清单（问题仍在则更新、已改掉则消失），**默认不再扩表**；真要再挖新问题点「重新全量扫描」（已忽略仍不回潮）。还没有报告时可用空态「开始审查」。主清单只报需要人确认的事（需求点未覆盖、原文不清、需业务拍板等），不是「需求缺字段」质检。规则层算覆盖率；模型层只补待确认。故事缺角色 / 异常等改在故事卡提示。
- **缺口操作**：勾选后可「补写选中缺口」（AI 改故事）、「补充」（手动加故事）、「忽略 / 批量忽略」。审查结果页左侧待确认、右侧忽略列表，可恢复或「落成用户故事」；再审查不会把已忽略项灌回。
- **编辑故事**：卡片展开即七段式，可逐段改、增删行、上下移 / 删故事。
- **源文档变了**：指纹变化后提示重新拆解需求；确认后旧故事、体检、测试点与忽略一并清掉，按文档结构重新播种条目。
- **生成测试点**：主链路仍是故事 → 五维测试点；重新生成前会确认。正式点优先，扩展点可标 supplemental。导出 XMind 与原文结构同一套向右逻辑图骨架（折线竖脊、根深蓝 / 需求蓝 / 维度白底细边框，测试点叶子不单独设样式）。
- **关联技能**：工作台不再显示关联技能状态卡，运行时按插件和业务类型自动加载「需求分析」「原文结构提取」「用户故事审查」等技能。日常在「插件仓库 → 技能」维护；旧规则名继续作为兼容路径解析，用户改过的正文不会被种子覆盖，未改动的插件种子会随代码缺省升级并提升技能版本。
- 拆解需求 / 生成用户故事 / 审查 / 补写 / 测试点都走当前配置的模型（BYOK），没配模型时按钮会拦下来并提示先配置。

### 业务地图

「我的插件」→「需求管理」→「业务地图」开启后，侧栏出现「业务地图」入口（`/business-map/`；默认关闭）。

- **数据位置**：当前空间的 `业务地图/业务地图.json`。一个空间管理多个业务系统，每个系统保存功能、业务流程、证据和待审核 AI 提案；只有真正保存数据时才创建目录 / 文件。文件带 `revision`，同一地图被另一个页面改过时会拒绝旧页面覆盖并刷新到最新版本。
- **三个系统视图**：详情顶部将发布状态胶囊放在系统名称右侧，与标题垂直居中；卡片与详情统一使用 24px 高、11px 字号的状态胶囊，待发布为琥珀色、已发布为青绿色。进入系统默认打开「系统概览」，集中查看业务域、流程预览、证据覆盖、人工确认与待完善项；顶部切换「功能目录 / 业务流程」。功能目录负责新建、编辑、删除、筛选和确认功能；业务流程维护纵向步骤、角色、参与系统、承载功能、输入输出、下一步、异常分支和跨系统依赖。流程不使用横向泳道；参与系统、步骤所属系统与跨系统依赖统一用非斜体胶囊显示，步骤标题与系统 / 角色信息分行。
- **系统卡片首页**：卡片展示系统名称、入口、业务说明、发布状态、功能 / 流程数、证据覆盖与业务域；独立底栏左侧显示更新时间或待审核提案数，右侧提供带文字的「系统设置」按钮，可直接维护入口、源码目录和登录配置。点击卡片主体进入系统概览，点击底栏设置不会触发卡片跳转；保存或关闭设置后仍留在当前列表并保留搜索与筛选。系统设置只从卡片底栏进入，不再在系统详情顶部重复显示。首页支持「全部系统 / 待发布 / 已发布 / 待审核」筛选，搜索系统名称、说明、入口、业务域、模块或功能名称，按最近更新或系统名称排序；无匹配时可重置筛选。
- **系统概览**：业务域行进入该域的功能目录，流程预览进入对应流程。待完善项包含提案待审核、功能待确认、缺少证据、未关联流程，点击直接定位对应审核或筛选结果；发布检查单独展示阻断项。证据覆盖 = 有至少一条证据记录的功能数 / 功能总数，不等于证据已经人工核验；空系统显示「—」。人工确认展示已确认功能数 / 功能总数。功能可同时出现在多类待完善项中，各类数量不可直接相加为功能总数。
- **详情页改版**：顶部使用紧凑的系统身份栏，返回入口、图标、名称、发布状态和概况分层排布。「AI 自动识别」是蓝色主行动，副文案说明用于补全业务地图；「发布检查」是带状态的次行动，直接显示阻断数量或检查通过。视图切换使用轻量胶囊 Tab。概览主区使用「业务全景」标题和成对的「新建功能 / 新建流程」入口；业务能力、业务流程、证据覆盖、人工确认四项按 01–04 连成一条横向维护路径，窄桌面自动排成 2×2。业务结构与流程合并在一个连续主面板中，右侧收敛为单一的「下一步」操作栏，集中展示待完善、发布检查与 AI 识别入口。
- **列表布局**：沿用自动化项目布局，页头仅展示图标、标题和说明；工具栏左侧显示汇总，右侧放搜索、排序和新建系统，下方保留状态筛选；卡片网格随视口按 1 / 2 / 3 / 4 列排列，间距 12px，整卡点击进入详情。
- **搜索与卡片密度**：系统列表及功能 / 流程目录搜索框沿用全局 36px 高度、搜索图标、主题配色与聚焦边框（仅外层变色，输入区不重复描边），关闭浏览器历史输入建议；系统卡片采用紧凑间距，数量与指标名称同行，保留说明、业务域和更新时间。
- **页面记忆**：当前系统、系统卡片状态筛选 / 排序 / 搜索、主视图 Tab、功能 / 流程 / 步骤选中项、筛选 / 搜索 / 业务域、详情 Tab 和详情抽屉开关都按数据空间保存在浏览器本地。刷新或重新进入业务地图会恢复上次位置；记录的系统、功能或流程已删除时自动回退到系统列表或第一项。
- **刷新与目录间距**：业务地图样式在首屏加载，数据就绪前使用骨架占位，避免闪出无样式文字或短暂加载文案；目录业务域与功能行之间保留独立间距，悬停和选中状态不会贴合；流程目录序号固定为 22×22px，流程名称使用剩余宽度，不改变序号胶囊尺寸。
- **功能检索**：支持「全部功能 / 待确认 / 缺少证据 / 未关联流程」维护状态筛选，和业务域、关键词组合使用；关键词支持名称、编号、模块、角色与规则。右侧详情跟随可见结果更新，空结果不会继续显示上一次功能。流程搜索没有结果时也不再展示不匹配的旧流程。
- **弹窗与抽屉**：新建系统、系统设置和流程编辑弹窗使用平台浅色 / 深色主题，遮罩与内容面板分离；系统新建 / 设置弹窗使用更宽的桌面布局，源码路径与浏览按钮同行，窄屏自动收边。长表单仅正文滚动，底部操作保持可见。支持 Esc 关闭、Tab 限制在弹窗内、关闭后回焦触发按钮。窄屏选择功能后展开详情。
- **功能详情**：右侧面板分组查看「概览 / 规则与落库 / 实现与证据」，可查看使用角色、入口、输入输出、业务规则、落库口径、关联流程和证据来源。编辑支持异常与待确认、实现说明；未修改的证据保留原 ID、备注和置信度。人工保存后，本次修改字段进入锁定字段；后续重新识别只生成建议，不会静默覆盖。
- **示例地图**：示例系统使用虚构业务数据，入口为 `https://example.com`，流程参与系统与证据标题均标明示例；用于了解维护方式，不代表真实系统取证结果。
- **统一下拉**：业务地图的排序、筛选、承载功能、人工环节、分支状态与识别任务均使用平台下拉组件；菜单与对应字段等宽，选中值和选项超宽时显示省略号，悬停气泡预览完整文本。承载功能支持按名称或编号搜索。
- **流程编辑**：「编辑流程」可修改名称和最终业务结果；「在第 N 步后添加」按指定位置插入，保存后重新编号，数字形式的下一步引用随顺序调整。删除被引用步骤时清空对应的下一步，需要手工补全。新增步骤默认属于当前系统；支持标记异常分支「待补全 / 已连接」。
- **系统登录配置**：已创建的业务系统在「系统设置 → 登录配置」选择「无需登录」「账号密码登录」「SSO / 接口登录」或「手动登录（验证码 / 扫码）」。三种需要登录的方式共用右下角验证操作区，按钮文案分别显示「验证账号密码」「验证接口登录」「打开登录页面」，点击时都会先保存当前配置。账号密码方式可填写登录地址及可选控件选择器，遇验证码或无法匹配控件时保留浏览器窗口；SSO 使用 POST JSON 登录接口，支持完整 URL 或相对系统入口的地址、请求体模板、Token 路径与 localStorage 名称。手动登录点击「打开登录页面」后会跳转到登录地址或系统入口，但不会自动保存登录态；完成验证码、扫码或二次验证并进入业务系统后，需要回到设置面板点击「保存登录态」。登录配置下方会显示验证中、验证成功、等待人工完成或验证失败状态；成功后明确提示自动识别可复用当前登录态。验证码、扫码及二次验证由用户在打开的浏览器完成，不自动绕过。
- **登录配置保存与恢复**：登录配置不再提供独立保存按钮，随系统面板的「保存设置」默认保存；「验证登录」也会先保存当前配置。登录操作的错误统一通过 Toast 提示，不在按钮下重复显示红字。旧后端尚未加载登录接口时，提示重启 Lantern 并禁用不可用的登录操作，不再误报地图版本冲突。登录配置保存不改变业务地图 revision。密码保存后仅以掩码显示，留空保存继续保留原密码；需要更新时直接输入新密码即可，不提供「清除已存密码」入口。更改登录配置或系统入口后旧登录态失效；登录窗口可取消，闲置 15 分钟自动关闭。新建系统先保存，再进入系统设置配置登录。自动识别的「系统登录配置」及等待登录任务中也提供同一入口；保存登录态后，从原任务重试。登录阶段与只读采集分开，采集阶段仍拦截业务写请求。
- **凭据位置与范围**：账号密码与 Cookie / localStorage 登录态放在本机用户配置目录（macOS / Linux 默认 `~/.config/lantern-harness/business-map/auth/<空间路径哈希>/<系统ID>/`；Windows 为 `%APPDATA%/lantern-harness/business-map/auth/…`），按空间与系统隔离，配置与登录态文件权限为 0600。它们不进入地图 JSON、导出、模型输入或识别源码扫描；删除业务系统时同时清理该系统的本机凭据。历史 `loginState` 文件仍兼容，尚未设置新版登录配置时继续读取。
- **切换系统**：进入另一系统时重置搜索、业务域与维护状态筛选，回到系统概览，并使用该系统自己的源码目录与识别范围。
- **AI 自动识别入口**：系统顶部与概览提供「AI 自动识别」，功能详情「AI 补充」预选当前功能。保留手动「新建功能」。识别设置中的「识别目标」把已有功能和待发现功能分开：已有功能使用可搜索的选择器，待发现功能按行输入并以胶囊预览，顶部实时显示目标数量。AI 使用当前模型设置，采集正文会发送给所选模型服务。
- **单选与复选控件**：业务地图页面及弹层内的单选框、复选框聚焦时不额外显示外侧聚焦框，选中圆点与勾选状态照常显示。
- **三个识别范围**：「指定功能」选择或输入 1 个功能，已有功能与待发现功能保持互斥；「多个功能」可组合选择已有功能并追加多个待发现名称；「系统全量」自动发现当前账号和所选资料覆盖的业务。已有功能可定向补证据，新功能无需先手工创建；未识别到指定目标会列在任务说明中，不当作完整成功。
- **取证配置**：可选「系统页面 / 在线文档 / 业务流程 / 需求文档 / 本地资料 / 源码目录」，六类来源可任意组合。页面支持入口和额外 URL；在线文档按一行一个 HTTP(S) 链接读取正文并复用当前系统登录态；业务流程读取当前地图中已维护的流程、步骤、角色、系统和输入输出。需求文档必须逐份选择，不默认扫描整个库。本地资料上传到 `业务地图/识别资料/<系统ID>/`，支持 Markdown、TXT、CSV、JSON、XML、HTML、Word（DOC / DOCX）、Excel（XLS / XLSX）、XMind 和 PPTX；无法解析的文件会保留并列入任务说明。源码目录可直接填写，也可点「浏览…」打开系统目录选择窗口；分析时忽略依赖、构建目录、符号链接和常见密钥文件，并支持填写排除相对路径。
- **后台任务**：「后台任务」查看实际页面、在线文档、需求文档、本地资料、业务流程和源码数量，以及分析批次、模型 token 用量与失败说明；离开或刷新页面不停止识别。可取消任务；服务中断、模型失败、部分采集失败可「从检查点重试」，相同内容与模型 / 技能复用已完成结果。
- **自动草稿策略**：新增功能具有至少两类来源的可验证原文、模型标记为高置信 / 低风险、无异常或字段冲突时，可自动入草稿并标记 AI 来源、尚未人工确认。可取消勾选自动入草稿，使全部候选先审核。更新 / 删除 / 流程变更均待审核；人工锁定字段不覆盖。识别后读取最新地图应用结果，识别期间手工新增的同名功能不会被覆盖。
- **批次撤回**：任务完成后可撤回该批自动新增功能；已经被编辑或已被流程引用的功能会保留，并显示保留数量。撤回仅处理自动新增，不撤回用户审核应用的提案。
- **覆盖与限制**：默认最多 100 个页面、深度 5、30 分钟，可调整页面数（1–300）、深度（0–8）和时间（1–60 分钟）；源码最多 600 文件、单文件 256KB，需求文档单份最多 8MB，本地资料单份最多 25MB，来源正文总计最多 200 万字符。达到限制显示部分覆盖。页面和在线文档采集需要 Chromium；只执行 GET / HEAD 读取，拦截 POST 等写请求、危险 URL、WebSocket 与 beacon。依赖 POST 查询的页面可能无法完整采集，失败会记录而不是模拟结果。系统全量不代表覆盖不可访问角色与隐藏后台规则。
- **本机任务数据**：任务元数据和采集检查点保存在 `.lantern/local/business-map/analyses/`；检查点含来源正文及已完成模型结果，不包含模型 API Key。地图继续使用 `业务地图/业务地图.json`，证据保留来源路径和原文摘录。
- **审核提案**：识别结果按功能 / 流程分组，显示新增、更新、删除、风险、置信度和来源。可展开字段前后差异与来源原文；应用后只进入待发布草稿，删除和高风险项默认不勾选。低风险自动新增会单独在任务结果中统计。
- **发布检查**：顶部「发布」打开检查抽屉，集中列出待审核 AI 结果、未连接分支、缺少承载功能等功能；空流程、缺失或失效的承载功能同样阻断发布；人工环节可不关联功能。有阻断项时不能发布。发布后记录 `publishedRevision`，人工确认字段继续保持锁定。
- **来源边界**：页面记录实际观察结果，在线文档 / 需求文档 / 本地资料记录需求与业务口径，业务流程记录当前已知过程，代码记录实现线索；证据原文与采集 ID 验证失败的候选不进入地图。识别不到内容不等于功能已删除。
- **关联技能**：开启业务地图时准备「业务地图识别」技能，保留既有规则正文和原文件引用；在「插件仓库 → 技能」编辑规则与流程。识别任务启动时固定规则快照并记录技能版本，运行期间的修改影响后续任务。技能处于停用状态时不阻断业务地图识别，任务继续使用当前保存的规则正文。
- **示例地图**：空间里还没有系统时，页面提供「创建示例地图」，用于查看完整的工单受理 / 承办 / 知识库 / 系统设置联动和发布检查；不需要时可删除示例系统。

### 用例质量评审与场景遗漏补全

「我的插件」→「测试技能」→「用例质量评审 / 场景遗漏补全」开启后，不新增侧栏入口，能力长在「用例管理」里：文件行的「评审」列显示上次分数、补全条数与是否过期，右侧「评审」按钮打开评审抽屉。两个插件都跟随「用例管理」默认一并打开，也可单独关掉；关掉后入口隐藏，已生成的报告仍留在磁盘上。

- **抽屉三个 Tab**：质量评审 / 场景补全 / 用例表格。页头显示文件名、对照需求（按文件名自动猜一个，可换）、模型是否就绪与「开始评审 / 重新评审」「停止」「导出 Markdown」。
- **质量评审**：规则 + 模型两层。规则层先在本地算七项量化指标（总数 / 字段完整率 / 步骤可执行率 / 预期可判定率 / 需求覆盖率 / 重复率 / 优先级合规率）与硬伤（标题 / 步骤 / 预期为空或写「同上」、编号重复等）；模型层逐条给五维分（需求覆盖 25% / 步骤可执行 25% / 预期可判定 20% / 数据与边界 15% / 规范完整 15%）与扣分原因、可直接照改的建议。
- **判定怎么来的**：总分 = 各维度得分 × 权重求和；`≥ 85` 可用、`60–84` 待修改、`< 60` 错误无效。模型可以判「错误无效」，但必须给出 `hard` 证据（与需求哪条冲突 / 和哪条重复），只给低分不给证据时按分数算——避免出现「86 分 · 错误无效」这种自相矛盾的结果。规则命中的硬伤模型不能推翻。
- **逐条明细**：每条一行显示判定、编号、标题、得分与「详情」；悬停行时标题右侧出现「修改」，带着编号、扣分原因与建议跳到这条用例绑定的工作台会话（没有会话就新建），由模型按文件表头改原文件；跳转后该条立刻标「已修改」，不再计入「需改」、也不能再点修改。顶部可筛「可用 / 待修改 / 错误无效」、搜索编号或标题、按分数升序，也可点「批量修改」把当前筛选出的待修改项一次交给工作台。展开详情可看五维分与每条扣分原因。**重新评审**：有「已修改」时只重审这些条（按硬伤 + 分数重判，未达 `≥ 85` 仍为待修改 / 错误无效，不会因标过「已修改」就自动变可用）；未改的条保留上次判定；已忽略的永远不送评。无「已修改」时评全部未忽略条。
- **用例表格**：默认六列（编号 / 标题 / 步骤 / 预期 / 判定 / 建议），只读对照，步骤与预期默认两行、超出省略号，悬停看全文；拖动表头右边缘可调列宽。顶栏「字段」可勾选显示 / 隐藏步骤 / 预期 / 判定 / 建议（编号与标题始终保留），偏好按空间记在浏览器本地。判定列与质量评审一致：已交给工作台改的只显示绿色「已修改 xx」，不再叠「待修改 xx」。表格里不放操作按钮，改用例回「用例管理」或到逐条明细点「修改」。
- **场景补全**：专挖人工容易漏的场景，按非功能 / 安全边界与容错 / 兼容性 / 隐藏业务规则四类给出「为什么容易漏 + 建议用例（前置 / 步骤 / 预期 / 优先级 / 归属需求）」；勾选后可先「补全选中」写全字段，再点「去工作台写回」——按归属需求插到对应分组最后一行之后（有编号原样用、没有再补自定义编号；对不上组才落到末尾），写前自动备份到「用例管理/备份列表/」（首次备份时创建，主列表不展示）；写回后该条标「已修改」仍显示在列表，重新探测会去掉已确认写回的场景（角标只计未修改）。场景补全同样有进度日志与停止。备份不自动过期，在工具栏「备份列表」中手动删除。
- **对照需求匹配**：页头按用例文件名猜对照需求分析时，只比「产品前缀 + 版本号」（「版本 / 迭代版本」写法不影响对上）。
- **改完标待验证**：明细里「修改 / 批量修改」跳工作台写回时，会把有「用例状态」列的条目标为「待验证」；对照表只写在对话里，不会另存进用例管理目录。
- **数据位置**：报告存 `<空间>/用例评审/用例评审.json`，按用例文件路径分条；用例文件被改过会把报告标成「可能已过期」，重新评审即刷新。
- **关联技能**：开启时准备「用例质量评审」「用例场景补全」对应技能；已有正文完整保留，日常在技能页修改。仓库 `prompt/` 仅供对照，业务执行沿用既有评审和补写入口。

### 仪表盘

「我的插件」→「仪表盘」→「仪表盘」开启后，侧栏出现「仪表盘」入口（`/dashboard/`；新空间默认在最前面，已有空间按已保存的菜单顺序追加，可在侧栏拖动调整）。

- 首次进入是空白画布：所有卡片默认全部关闭，点右上角「编辑组件」自己挑要显示的卡片（之后布局按空间记住）。
- 页头照 luckytask 的工作台：左侧图标块旁是按当前时间变的问候（早上好 / 上午好 / 中午好 / 下午好 / 晚上好），有逾期待办时在问候后跟一句「N 项已延期」，下面是「2026年10月19日 星期一」格式的日期。
- 纯前端聚合当前空间的待办、任务与测试统计，不新增数据目录；数据仍由各自插件维护，仪表盘只读展示，只有「今日待办」的勾选完成会写回待办。
- 卡片清单：
  - **进行中待办**：状态为「进行中」的待办数量，下方补充「共 N 条待办」。
  - **进行中任务**：状态为「进行中」的任务数量，下方补充「共 N 个任务」。
  - **已逾期**：已过截止日期且未完成的待办数量，有逾期时数字与「需要关注」标红。
  - **待办完成率** / **任务完成率**：已完成 ÷ 可计完成（待办排除已取消、任务排除已关闭 / 已取消）；分母为 0 时显示 0%，带进度条与「已完成 / 总数」。每个指标各是一张独立卡片，不再合并成一张「待办概览」；旧布局里存过的「待办概览」会在读取时自动拆成五张。活跃项目与数据空间也是同样样式的独立指标卡。
  - **活跃项目**：项目管理里状态为「进行中」的项目数量，下方补充项目总数，点卡片进入项目列表（需要同时开启「项目列表」与本地服务）。
  - **数据空间**：当前账号下一共有多少个数据空间，下方标出正在使用的空间名；静态部署 / 服务不可用时显示「—」。
  - **倒计时**：四格数字块显示天 / 时 / 分 / 秒，右上角四格切换终点：**今天**（到今天 24:00）、**下班**（到自己设的下班时间）、**周末**（到下一个休息日，默认 00:00，可改成 18:00 之类）、**今年**（到次年 1 月 1 日 00:00），选择按空间记住。**进页不会自动弹出时间编辑框**：还没手存过时间时，下班按 18:00、周末按 00:00 直接倒计时。第一次点「下班」且尚未保存过下班时间时，会在说明行弹出时间输入框（预填 18:00，回车或点「确定」保存，点「取消」退回原来的终点）；之后按保存的点倒计时。「下班」和「周末」说明行的「修改」都可随时改时分（平时隐藏，鼠标移入这一行才出现），时间按空间记住（浏览器会带秒的写法也会收成 `HH:mm` 再落盘）。过了下班点就停在 0 并写「已经下班啦」，不会自动跳到明天。**当天已是休息日（周末 / 法定节假日；调休补班除外）时，「下班」终点四格全 0，说明改为「今天休息，不上班」**。周末设了非 00:00 的时点后，按休息日前一天的该时点算（下一个休息日是 10-24 周六时，设 18:00 就倒到 10-23 周五 18:00，下班即算进入周末），过了这个点直接显示「愉快」，不用等到周六；设回 00:00 时终点仍是休息日当天 0 点（周六 0 点 = 周五 24 点）。底部一行注明终点，例如「到 2026-10-23 18:00 开始休息」。休息日 = 法定节假日 + 周末，调休补班的周六 / 周日不算（例如 2026-10-10 补班，倒计时直接跳到 10-11 周日）。当天已在休息（周末或假期）时，周末终点显示全 0 并写「周末愉快 / XX 假期愉快」。节假日与调休数据单独放在 `public/cn-holidays.json`（不参与编译，改完刷新即生效），每年国务院办公厅公布次年安排后照通知往 `years` 里加一年即可，逻辑不用动；没有收录的年份按普通周末算。已录入 2026（正式）与 2027（官方尚未公布，只录了法定假日，卡片上会标「2027 年安排待公布」）。
  - **今日待办**：表格展示「开始时间 ~ 截止时间」区间包含今天的未完成待办（只填一端时按那一天算），已过截止日期的「已延期」待办也会留在列表里继续跟进，列为待办名称 / 待办状态 / 所属任务 / 开始日期 / 截止日期，每页 5 条可翻页；点名称前的圆圈可直接标记完成（立即写回待办，完成后会从本卡移出）；状态胶囊只读展示，改状态请到待办页。
  - **进行中任务**：表格展示状态为「进行中」的任务，列为任务描述 / 任务状态 / 重要紧急程度 / 开始日期 / 结束日期，每页 5 条可翻页；结束日期逾期标红。
  - **测试统计**：每个维度把所有统计日的数量**加总**，按合计降序最多 10 个维度；照飞书柱状图带纵轴刻度（居中贴网格线）、横向网格线与柱顶数值，拉高时柱子一起变高。
  - 表格单元格 / 柱状图维度名过长会显示省略号，鼠标悬停出气泡看全称；内容超出卡片高度时卡片内出现细滚动条（表头吸顶）。点进卡片后，若卡片本身没有纵向溢出（例如表格只是横向溢出），滚轮仍滚动整页；卡片内滚到顶 / 底后继续滚也会带动页面。
  - **待办日历**：照飞书日历的日 / 周 / 月视图。跨天待办按「开始 → 截止」展示：周 / 日视图的全天区是一条横跨多列的色条（同一天开始的自动上下分泳道，最多 3 行，日视图 6 行；超出可视范围的部分裁到首末列）；月视图同样是一条跨日期的连续长条，按周换行（跨周自动断开），泳道先按整月排好再按周裁切，同一条待办每一周都停在同一行、上下顺序不会每周翻一次，每周能铺几条按卡片高度自动算，放不下的在右下角显示「+N」。日 / 周 / 月切换按空间记住，刷新后还是上次的视图。每条待办在日历上颜色不同（按 id 稳定取 8 个浅色之一，刷新不变色），左侧 2px 色条仍表示重要紧急程度；已完成统一置灰并划线。下方 00:00–23:00 完整 24 小时网格，今天带红色当前时间线与时刻。点月视图的日期（或周 / 日视图的日期）弹出当天的全部待办；点列表里的记录看详情（名称 / 状态 / 重要紧急程度 / 起止日期 / 备注，左上角 ‹ 返回当天的列表），点横条直接看该条详情；弹层上方 / 下方带一个小三角指回所点的格子或横条，可按 Esc 或点空白处关闭。左上角「今天」回到今天，‹ › 按当前视图翻页。卡片被拉高时，小时网格跟着均分撑满；放不下 24 小时时自动滚到当前时间附近。日历最小高度 320px，避免压到网格放不下。
- 数据按对应插件开关决定是否拉取：待办 / 任务 / 测试统计任一插件关闭时，相关卡片显示「插件未启用 + 去开启」，不影响其它卡片。
- 卡片排布是照飞书仪表盘的 12 列自由画布（`react-grid-layout`）：每张卡记一组坐标（列 / 行 / 宽 / 高），拖到哪就停在哪，同一行的卡片不再互相等高，右侧卡片也不会被左侧撑高。鼠标移到卡片上，顶部中间出现六个小圆点手柄，按住即可拖动位置；拖动时出现的淡蓝色块是落点预览。选中卡片带蓝色描边，点画布空白处取消选中。拖到视口上下边缘会自动滚动，长页面也能一路拖上去。位置松手后立即保存。鼠标悬停任意卡片都会轻微抬起并加深阴影（拖 / 拉期间不跟随浮动），被悬停的卡片连同选中描边一起压在其他卡片上方，不会被邻居的边框切掉。
- 卡片右下角有四点拉伸把手（悬停卡片时出现）：按住可独立改宽 / 改高，宽度按 12 列吸附、高度按 20px 一档吸附；挡住相邻卡片时，松手会把它们顺势推开（推开的卡再压到别的卡就继续传递），所以拉高右侧卡片不会再被左侧高度限制。拖动卡片落到别的卡上时，被压住的卡会先往同一行的空位左右挤开（左右都放不下才向下让位）；**往上拖**时原本在上面的卡片优先继续往上让（回到拖动卡腾出的空位），上方实在放不下才往下推，不会「往上一拖就把上面的卡全顶下来」。缩放卡片仍只往下推。双击把手在原位恢复这张卡的默认大小（原位放不下时排到画布最下方）。卡片内容跟着尺寸自适应，只有内容真的超出高度时才在卡片内出细滚动条；指标卡被拉高时数字块在标题和说明之间垂直居中，不会挤在顶部、底下空一大片。
- 卡片之间的间距是 12px（格子内边距 6px）；默认摆放会从左上角依次填空位，不再在中间留下整块空档。已有布局如果被拖出了空隙，可在「编辑组件」里点「自动整理」：只把卡片往上收、横向位置不变，每张卡保留自己拖好的宽高。组件目录里后来新增的卡片（例如「活跃项目」「数据空间」）会自动补到画布的第一个空位，不会压在已经摆好的卡片上。
- 页头右上角「编辑组件」：以卡片形式挑选组件，一行三个、组件多时弹层内滚动，点一下切换添加 / 移除（重新添加会尽量放回原位），左下角「全部添加」可一次放回所有卡片（已经摆好的卡保留原位置和大小，只补上缺的），旁边的「自动整理」把卡片往上收掉纵向空档（横向位置不变）；布局（显示 / 坐标 / 宽高）改动立即保存，按当前数据空间记在浏览器本地（`tw.view.dashboard.layout.v1`），不写空间文件，也不进 git。
- 页面没有单独的「刷新」按钮：数据每 15 秒静默轮询，回到前台（窗口聚焦或切回标签页）也会自动刷新；页面在后台时跳过一次请求。
- 刷新页面或重新进入仪表盘会回到上次浏览到的滚动位置（按标签页记在 `sessionStorage`，卡片高度撑开后再恢复），新开的标签页仍从顶部开始。
- 画布窄于 760px（手机、分栏、侧栏展开后剩余很窄）时不再按坐标铺开：卡片按「从上到下、从左到右」的阅读顺序堆成一列满宽，拖动 / 缩放手柄暂时隐藏，避免在十几 px 的列宽里挤成一团；窗口变宽后自动回到原来保存的坐标。

### 插件开发

> 需在 Lantern Harness 源码仓库中运行（`pnpm dev` / 本地服务），并能读写项目源码。生成的新插件进入仓库代码，开发服会热更新。

1. `+` →「扩展插件」→「插件开发」（或输入 `/` 选择）：输入框上方出现「插件开发」胶囊，形态与「计划」一致，没有侧边抽屉。
2. 直接在主输入框描述插件需求（做什么、给谁用、希望从哪里进入）后发送：模型先只读评估，再用选择题给出确认项（形态 / 范围 / 命名与入口 / 默认开关）。
3. **确认之前不会改任何文件**；在提问卡片里选定选项并提交后，才按项目插件规范实现，新插件并入「扩展插件」。
4. 开发会话自动切到 harness 源码根（`pnpm dev` 时即仓库根）并设为「工作区内修改」：`src / lh-plugins / config / docs` 都能直接改，`node_modules`、`dist`、`.git` 仍禁写。该目录只是临时占用，**不会**在侧栏「工作区」里新增一条。在已有内容的会话里进入插件开发不会自动新建会话（避免出现重复会话、像输入被吞），需要独立上下文时可先手动「新会话」。
5. 胶囊保持激活时后续消息继续使用同一套固定开发技能；点胶囊上的 × 退出（清除本会话的插件开发配置）。

### 生成类扩展（用例 / 知识库）

1. 用 `/` 或 `+` →「扩展插件」打开对应配置抽屉，也可在工作台「我的插件」里配；确认后进入（或复用）空会话，并关闭「我的插件」覆盖层回到会话区，标题保持「新对话」直至首次发送。
2. 抽屉内可增删改类型 / 分类（删除为行内二次确认）；确认后输入区上方显示「已启用 · 配置摘要」，可「改配置」或「取消」。
3. 在主输入框描述素材与要求后发送；结果经质检后写入对应目录，可在「用例管理 / 插件仓库的技能 / 知识库管理」中查看。
4. 生成用例可另选：用例类型、输出格式、需求文档、用例模板、知识库文档。插件会按用例类型自动使用对应技能，无需手动选择。
5. **入库文件名**（固定格式）：从需求文档名里抽出 **产品 + `v` 版本号**，再拼 `迭代版本_{功能|接口|性能|自动化}测试用例_{YYYYMMDD-HHmmss}`（例：`政企通v1.16.0迭代版本_功能测试用例_20261103-154800.xlsx`）。版本号后面的「版本 / 需求规格说明书 / …」一律丢掉，不靠枚举固定文案；类型段跟本轮用例类型走。无版本号时只用产品名。每次生成带新时间戳，不覆盖旧稿。

> 类型 / 分类与磁盘目录：模板库按分类分子目录（如 `测试模板库/安全测试用例/`）；用例与知识库为**平铺**存储——用例类型体现在文件名，知识库分类写入文档 frontmatter，均不产生子目录。改名不会自动迁移已有文件。

#### 用例顺序与「重排」

- **入库顺序**：生成的用例写入文件前会统一排序，口径为**需求条目（RO）→ 条目内测试点（TP）→ 生成顺序**。所以同一份需求里「第二步创建问卷」不会被后生成的条目挤到文件末尾。
- **引用需求点格式**：`RO-id 标题或原文；TP-xxx`（RO 在前，TP 在后）。RO 用来定条目顺序，TP 用来定条目内的先后；只写 US 编号时按故事的「来源条目」反查。
- **模块字段**：`模块` 填大模块原文，`子模块 / 小模块` 填小模块名。需求表是「大模块,小模块」这种层级路径时，子模块只写最后一段（叶子名），入库与重排都能对上。
- **兜底**：老文件没有「引用需求点」时，按 Ideal 小模块 / 章节文本匹配排；再对不上才退用户故事 / 用例编号。
- **已有文件重排**：用例管理行内点「重排」→ 选一份需求分析记录（或「仅按引用编号」）→ 预览需移动的行数与前 5 条 → 「开始重排」。写回前自动备份到「用例管理/备份列表/」，用例编号重编为 1…N；该文件的评审结论会一并清空（编号变了，旧结论对不上），需要的话重新评审。

### 知识库检索（@ 引用）

1. 插件库打开「知识库检索」。
2. 在 AI 工作台输入 `@`（可继续输入关键词过滤），↑↓ 选择，Enter 确认；文档会挂到输入框附件区并随消息发送。
3. 构建期写入文档列表，静态站同样可用（读 `/raw/...` 路径）；工作区文件需本地文件服务。
4. 未启用「知识库检索」时，`@` 只列工作区文件，并在菜单里提示启用后可引用 `知识库管理/`、`测试模板库/` 文档。

### 会话记忆

1. 插件页打开「会话记忆」后，工作台出现「记忆」Tab；存储为 `.lantern/local/memories/`。
2. 记忆轨：长期记忆 `MEMORY.md`、项目关键记忆 `KEY.md`（两者注入对话）、项目日志（可直写但不注入），存储层另有用户档案与每日日志。

5. 旧版 `graph.json` 首次启动会尝试迁入用户档案 / 长期记忆。

## 权限与本地能力

访问权限三档（输入区左侧切换），离线或静态站下文件与命令类工具均不可用：

| 档位         | 行为                                                 |
| ------------ | ---------------------------------------------------- |
| 仅可查看     | 只提供读取与搜索，不提供写入工具，命令执行不可用     |
| 工作区内修改 | 可在工作区读写；命令执行的工作目录被强制限定在工作区 |
| 完全权限     | 放开工作区外路径与更大范围的命令执行                 |

> 工作区默认是**当前空间目录**。插件开发会把工作区切到 harness 源码根（`pnpm dev` 时即仓库根）：这是唯一允许把「空间上级目录」设为工作区的例外，且只临时占用、不会出现在「工作区」列表里；其它上级目录仍会被拒绝。读不到仓库源码时，先确认是否落在「工作区内修改」及以上。

本地工具（需本地服务）：文件读写与 `glob` / `grep` 搜索、`bash` / PowerShell（含持久会话 write/signal 与后台任务）、网页搜索与抓取（可配置是否允许私网）、外接 MCP（`mcp__*__*`）、Office 转 PDF（需本机 LibreOffice）、`present` 交付清单、超大结果落盘（spill）、按需加载工作区 Skill；另外会自动加载工作区 `AGENTS.md` / `CLAUDE.md` 并注入当前时间。

## 插件仓库与技能

- **统一入口**：侧栏独立「插件仓库」入口提供扩展插件、MCP、技能三个标签页，工作台不再嵌套插件管理面板；侧栏折叠时保留插件仓库图标。旧 `/prompts/` 页面已下线。
- **迁移**：首次打开技能页会检查当前空间的提示词并完整导入，不修改原文；重复执行不新增副本。技能以独立名称和描述展示，同用途的多个规则收为技能内部变体，不自动合并或外显成多项技能。旧文件保留为原始备份，运行时通过旧引用解析到技能包；已迁移正文请在技能页维护，旧文档写接口会阻止直接覆盖。
- **默认规则**：默认提示词归为「空间基础规则」，常驻且不可停用；空间编辑与技能编辑共用同一份正文。不会因为改为按需技能而丢失默认规则。
- **插件联动**：开启扩展插件时准备对应技能，已有修改保留；展开插件卡片可点「配置关联技能」定位对应技能。插件只声明推荐关系，展示为「推荐给」标签，不会在开关变化时覆盖技能启停。技能卡片用独立开关控制；切换一个技能时只禁用当前开关，其他技能卡保持原状态，不再整页闪动。空间基础规则常驻且不可停用；当前技能页不提供卸载入口。
- **查看与编辑**：点击技能卡片打开详情弹窗；有多个内部变体时先在弹窗顶部切换，再在「业务规则 / 流程 / 资源与关联 / 输出校验」间编辑。保存产生新版本；编辑冲突时需重新加载。可选择历史版本恢复内容，恢复会生成新版本，不撤销此前业务写入。后台业务流程沿用已有执行器，流程文本用于会话指导。
- **资源交换**：可导入单份 Markdown 或包含 `SKILL.md` 和文本资源的 JSON 技能包（最多2MB、100个资源）；单份 Markdown 引用的外部资源不会自动下载。可导出完整技能包或合并后的说明。导入包的脚本不自动执行。
- **输出校验**：输入 JSON 的 `rows`、模板 `columns`、合法 `sourceIds`；可选 `enums`、`stats`、`requiredSections/sections`、`metrics`、`requiredFiles/files`。确定性检查结构、表头、编号、引用、优先级、分数、统计、章节和必需项目文件。未提供的检查条件会显示提示；它不调用模型，也不执行实际压测或业务操作。
- **工作台使用**：详情中「在工作台使用此技能」加载该变体的流程及业务规则，顶部显示技能与版本，可取消关联。会话也可通过 `skill_list` / `skill_load` 按需发现与加载，使用 `skill_validate` 校验输出。技能加载不改变现有工具权限。
- **磁盘位置**：当前内容根下 `技能管理/<id>/SKILL.md`、`references/business-rules.md` 以及需要的 `scripts/validate.mjs`，符合标准 Agent Skills 目录；版本与迁移恢复资料位于 `.lantern/local/skills/`。MCP 凭据仍在本机 `.lantern/local/mcp.json`，不随技能导出。

## Codex MCP 集成

- **入口**：`lantern mcp` 通过 stdio MCP 把当前空间能力交给 Codex；已有 `lantern web` 时直接连接，否则启动内嵌服务，页面不是必须打开。
- **外接 MCP 互通**：通过 `lantern_mcp_tools` 读取当前空间外接工具的真实名称、参数定义和连接错误，再用 `lantern_mcp_call` 调用。与工作台复用连接和权限，可读取规则引用的其他腾讯文档；调用可产生外部写入，须按用户授权执行。更新后重启服务及 MCP 进程，并新建 Codex 会话发现入口。
- **工具范围**：空间与技能查询、需求分析工作区准备、需求文档列表与导入、需求源文与技能上下文、需求分析读取、用户故事保存 / 单条修改 / 删除、故事审查上下文与保存、测试点上下文与保存。
- **首次使用**：Codex 会先准备需求分析工作区，启用需求文档库 / 需求分析 / 用户故事审查 / 测试点，并把当前空间的技能规则补种、迁移完成；重复执行不会覆盖已修改规则。
- **拆解需求**：Codex 先导入附件，再读取 Lantern 需求分析与原文结构技能，生成用户故事并保存；“拆解需求”默认不继续生成测试点。
- **文档导入**：同名文件默认自动改名保留历史版本，不静默覆盖。
- **完整需求分析**：在故事保存后继续保存审查结果、读取测试点技能并保存测试点。
- **互通**：正式数据只写入 Lantern 当前空间；Codex 返回 `analysisId`、`revision`、摘要和页面链接。Lantern 页面与 Codex 使用同一份需求分析和测试资产。
- **并发保护**：修改已有分析必须携带最新 `expectedRevision`。页面或另一会话先更新时返回冲突，Codex 需重新读取再改，不能覆盖新内容。
- **修改结果**：改单条故事使用增量补丁；删除故事会移除引用它的测试点。影响验收或边界的修改需要重新检查测试点。
- **边界**：Codex 不直接编辑 Lantern JSON，不使用浏览器点击 Lantern 页面；已停用技能不进入拆解和测试点上下文。导入与保存工具带写操作标注，按 Codex MCP 审批策略确认。
- **完整说明**：见 `docs/Codex-MCP集成.md`。

## 缺陷规则

在「插件仓库 → 测试技能」开启「缺陷规则」，从侧栏进入。规则按卡片展示名称、目标、字段和必填数，支持按名称、链接或字段搜索。

点击「新建规则」打开右侧编辑面板。填写规则名称并维护目标与字段；当前迭代不在编辑抽屉内维护。规则卡片在标题下的平台名称右侧展示字段数与必填数，底部标注「当前迭代」，下拉仅展示已维护的迭代，不提供「不设置当前迭代」选项；胶囊可直接切换、回车新增、改名或删除并立即保存，不会触发进入规则编辑抽屉。该列表仅手动维护，不从目标表识别结果自动生成；胶囊聚焦时只显示一层柔和焦点环。

可选择输入入口链接并点击「识别字段」。当前已实现腾讯文档链接识别，选定子表后会读取可用字段；已有的同一子表字段再次识别时保留填写口径，也可移除不需要的字段。其他入口或暂不支持识别的链接可先手动维护字段。

点击「添加字段」可手动输入字段名称。新建、手动添加和新识别的字段默认勾选必填，可按实际规则单独取消；每个字段分别维护填写规则、独立默认值和必填状态。填写规则是 AI 必须执行的判断或生成口径，例如严重程度可按功能影响、用户影响范围、是否阻塞主流程和数据损失风险判断；只要规则提供了判断标准，AI 应结合问题事实判断并说明依据，不能用默认值跳过判断。默认值在字段标题行内联显示：未设置时右侧为添加图标，设置后显示铅笔「修改」和垃圾桶「删除」图标；说明通过悬停提示查看，不再单独占用一块高度，窄屏时默认值自动换到标题下方一行。「迭代版本」字段不再单独编辑默认值，而显示「取自当前迭代」，保存草稿时自动使用规则级当前迭代。打开已有腾讯文档规则时会自动读取字段选项，不需要再次点击「识别字段」。单选和多选字段的下拉选项行悬停后可用铅笔修改显示名称，或用垃圾桶删除选项。自动识别字段的删除只从当前规则隐藏该选项，不改腾讯文档字段或已有记录；手动字段的选项属于当前规则，删除会直接从规则中移除。两种删除都会二次确认。草稿没有提供该字段时自动带入默认值，本次输入明确给出其他值则优先使用本次值。文本和数字字段直接输入默认值，单选项和关联项从当前表选项中选择一个默认值，多选项可增删多个默认项。图片字段先通过目标平台上传取得 image ID；附件字段仅在连接器支持上传和回写时填写，非必填的图片 / 附件没有材料时保持为空，不阻塞提交。通用规则用于填写整体要求；若通用规则引用了其他文档、知识库页面或目标平台记录，AI 会先读取并核对其中的人员、项目和子项目映射，再填写对应字段，例如按指定经办人归前端、其他经办人归后端。整理重现步骤时，账号密码、登录账号、权限、特定数据准备等前置内容不混在操作步骤里，而是放到末尾「前置条件：」下按 1.、2. 编号列出；没有前置条件时不添加，也不能编造账号密码。可只保存手动规则，目标入口留到使用时提供。点击「保存规则」后回到卡片列表，并在页面顶部显示保存成功 Toast；点击规则卡片主体可直接编辑，支持键盘 Enter / Space 打开。卡片中的「在工作台使用」独立执行。

卡片的「在工作台使用」会把规则及字段填写要求作为任务卡带入新会话。在工作台输入问题描述、缺陷编号或目标链接后发送，由 AI 按目标平台和当前空间可用连接器定位、新建或更新缺陷，写入后回读核验。说「提个缺陷」「提交缺陷」或「录入缺陷」时直接保存并提交同一版本，不再停在草稿等待二次确认；只有说「生成缺陷」「先做个草稿」「预览后再提交」时才停在草稿。必填字段缺失、目标有歧义，或负责人 / 迭代 / 需求关联等关键字段无法从证据匹配时会先说明。目标可以是腾讯文档、JIRA、禅道或其他已连接系统；只使用与目标平台匹配的连接器，不会默认走腾讯文档。输入明确指定的目标入口优先，否则使用规则保存的入口。当前自动识别字段的适配器实现为腾讯文档，后续平台通过相同入口模型扩展。

规则按空间保存于 `.lantern/local/defect-submit/`，原模板数据继续读取。旧缺陷提交及模板页面链接继续可用。页面沿用平台桌面布局，桌面端规则卡片一行两列，窄屏自动切换为单列，同排卡片保持统一高度。

缺陷规则编辑抽屉覆盖完整视口及左侧菜单，可点击遮罩、关闭按钮或按 Escape 关闭。首次打开已配置规则时会读取字段和子表，随后同一入口与子表的识别结果会缓存在当前标签页会话；关闭重开甚至刷新页面后仍直接复用缓存，不再重复请求或闪出目标子表。需要刷新腾讯文档最新结构时点「识别字段」。识别字段时优先读取链接中的子表，链接未指定时自动读取第一个可见子表，随后可用平台下拉组件切换。再次识别会按字段标识或原手动字段名称保留填写规则和默认值，并合并同名字段；选项已不存在时保存会提示重新选择。目标链接输入框与「识别字段」按钮同高，字段名称输入框与默认值控件同高；多选默认值的胶囊与空占位文字均垂直居中。

缺陷规则卡片按名称、目标、规则摘要和字段标签展示，超出内容省略并可悬停查看全文。点击卡片主体编辑，底部「在工作台使用」独立操作。删除按钮位于卡片底部，点击后弹出二次确认并显示规则名称，取消不执行删除。删除当前选中规则后自动选中剩余第一条；删除最后一条后回到空状态。规则编辑中的下拉统一使用平台组件。

缺陷规则卡片按实际可用宽度显示字段胶囊，放不下的字段以「+N」数量胶囊显示，悬停「+N」可查看全部剩余字段名称。单个长字段名称省略并提供完整气泡。编辑抽屉从右侧滑入、关闭时滑出，遮罩同步淡入淡出，动画结束后卸载并恢复卡片焦点。系统开启减少动态效果时立即切换。

缺陷规则卡片采用统一的紧凑高度，字段胶囊数量按卡片内部可用宽度自动计算，窗口尺寸变化时重新测量。
