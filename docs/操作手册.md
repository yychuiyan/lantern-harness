# 操作手册

界面从左到右为：左侧导航（功能入口）→ 中间内容区（工作台 / 内容库）→ 底部「设置」。首次使用请先完成模型配置。

| 区域     | 内容                                                                                                                                                                                                                                                                                                  |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 左侧导航 | 新建空间默认有「我的工作台」「提示词管理」「帮助中心」；提示词管理固定在帮助中心上方、不参与分组排序，其余内容库开启插件后才出现用例管理 / 知识库管理 / 需求文档库 / 测试模板库（可自行建分组）；「仪表盘」插件开启后入口出现在侧栏（新空间默认在最前面，已有空间按已保存的菜单顺序追加，可拖动调整） |
| 底部设置 | 通用设置与模型（BYOK）配置                                                                                                                                                                                                                                                                            |
| 帮助中心 | 版本日志 / 操作手册 / 安装手册，以及「问题与建议」外链                                                                                                                                                                                                                                                |

## 模型配置（BYOK，自带密钥）

点击侧栏底部「设置」→「模型」→「+ 添加模型提供商」，填入任意 OpenAI 兼容接口：

| 预设     | Base URL                                            | 模型示例         |
| -------- | --------------------------------------------------- | ---------------- |
| DeepSeek | `https://api.deepseek.com/v1`                       | `deepseek-flash` |
| 通义千问 | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus`      |
| OpenAI   | `https://api.openai.com/v1`                         | `gpt-4o-mini`    |
| 自定义   | 任意 OpenAI 兼容端点                                | 任意模型名       |

- 可添加多个提供商；在输入区右侧「模型 / 推理等级」菜单中切换，打开菜单时会实时请求端点 `GET /models` 刷新候选模型。
- 推理等级：**Low**（响应更快，适合简单问答）／ **High**（默认，质量与速度均衡）／ **Max**（最深推理，适合复杂分析）。
- 通用设置中可指定「子代理模型」，默认跟随主会话模型。

> 模型名以设置弹窗自动识别的下拉列表为准（来自 `GET /models` 的实时返回）。例如 DeepSeek 的 `deepseek-chat` / `deepseek-reasoner` 已于 2026-07 停用，当前可用型号为 `deepseek-flash`（V4.1 Flash）。
>
> **安全提示**：Key 仅保存在本机（本地服务写入 `.lantern/local/app.config.json`，静态站回退浏览器 localStorage），不上传任何服务器，也不会进入仓库。请勿在公共电脑上使用；请勿把 Key 写入任何会被提交的文件。

## 平台版本与更新

「设置 → 通用」底部的「平台版本」显示当前版本，并提供检查与更新：

- **检查更新**：向 npm registry（跟随 `npm config get registry`，读不到时用官方源）查最新版本，结果缓存 30 分钟；检查失败只提示「无法检查更新」，不影响使用。
- **有新版本**：侧栏版本号旁出现小圆点，点圆点直接打开该设置项；点「更新并重启」后服务会停掉、全局安装新版本、再用原端口和数据空间重启，页面轮询等待后显示「已更新到 vX」，可点「刷新页面」。
- **更新进行中**：按钮禁用并显示进度；期间页面请求短暂失败属正常现象，不会弹错误条。
- **更新失败**：显示错误与日志路径（`~/.config/lantern-harness/logs/server.log`），旧版本会自动恢复启动；也可以回终端执行 `lantern update`。
- **源码 / dev 模式**：只提示、不执行更新，请在仓库里 `git pull` 后重新 `pnpm build`；**npx 模式**：更新会转为全局安装并重启，之后不再走 npx 缓存。

## 我的工作台

侧栏进入「我的工作台」（`/workbench/`；站点根 `/` 是「自动化测试」入口，开启该插件时默认落在那里）。空会话居中展示品牌与标志语「提灯的人不问路」，并隐藏会话标题与「对话 / 回合 / 记忆」Tab；发出首条消息后顶栏与 Tab 出现。

- **Tab 记忆**：在「对话 / 回合 / 待办 / 记忆」之间切换后，刷新或重新进入页面仍停在原 Tab；选择按当前数据空间记在浏览器本地。空会话没有 Tab 栏，自动回到「对话」。

### 会话与工作区

- 「新会话」创建空对话；无消息的空会话在切换走时会被丢弃。
- 会话可置顶、重命名、归档、软删除；永久删除仅对已归档会话开放。标题由首条消息经模型自动生成短标题。
- 顶部搜索框可按工作区 / 会话标题 / 消息内容检索。
- 会话按工作区文件夹组织；输入区可切换 / 添加本地工作区，模型读写文件即落在该工作区。

### 对话 Tab

- 流式回复；思考与工具步骤在时间线中折叠展示，点击可展开全文。
- 每条助手消息显示用量与耗时（模型用时、工具用时、TTFT、TPS）；「+」→「会话统计」可查看整会话摘要。
- 生成中「发送」按钮变为「停止」；离开底部时会出现「回到底部」悬浮按钮。
- 有一体服务时，回合可在服务端继续跑，刷新 / 切页可重连；手动停止展示「已停止」。
- 上下文过长时自动摘要压缩；也可用「+」→「压缩」手动压缩以上对话。

### 输入区

输入框下方工具栏：

| 位置 | 控件            | 说明                                                             |
| ---- | --------------- | ---------------------------------------------------------------- |
| 左   | `+`             | 添加面板：文件、目标、计划、扩展插件、（指令）压缩、会话统计     |
| 左   | 工作区          | 显示当前目录，可切换 / 添加工作区                                |
| 左   | 访问权限        | 仅可查看 / 工作区内修改 / 完全权限；圆点表示本地文件服务是否在线 |
| 右   | 模型 · 推理等级 | 切换提供商、模型与推理等级                                       |
| 右   | 发送 / 停止     | 生成中为停止，空闲为发送                                         |

- `+` →「文件」添加本地附件（文本、Excel、Word 转正文附件）；也可直接粘贴图片或本地文件路径。
- `@` 引用知识库 / 模板 / 工作区文档（可继续输入关键词过滤，↑↓ 选择，Enter 确认），引用的文档随消息发送。
- 输入末尾 `/` 唤起已启用的面板型插件；未启用会提示先到「我的插件」打开。
- Enter 发送；生成中 Cmd/Ctrl+Enter 按通用设置选择的「排队发送」或「插话发送」执行。

### 回合 Tab

- 按轮次列出用户 / 助手摘要，可展开查看完整正文（不含思考）。
- **从此处继续**：截断到该轮末，切回「对话」，填入「请从第 N 轮继续」并自动发送。待回复或生成中时按钮不可用。

### 记忆 Tab

需先启用扩展插件「会话记忆」。见下文「会话记忆」。

### 计划模式、目标与定时

- **计划模式**：`+` →「计划」进入。探查阶段模型只读不改，先给出方案（`submit_plan`），批准后才实施；输入区显示「计划模式·探查中 / 已批准」胶囊，可随时退出。
- **目标**：`+` →「目标」设置本会话的长期任务目标；目标写入系统提示，模型可读写并按目标驱动多轮续跑。
- **定时提醒**：模型可创建定时任务，到点以系统通知与消息回到原会话。
- **子代理 / 工作流**：模型可按需派生子代理并行执行子任务（子代理模型见通用设置）。

## 内容目录约定

磁盘目录与侧栏 / 文案一致，均为**中文**。文件即数据：放入对应目录并 push，构建后上架；本地服务下也可在界面里增删。

| 目录          | 用途                                 |
| ------------- | ------------------------------------ |
| `需求文档库/` | 需求文档（`.md` / `.txt` / `.docx`） |
| `用例管理/`   | 生成的测试用例                       |
| `提示词管理/` | 提示词（系统提示词不可删）           |
| `知识库管理/` | 规范 / 方法论 / 环境约定             |
| `测试模板库/` | 用例与报告模板                       |

> 目录**按插件开关懒建**：新建 / 首次选中的数据空间只有隐藏的 `.lantern/` 元数据，启用对应内容库插件后才出现上表目录并补入种子文件；旧版本留下的空目录（只有 `.gitkeep`）会自动收起，已有文件的目录不动。**`提示词管理/` 是唯一例外**：每个空间都有默认提示词，因此该目录与 `默认提示词.md` 会始终铺好。

> 待办、任务、工作汇报、测试统计、用例执行统计、项目管理的四个插件的数据也直接放在空间里，跟侧栏入口对应：`待办事项/待办.json`、`任务管理/任务.json`、`工作汇报/日报 · 周报 · 月报/`、`测试统计/测试统计.json`、`用例执行统计/用例执行统计.json`、`项目列表/项目列表.json`、`迭代管理/迭代管理.json`、`需求管理/需求管理.json`、`缺陷管理/缺陷管理.json`、`自动化测试/自动化测试.json`。这些目录只在真的有数据时创建，没有数据就保持干净：打开开关、进入页面都不会预建空目录 / 空文件，第一次写入（新增记录、保存汇报文件）时才落盘。旧版放在 `.lantern/local/todos.json`、`tasks.json` 的数据读取时仍能直接看到，第一次写入时自动搬进 `待办事项/`、`任务管理/`；旧版四插件共用的 `项目管理/项目管理.json` 也会在首次读取或打开开关时自动拆到四个目录。

> 「空间管理」默认展示全部空间：右上角「+ 新增空间」新建并立即写入默认提示词；每行的「编辑」可修改空间名称、提示词要求与默认提示词正文，保存后工作台立即生效。

> 旧版英文目录（`requirements/` / `cases/` / `prompts/` / `knowledge/` / `templates/`）在启动时**自动改名**为上述中文目录，无需手工迁移；若目标目录已存在则不覆盖。

### 整体拷贝 / 扫描纳入

把一份空间文件夹（带 `.lantern/space.json` 清单）整体拷进数据目录后，在「空间管理」点「扫描文件夹」，即可纳入列表：名称以目录名为准，清单里的 id 与已有空间撞车时自动换新。

「空间管理」里的「复制」是另一种做法：在数据目录内**逐文件复制**出一个新空间（含待办、任务、汇报、会话、记忆与配置），新空间直接出现在列表里、不需要再扫描。

- 复制会跳过 `node_modules` / `.git` / `.astro` / `dist` 与 `.DS_Store`；也会跳过可重建的派生缓存（`.lantern/local/session-query.sqlite` 及其 `-wal` / `-shm`、`.lantern/local/spill/`），避免拷到写了一半的文件。
- 复制品里的工作区注册表会被改指新目录，所以新空间的「工作区」停在自己身上，而不是被复制的那个空间。
- 有会话正在运行时不允许复制（与切换空间一致，先停止再操作）。
- 复制**不会**自动切过去；切到新空间时页面会重载，待办 / 任务等按新空间的数据重新加载。
- 浏览器本地存储里按空间 id 记的界面偏好（列宽、侧栏展开状态等）不会跟着复制，新空间用默认值。

同一目录里其它**不是空间**的文件夹会在扫描后列出来，勾选并确认才纳入：

- 纳入只把文件夹登记进列表，**不写入 `.lantern/space.json`，也不铺内容目录、不播种子**，文件夹内容保持原样。
- 不勾选直接「忽略」则什么都不做。
- 切换到这类空间时才会写运行时配置（`.lantern/config`、`.lantern/local`，插件开关与会话需要落地），内容目录与文件仍按原样保留。
- 命令行等价操作：`lantern space discover`（列出候选）→ `lantern space discover --adopt <文件夹名>`。

### 侧栏分组即文件夹

侧栏分组会落成空间根下的真实文件夹：分组名就是文件夹名，文件夹里的 `.group.json` 记录分组 id 与成员菜单（子文件夹即子分组）。把整个空间目录拷到另一台机器后，本地服务扫一遍目录即可还原分组，不依赖本机配置。

**组内的内容目录会一起搬进分组文件夹**：把「需求文档库」拖进「文档组」后，磁盘上是 `文档组/需求文档库/`；取消分组再搬回空间根。子分组同理（`父组/子组/用例管理/`）。这样只看文件夹结构就能看出哪份内容属于哪个分组。搬到目标位置时若已有同名文件，不会覆盖，只把冲突条目留在原处并给出提示。待办、任务、工作汇报、测试统计、用例执行统计这类数据目录也一样跟着分组走（`待办管理/待办事项/待办.json`、`待办管理/任务管理/任务.json`、`待办管理/工作汇报/日报/…`、`质量数据/测试统计/测试统计.json`、`质量数据/用例执行统计/用例执行统计.json`）。

```text
任务空间/
├── 文档组/
│   ├── .group.json          # {"id":"ng_xxx","items":["requirements"]}
│   └── 需求文档库/
├── 用例管理/                # 未分组的内容仍在空间根
└── 提示词管理/
```

- 只认带 `.group.json` 的目录，空间里其它随手建的文件夹不会被当成菜单分组。
- 内容目录按「分组内优先、其次空间根」解析，所以把整份空间拷过来后（配置可能还没生成）也能直接读。
- 每个菜单项都带图标，可在三点菜单的「选择图标」里从内置图标中更换；图标不随分组变化而消失。
- 分组顺序可调：分组行三点菜单里的「排序」——顶层分组打开侧栏整体顺序（分组之间可拖动），子分组打开所属父组的列表（菜单与子分组各一段，分别拖动）；子分组顺序单独记录，刷新、切换空间后保持。
- 取消分组时，组内内容目录先搬回空间根（分组内菜单的「移出分组」只动这一项）；目录里还有用户放的其它文件时，会保留目录、只移除分组关系。旧版本留下的「清单已删但数据没搬走」的残留文件夹，会在下次读取分组时把数据搬回空间根并清掉空目录。
- 首次识别到内容目录（有文件，或已被分组引用）时，自动打开对应的管理插件（用例 / 提示词 / 知识库）；之后尊重手动关闭。

```text
用例管理/
  # 平铺存放（不再按用例类型分子目录）
测试模板库/
  功能测试用例/  接口测试用例/  性能测试用例/  自动化测试用例/
  功能测试报告/  接口测试报告/  性能测试报告/
知识库管理/
  # 平铺存放；分类写在文档 frontmatter 的 category（测试规范 / 方法论 / 环境约定）
```

### 各库操作

| 库         | 操作                                                                                                                                                                                          |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 用例管理   | 双击本地打开；批量删除；「在会话中打开」                                                                                                                                                      |
| 提示词管理 | 双击本地打开；删除（系统提示词不可删；插件开启期间，插件引用的提示词也不可删）；「关联插件」列标出归属；行内可复制 / 改名（悬停文件名右侧出现改名按钮，重名会拦下）；「生成提示词」跳转工作台 |
| 知识库管理 | 双击本地打开；批量删除；「在会话中打开」；「生成知识库」跳转工作台                                                                                                                            |
| 需求文档库 | 新建文件夹 / 上传文件（`.md` / `.txt` / `.docx`）；单击预览，双击本地打开；删除                                                                                                               |
| 测试模板库 | 分类浏览；双击本地打开；`.md` 可在线预览与下载                                                                                                                                                |

> 双击本地打开、读写文件依赖本地文件服务（`lantern web` 或 `pnpm dev`）；静态站仅能浏览与下载。

用例管理 / 提示词管理 / 知识库管理的列表都支持搜索与「按修改时间 / 按文件名」排序；**搜索词与排序方式会记住**，刷新或重新进入页面仍是上次的样子（三个库各记各的，按当前数据空间分开存）。

提示词列表在「文件名」右侧多一列**关联插件**：`工作汇报提示词.md` 显示「工作汇报」、`Playwright提示词.md` 显示「自动化测试」、`默认提示词.md` 显示「系统默认」，其它提示词一律显示「未关联」。**按实际挂载的也算关联**：在自动化测试「挂载提示词」里给某个项目选了 `pytest提示词.md` 后，这里同样显示「自动化测试」；在工作汇报页把提示词换成自定义文件，则显示「工作汇报」。各项目各挂各的，互不影响。只有**此刻真的被挂载**的那份才会再标一个「引用中」——一个项目只挂一份，换掉挂载后上一份立刻变回普通提示词（`Playwright提示词.md` 没人挂时只显示「自动化测试」，不带「引用中」）。`引用中` 的行 `删除 / 改名` 置灰并锁定（服务端也会拒绝，避免绕过界面），先换挂载或关掉对应插件再操作；插件自带的那份提示词在插件开启期间也保持锁定（插件要拿它做种子 / 模板），关掉插件后可删，再打开会重新生成种子。文件没删的话，再次打开插件会继续引用原来那份，不会被模板盖掉。

每行还能直接经营：操作列在「在会话中打开」右侧有**复制**（同名同目录复制一份，先弹命名，默认 `原名（副本）`；同名会拦下）与**删除**（带图标），三者同一行对齐；文件名右侧悬停出现**改名**按钮，只改主名、扩展名锁定，同一目录下重名同样拦下并提示。改名 / 删除后列表立即刷新。移出自动化测试项目时，它挂载的提示词会自动取消挂载，这里立刻回到「未关联」（同页在线时即时刷新，不用等切页）。

### 测试模板库格式

| 格式             | 行为                                                                   |
| ---------------- | ---------------------------------------------------------------------- |
| `.md`            | 在线上架预览 + 下载（须带 frontmatter）                                |
| `.xlsx` / `.xls` | 按分类上架；读取工作表名与首行表头，列表展示字段摘要；**仅下载**不预览 |
| `.docx` / `.doc` | 按分类上架，**仅下载**（不做在线预览）                                 |

模板库分类共七类：功能测试用例 / 接口测试用例 / 性能测试用例 / 自动化测试用例 / 功能测试报告 / 接口测试报告 / 性能测试报告。

Markdown frontmatter（构建期校验，不合规会构建报错）：

```yaml
---
title: 显示标题 # 必填
category: 功能测试用例 # 必填；模板库七类之一
description: 一句话描述 # 可选
version: '1.0' # 可选
---
```

知识库条目（`知识库管理/**.md`）frontmatter 为 `title` / `category` / `description`，缺省时用 `未命名` / `未分类`，不会中断构建。

### 待办事项

「我的插件」→「待办与效率」→「待办事项」开启后，侧栏出现「待办事项」入口（`/todos/`）。

- 数据落在当前数据空间的 `待办事项/待办.json`（放进侧栏分组后跟着走，如 `待办管理/待办事项/待办.json`），随空间走、不进 git；切换空间后看到的是各空间自己的待办。旧版的 `.lantern/local/todos.json` 会在首次读写时自动搬过来。
- 字段：待办名称、待办状态（待开始 / 进行中 / 已完成 / 已延期 / 已取消）、紧急程度（重要紧急 / 重要不紧急 / 紧急不重要 / 普通）、所属任务、开始日期、截止日期、结束日期、备注。
- **结束日期是只读派生值**：状态改为「已完成 / 已取消」时自动记为当天（再改其他字段不会刷新）；状态改回「待开始 / 进行中 / 已延期」时清空，界面上显示「待办未完成」。表格行内、抽屉、AI 工具（`todo_update`）改状态都按同一规则处理。
- **已延期由系统自动标记**：未结束且过了截止日期的待办，在读取 / 写入时自动把状态改成「已延期」并落库，页面与 AI 读到同一个状态；把截止日期推到将来后再手动改回「进行中」即可，不会被反复改回。
- 新建待办（抽屉与「+ 新增记录」）的**开始日期 / 截止日期默认是当天**，可直接改。
- 「所属任务」从「任务管理」里选（需同时开启该插件），选中后写回任务 id 与任务名称；**已关闭 / 已取消的任务不出现在选项里**。待办关联任务时，任务会从「任务池 / 已完成」被拉回「进行中」（已关闭 / 已取消的不动）；打开待办页时也会对「仍有未完成待办」的已关联任务做同样处理。任务管理开启时，旧数据里只存了任务名的待办会按名称自动补上关联，任务管理关闭时该列显示「任务管理插件未启用」，原任务名不会丢。
- 「待办周期」与「剩余天数」由日期自动算出（含首尾）；未完成且过了截止日期会显示「已延期」，状态也会自动标成「已延期」。
- 表格按飞书多维表格的方式展示：默认按「待办状态」分组（进行中 / 待开始 / 已完成 / 已延期 / 已取消），每组标题带记录数，点标题可折叠；顶部的分组下拉可切换为「按紧急程度分组」或「不分组」。**分组方式会记住**：刷新或重新进入页面仍停在上次选的分组，选择按当前数据空间记在浏览器本地。
- 单元格直接改：点名称 / 所属任务 / 日期 / 备注即可编辑，回车或点空白处保存，Esc 放弃；状态下拉与紧急程度下拉在行内改完立即生效（改状态后会自动换到对应分组）。
- 日期格不再显示系统小日历图标：点一下弹出白色卡片日历（可翻月，底部「清除 / 今天」），选完立即保存。
- 工具栏与单元格里的下拉都是卡片菜单（白底圆角），状态 / 紧急程度用颜色点和选中底色区分，不显示对钩，不会弹出系统原生下拉。
- 每组底部有「+ 新增记录」（手动新增入口）：点开后在组内展开一行，包含全部列（名称 / 状态 / 紧急程度 / 所属任务 / 开始日期 / 截止日期 / 备注；结束日期随状态自动生成，不在这里填）；没有单独的保存 / 取消按钮——填好名称后回车，或直接点页面空白处即自动保存，完全没填内容时点空白处则自动收起，Esc 放弃。顶部「新建待办」会从右侧滑出记录抽屉，按顺序填写名称、状态、任务详情、日期与备注后保存；没有数据时只保留右上角的「新建待办」按钮。
- 抽屉里的「待办状态」整行都可点：点击范围一直延伸到「待办名称」输入框的右边界，胶囊只是选中值的样子，点行的任意位置都会展开状态选项。
- 行尾的展开按钮可用同一个抽屉回看 / 修改整条记录；抽屉里的「待办周期」「剩余天数」是只读派生值，会随日期即时计算。
- 顶部可搜索，并按紧急程度筛选；支持批量删除，行尾「操作」列可删除单条，都会二次弹窗确认；表格右侧列较多时可横向滚动。**搜索词与紧急程度筛选会记住**（分组方式同样），刷新或重新进入页面仍是上次的样子，按当前数据空间存在浏览器本地。
- 列宽可拖：把鼠标放到表头字段的右边缘，出现竖线后左右拖即可调整；默认宽度就是设计稿宽度。调过的列宽存在浏览器本地（localStorage），刷新、切换页面后保持，不会写进数据空间。
- 新增行没有任何内容时，点页面其它位置会自动收起；已经填了名称则点空白处（或回车）即自动保存，不再有单独的 ✓ / ✕ 按钮。
- 「我的工作台」对话上方的 Tab 里有「待办」（待办插件开启时，排在「回合」右侧）：默认「全部待办」，按 已逾期 / 今天截止 / 接下来 / 没有截止日期 / 已完成 分桶（今日与其它待办都在里面）；也可只看「未完成」或「已完成」。每行显示待办名称、紧急程度，以及第二行的截止日期、剩余天数（逾期会标红）和所属任务；点左侧圆圈即可标记完成 / 恢复，右上角「打开待办页」跳到完整表格。停在 Tab 上每 15 秒自动刷新，AI 在会话里写入后不用手动刷。
- 输入框左侧「+」→「计划」下面会按插件开关给出「待办」「任务」两个手动入口（对应插件关闭时入口直接隐藏，不会触发新增）：点开后弹出同一张确认卡片，手动入口的最后一个按钮是「提交」。待办分两页：第一页填待办自身字段（名称 / 状态 / 紧急程度 / 开始日期 / 截止日期 / 备注，开始 / 截止默认今天），第二页选「所属任务」并只读展示该任务的名称、状态、紧急程度与起止日期；选中任务后，任务有值的开始日期 / 截止日期 / 紧急程度会自动带到第一页（紧急程度仅在待办未设置时带出），仍可再改。任务没有所属任务，一页填完（名称 / 状态 / 紧急程度 / 开始日期 / 截止日期 / 备注）。填好「提交」直接落库，不经过模型；点「取消」或点卡片外面任意位置（包括切到别的 Tab）只会播放收起动画并放弃这次新增，不会写入待办 / 任务。
- 工作台里直接说「记一条待办：周五前提交测试报告」，AI 会调用 `todo_add`；写入前聊天区会弹出**待办快卡**（与「+ → 待办」的完整表单不同）：只需要确认 / 修改待办名称，其余字段按固定规则自动填好——状态「进行中」、开始与截止日期默认当天，日期是**可改的区间**（点开始 / 截止任一日期就能打开日历，改起点晚于截止时截止会跟着挪，反之亦然；AI 明确给出日期时按给出的，例如「周五前」默认开始到截止都是那天）、所属任务默认「日常待办」，这一行也是下拉，可以换成任务管理里已有的任务；任务管理里没有「日常待办」时，选项里显示「日常待办（确认后自动创建）」，点「确认新增」后自动创建（状态进行中、紧急程度重要不紧急、开始日期当年第一天、截止日期当年最后一天；任务管理插件关闭时不关联任务）。紧急程度跟随所属任务，快卡里不再单独填。点「取消」或点卡片外面会收起卡片、不写任何数据，也不会留下一张空任务。快卡只在用户**明确要求记录待办**（「记一下 / 加个待办 / 帮我跟进 / 提醒我周五前完成」）时出现；只是聊天里提到一件事、行程或计划时 AI 不会建待办，也不会弹卡。如果 AI 已经明确识别出要归到哪个任务（例如你说「加到登录模块这个任务下」），会按该任务关联，不再套「日常待办」。查进度用 `todo_list`，完成用 `todo_update`。停在该页时会定时刷新，AI 在会话里写入后不用手动刷新。
- 待办表格里「所属任务」在「紧急程度」左侧：关联了任务时紧急程度显示为任务的紧急程度（单元格只读，换任务会自动跟着变，要改就去任务管理改那个任务）；没有关联任务时仍可在单元格里直接选。按紧急程度筛选 / 分组也按任务带出的紧急程度计算。

### 任务管理

「我的插件」→「待办与效率」→「任务管理」开启后，侧栏出现「任务管理」入口（`/tasks/`）。

- 数据落在当前数据空间的 `任务管理/任务.json`（放进侧栏分组后跟着走，如 `待办管理/任务管理/任务.json`）；切换空间后看到各空间自己的任务。旧版的 `.lantern/local/tasks.json` 会在首次读写时自动搬过来。
- 顶部七张统计卡片：全部任务、任务池、进行中、已完成、已关闭、已取消、需要紧急（重要紧急 + 紧急不重要）。
- **状态 Tab 记忆**：状态栏「全部 / 任务池 / 进行中 / 已完成 / 已关闭 / 已取消」切到哪个，刷新或重新进入页面仍停在哪个；选择按当前数据空间记在浏览器本地。
- **筛选与搜索记忆**：优先级筛选和顶部搜索词也会记住，刷新或重新进入页面仍按上次的条件过滤。
- 列表字段：任务描述、任务状态、紧急程度、开始日期、截止日期、任务周期、待办数量、完成进度、备注。
- 列表默认按**修改时间倒序**排列（最近改过的任务排最前，同一时间再按创建时间倒序）；创建时间与修改时间都会落库，但不在列表里显示。
- 新建任务的开始日期 / 截止日期默认是当天，可直接改。
- 「任务周期」由开始 / 截止日期算出；「待办数量」与「完成进度」按待办里的「所属任务」实时汇总（待办完成状态变化后自动刷新）。待办事项插件关闭时，这两列显示「待办事项未启用」。
- 状态 / 紧急程度在行内用卡片菜单改；日期点开卡片日历；点任务名称或用行尾展开按钮打开右侧抽屉，可改名称、日期与备注，并看到该任务下已关联的待办。
- 工作台里也可以让 AI 建任务：说「新建一个任务：…」会调用 `task_add`，同样直接弹确认卡片（一页：名称 / 状态 / 紧急程度 / 开始 / 截止日期 / 备注），确认后才创建；没有给出任务名称时卡片以空白形式打开。AI 不会先用提问卡片逐项追问字段；点「取消」或点卡片外面不会写入。查询用 `task_list`、改字段用 `task_update`、删除用 `task_delete`。
- 删除任务不会删待办，只是解除关联（待办里的「所属任务」变为未关联）。
- 列宽同样可拖表头右边缘调整，与待办页一致；表头、行高、状态胶囊、行尾展开 / 删除按钮的样式也与待办页保持同一套。

### 项目管理

「我的插件」→「项目管理」下有四个独立插件：**项目列表**、**迭代管理**、**需求管理**、**缺陷管理**，新建空间默认全部关闭。后三个依赖「项目列表」：开启任一子项会自动打开「项目列表」，关闭「项目列表」会连带关闭另外三个。

- 四类数据各自放在当前空间对应的目录里：`项目列表/项目列表.json`、`迭代管理/迭代管理.json`、`需求管理/需求管理.json`、`缺陷管理/缺陷管理.json`，文件里是 `{ version, items }`（需求 / 缺陷另带 `seq`）。目录固定挂在空间根，不随侧栏分组移动；**只有真的有数据时才创建**，没有数据不会铺空目录。切换空间后看到各空间自己的数据。页面每 8 秒静默刷新一次。旧版四插件共用的 `项目管理/项目管理.json` 会在首次读取（或打开开关）时自动按实体拆到四个目录，拆完删除旧文件。
- 状态枚举沿用 luckytask：项目 `规划中 / 进行中 / 已归档`；迭代 `规划中 / 进行中 / 已完成`；需求 `待评估 / 待开发 / 开发中 / 测试中 / 已完成 / 已取消`（优先级 `紧急 / 高 / 中 / 低`）；缺陷 `待确认 / 待修复 / 修复完成 / 待验证 / 验证通过 / 已取消`（严重程度 `致命 / 严重 / 一般 / 轻微`）。
- **缺陷状态流转**：`待确认 → 待修复 → 修复完成 → 待验证 → 验证通过`，任何阶段都可以改「已取消」。AI 改完并自测通过后**只推进到「待验证」**；「验证通过 / 已取消」由你验证后再定。项目详情页的「缺陷完成 %」= （验证通过 + 已取消）÷ 缺陷总数。旧数据里保存的「修复中」读取时按「修复完成」、「已关闭」按「验证通过」显示，不用手工改文件。
- **级联规则**：删项目会连带删掉它的迭代、需求与缺陷（确认弹窗里有说明）；删迭代只把需求 / 缺陷的「所属迭代」置空；删需求只把缺陷的「关联需求」置空。迭代、需求、缺陷本身都保留。把迭代改挂到别的项目时，原项目下关联它的需求 / 缺陷会解除迭代关联；把需求改挂到别的项目时，原项目下关联它的缺陷会解除需求关联。
- **编号**：需求 `REQ-001`、缺陷 `BUG-001` 由服务端按递增序号分配，删除后不回收。
- **筛选记忆**：四个看板的状态 / 项目 / 迭代 / 优先级 / 严重程度筛选与搜索词都按当前数据空间记在浏览器本地，刷新、重新进入页面或切回同一空间时保持上次的筛选；项目或迭代被删掉后，失效的筛选值会自动回到「全部」。
- **项目列表**（`/pm/projects/`）：卡片显示项目名首字、状态徽标、描述与「N 迭代 · N 需求 · N 缺陷」，右下角显示需求完成度；顶部可按状态筛选、搜索，卡片三点菜单提供「编辑 / 归档（或取消归档）/ 删除」。**点卡片（或卡片上的箭头）进入项目详情二级页** `/pm/projects/detail/?id=<项目 id>`：页头是返回按钮 + 项目名 / 描述 / 状态，下面用「迭代 / 需求 / 缺陷」三个页签切换当前项目的数据，可直接新建、改状态、编辑与删除；关闭「项目列表」插件后详情页同样不可用。
- **迭代管理**（`/pm/iterations/`）：按项目与状态下拉筛选，卡片显示「项目 · 开始 → 截止」、时间进度条与百分比；未完成且过了截止日期会标出逾期天数，未到期显示还剩几天。行内可「开始 / 完成」、编辑或删除；结束日期不能早于开始日期。
- **需求管理**（`/pm/requirements/`）：表格列 ID / 需求描述 / 优先级 / 需求状态 / 所属项目 / 所属迭代；顶部用状态胶囊（全部 / 待评估 / 待开发 / 开发中 / 测试中 / 已完成 / 已取消）筛选，状态下拉可在行内直接改。右侧抽屉可改所属项目、迭代（按项目联动）、需求描述（多行）、优先级、状态、备注与附件；附件支持上传文件 / 图片、拖拽或直接粘贴截图（可多张），抽屉里显示缩略图 / 文件名，点 X 单个移除，切换项目时会清空不属于新项目的迭代。分页与「测试统计」一致（每页条数可选，首页 / 末页）。
- **缺陷管理**（`/pm/bugs/`）：表格列 ID / 缺陷标题 / 严重程度 / 缺陷状态 / 所属项目 / 所属迭代；**默认按创建时间倒序排列**（新建的在最前，所以编号通常是倒着看的），顶部用状态胶囊筛选，另可按项目、迭代、严重程度筛选与搜索；状态可行内改。抽屉只填缺陷描述（第一行自动作为列表标题）、附件与备注，另可关联同一项目的需求；附件支持上传文件 / 图片（可多选），落到当前空间的 `缺陷管理/附件/`，可单个移除，删除缺陷时一并清理。分页与「测试统计」一致（每页条数可选，首页 / 末页）。
- **AI 工具**：项目 / 迭代 / 需求 / 缺陷各有一组 `list / add / update / delete`（共 16 个，名称为 `pm_project_*` 等）。可以让 AI「把登录需求挂到 v1.0 迭代」「把这条缺陷改成待验证」；写操作直接落库、不弹确认卡片，执行前 AI 会用 `list` 拿真实 id。计划模式下只允许查询，写入会被拦截。项目 / 迭代 / 需求也支持直接传名称，系统先精确、再忽略大小写匹配。

### 工作汇报

「我的插件」→「待办与效率」→「工作汇报」开启后，侧栏出现「工作汇报」入口（`/reports/`），并管理当前空间的提示词与汇报目录。

- **打开插件**：把内置的最小模板写成当前空间的 `提示词管理/工作汇报提示词.md`（文件已存在时不覆盖，保留用户改过的内容）。`工作汇报/日报 · 周报 · 月报` 目录**不预建**，等真正写入汇报文件时才出现。
- **工作台注入**：插件开启期间，发送消息时会把**当前选中的那份**提示词追加到系统提示词里（就是页面下拉里选的那份，默认 `工作汇报提示词.md`），用于把零散记录整理成日报 / 周报 / 月报等。工作台在进入页面时读取一次，所以换完提示词后「去工作台写汇报」或刷新页面即生效。
- **关闭插件**：侧栏入口隐藏，工作台不再注入；**提示词文件保留在「提示词管理」里**（改过的内容不会丢），已生成的汇报文件与目录也保留。重新打开还是原来那份，不会按模板覆盖。
- **换提示词**：工作汇报页刷新按钮左侧的下拉框可以从「提示词管理」里选任意一份 `.md` / `.txt` 作为汇报提示词，选择结果跟当前空间保存；选中的文件被改名或删除时，会自动回退到 `工作汇报提示词.md`（或名字里带「工作汇报」的那份），不会出现空提示词。
- **汇报列表**：侧栏「工作汇报」页按「日报 / 周报 / 月报」三个 Tab 展示各自目录里的 `.md` / `.txt` / `.html` 文件，每条汇报是一张卡片：左边类型角标，中间汇报名称（去掉扩展名，如 `周报（2026.10.12-2026.10.18）`）与「生成时间 · 文件大小」，右侧「打开」。宽屏按可用宽度一行两张 / 三张铺满（只有一条时撑满整行），不再是一张只有两列、右侧大片留白的表。按生成日期倒序分页（可切换每页条数）；**点卡片用系统默认程序在本地打开**（macOS 的访达 / 默认编辑器、Windows 的关联程序）——打开的是本机文件，所以页面上不再有预览弹窗。没有汇报时只显示一句「保存到 … 后会自动出现在这里」，不给跳转按钮。文件就是数据：手工放进目录，或让 AI 按提示词的约定存盘（如 `工作汇报/日报/2026-10-18.md`），刷新即可看到。
- **Tab 记忆**：切换成周报后刷新、关掉页面再进来，仍停在周报（月报同理）；选择按当前数据空间记在浏览器本地，换空间后各记各的。
- **去工作台写汇报**：点页面右上角「去工作台写汇报」，会把当前 Tab 带进工作台，输入框上方挂上「生成日报 / 生成周报 / 生成月报」胶囊；直接回车或点发送，就按页面下拉里选中的提示词写一份，点胶囊上的 × 可取消。斜杠菜单里只有插件，不列这三项。
- **修改提示词**：到「提示词管理」找到 `工作汇报提示词.md`，行尾点「在会话中打开」把文件挂到工作台作曲区，直接让 AI 改并保存；也可以双击本地打开编辑。改完重新进入工作台生效（提示词在进入页面时读取一次）。
- 开关、提示词与汇报目录都跟当前数据空间走，切换空间后各用各的。

### 测试统计

「我的插件」→「测试统计」→「测试统计」开启后，侧栏出现「测试统计」入口（`/test-stats/`）。

- 数据落在当前数据空间的 `测试统计/测试统计.json`（放进侧栏分组后跟着走，如 `质量数据/测试统计/测试统计.json`）；切换空间后看到各空间自己的记录。**打开开关或进入页面不会预建目录 / 空文件**，第一次添加记录（含空占位行）才铺出 `测试统计/` 与这份 JSON。
- 字段只有三个：**当前日期**（点一下弹卡片日历）、**测试统计维度**（单选彩色胶囊：功能测试用例 / 自动化测试用例 / 接口测试用例 / 测试报告 / 缺陷统计 / 自动化缺陷统计 / 测试计划）、**统计数量**。
- 维度下拉带「查找或创建选项」：输入后回车或点「创建「…」」即可新增维度，新维度会存进这份数据里，下次直接可选；每条记录只对应一个维度。
- 维度名称较长、列宽放不下时单元格里显示省略号，**鼠标悬停弹出气泡显示完整维度名**（没被截断就不弹）。
- 点右上角「+ 添加记录」会**立即生成一行并写入 JSON**（还没选维度的空行也算一条占位记录，刷新页面不会消失）；选好维度后它自动变成正式记录。可以连点追加多行，**列表按日期从新到旧排列**（最新的记录在最上面，同一天按创建时间倒序）。
- 单元格改完即自动保存（数量停止输入约 0.6 秒、失焦或回车落库），没有保存 / 取消按钮，行尾只有删除；删除占位行同样会把它从 JSON 里去掉。
- 顶部汇总显示记录数、覆盖维度数与数量合计，并支持按日期 / 维度 / 数量搜索；支持勾选后「批量删除」（二次确认），行尾也可删除单条。搜索词会记住（刷新 / 重新进入页面仍按上次的关键词过滤）。列表默认每页 20 条，可切换每页条数；列宽可拖表头右边缘调整，存在浏览器本地。

### 用例执行统计

「我的插件」→「测试统计」→「用例执行统计」开启后，侧栏出现「用例执行统计」入口（`/case-exec/`）。

- 数据落在当前数据空间的 `用例执行统计/用例执行统计.json`（放进侧栏分组后跟着走）；切换空间后看到各空间自己的记录。**打开开关或进入页面不会预建目录 / 空文件**，第一次添加记录（含空占位行）才铺出 `用例执行统计/` 与这份 JSON。
- 字段：当前日期、项目名称、开始日期、结束日期、用例总数、待执行用例、已执行用例；**当前剩余用例**与**执行比例**是只读派生列——剩余 = 用例总数 − 已执行用例，比例 = 已执行用例 ÷ 用例总数（保留两位小数，最多 100%）。
- 项目名称是彩色胶囊单选，同样支持「查找或创建选项」：输入新项目回车即创建，之后可直接复用。
- 项目名称过长时同样显示省略号，悬停弹出气泡预览完整名称。
- 点右上角「+ 添加记录」会**立即生成一行并写入 JSON**（还没填项目名称的空行也算一条占位记录，刷新页面不会消失）；填好项目后自动变成正式记录。开始 / 结束日期默认当天，结束日期早于开始日期时会提示并且不保存。可连点追加多行，**列表按日期从新到旧排列**（最新的记录在最上面，同一天按创建时间倒序）。
- 单元格改完即自动保存（数字停止输入约 0.6 秒、失焦或回车落库），没有保存 / 取消按钮，行尾只有删除（删掉该行会一并删掉 JSON 里的记录）。
- 顶部汇总显示记录数、项目数、已执行 / 用例总数与整体执行率；支持按项目 / 日期搜索，支持勾选本页后批量删除（二次确认），行尾也可删除单条。搜索词会记住（刷新 / 重新进入页面仍按上次的关键词过滤）。列表默认每页 20 条，可切换每页条数；列宽可拖表头右边缘调整，列窄时「执行比例」的进度条也会保留最小宽度，不会压成一条线。

### 自动化测试

「我的插件」→「测试统计」→「自动化测试」开启后，侧栏出现「自动化测试」入口（`/test-automation/`）。开启后打开应用根地址 `/` 会**默认落在这一页**；插件被关掉时根地址回落到工作台，工作台本身在 `/workbench/`。

- 挂载目标项目里**已有的测试项目**，不新增依赖、也不改项目文件：点「挂载项目」在卡片里展开目录面板（不是弹窗，按钮带箭头，再点一次收起），用「浏览…」调系统原生选目录，也可以直接粘贴 / 输入绝对路径（系统不允许弹窗时照样能挂载），点「挂载」即可：框架按 `playwright.config.ts`、`requirements.txt: pytest`、`pom.xml: selenium` 这类证据自动识别，挂完直接选中该项目、停在「运行」页。同一个目录重复挂载会切到已有记录。还没挂载任何项目时，面板常驻在空状态下方，打开页面就能填。首期支持：
  - **Playwright**（`playwright.config.*` 或依赖 `@playwright/test`）
  - **pytest**（`pytest.ini` / `pyproject.toml` / `conftest.py` / 依赖 `pytest`；按依赖自动区分接口与 UI，`requests` / `httpx` 为接口自动化，`selenium` / `playwright` 为 UI 自动化）
  - **Selenium**（Java 的 `pom.xml` / `build.gradle(.kts)` 含 selenium 依赖，或 Node 依赖 `selenium-webdriver` / `webdriverio`）
- **运行任务**是个下拉，对齐 Jenkins 的 choice 参数：除了「全量运行」（框架默认命令），还会把项目里**原本就声明好的跑法**列出来，挂载时扫一次，不用自己背命令：
  - Playwright / Node：`package.json` 的 `scripts`，筛 `test`、`test:*`、`e2e*`、`smoke*` 这类名字（`lint` / `format` / `--ui` / `--debug` 这类打开界面或会导致挂住的跳过），显示成 `npm run test:smoke`（pnpm / yarn 自动换），执行时透传 `--reporter=list,json,html` 以拿到 JSON 汇总
  - pytest：`Makefile` 里带 `## 说明` 的测试目标（`make smoke`）+ `pyproject.toml` / `pytest.ini` 的 markers（`pytest -m smoke`），解释器按 `.venv` → `uv` / `poetry` → `python3` 自动选
  - Selenium：`pom.xml` 的 `<profiles>`（`mvn test -Psmoke`）；Node 项目退回 `package.json` 脚本
  - 下拉里的任务名统一显示成「**名称（命令）**」，例如 `smoke（make smoke）`、`test:smoke（npm run test:smoke）`；自定义命令没填名称就直接显示命令
  - 下拉右侧的「**配置**」按钮打开运行配置弹窗，命令再多也只在弹窗里滚动，不会把卡片撑高：
    - 上半「自定义命令」：自己写「名称 + 命令」（比如 `uv run pytest -m "smoke or regression"`），在项目目录下**用 shell 执行**，支持引号与 `&&`，可删除；名称可以不填，不填时下拉里直接显示命令
    - 下半「自动发现」：挂载时扫出来的任务，每行显示短名 + 完整命令 + 来源说明（过长自动省略号），可以**修改**（改名 / 改命令，改完标「已改」，命令按原样执行、不再追加框架参数）或**删除**；改动只存差异（`taskOverrides` / `hiddenTasks`），项目配置变了也不串。右上角「**重新扫描**」会立刻重扫项目配置（比如刚在 `package.json` 里补了脚本），有改动时旁边还有「恢复默认」一键清空
    - 面板底部不再放「完成」按钮：点右上 ✕、点遮罩或按 Esc 关闭即可，面板配色跟随深浅主题
- 运行状态直接落在「运行」按钮上（按钮固定在运行条最右侧）：运行中显示「运行中…」并禁用、旁边出现「停止」；跑完后按钮变成「重新运行」，并用绿 / 红 / 黄小圆点标出上次是通过 / 失败 / 中断。失败策略（仅上次失败 / 失败即停）由框架自身限制，界面上不再提供。文件、`-k` / `-m`、headed、并发这些筛选控件先收起，后续再定。同一项目同时只允许一个运行，全局最多同时跑 2 个。
- 移出最后一个项目后页面不跳走：仍在同一张卡片里，只是没有挂载内容，顶栏和「挂载」面板都还在。侧栏菜单与页面首屏会用上次渲染的缓存先铺一遍，刷新不再空白闪烁，数据挂载后自动刷新（空闲时每 15 秒对一次）。
- 停止：先向进程组发 SIGTERM，5 秒未退出再 SIGKILL，浏览器 / 子进程会一起结束，状态记为「已取消」。
- 日志：运行中每秒增量拉取，显示在卡片内的浅色日志面板里并默认自动滚底（往上翻时暂停，滚回底部自动恢复，不再有「自动滚动」勾选框）；结束后保留原始日志，历史里点「日志」可回看。常见失败会额外给一句可操作提示（缺浏览器内核、没装 pytest、Maven 依赖下载失败等）。
- 报告：运行结束后把项目自己生成的 HTML 报告快照到 `自动化测试/<项目名>/报告/<runId>/`（Playwright 的 `playwright-report/`、Gradle 的 `build/reports/tests/test` 等；pytest 声明 `pytest-html` 时直接写进该目录），点「查看报告」在新标签打开，历史记录不会被下次运行覆盖；汇总条显示总数 / 通过 / 失败 / 跳过 / 耗时与本次命令（命令里的本机绝对路径收掉，只显示 `playwright test …` 这样的命令名 + 参数），Playwright 失败时可直接「重跑失败用例」（`--last-failed`）。
- 目录：页面上有「运行」「生成」「历史」三个 Tab，顶部是一行（下划线 Tab + 固定宽度提示词框 + 项目下拉 + 框架只读徽标 + 打开方式 + 挂载 + 更多菜单），不再有左侧项目文件树；提示词框只显示当前挂载的文件名（超长省略号 + 气泡），点它打开挂载弹窗；项目下拉宽度固定，菜单每一项第二行显示真实目录（过长省略号 + 气泡），整项悬停右侧出现删除按钮，点它会二次确认后移出项目（只删挂载记录，项目文件与历史报告都留，**该项目的提示词同时取消挂载**，提示词管理里对应的「引用中」立即消失）；更多菜单里有「复制项目路径 / 在访达中显示 / 重新指定目录 / 移出项目」；除「生成」里用户确认写入脚本外，插件不会修改项目文件。
- **打开方式**：顶栏右侧是一个分裂按钮——左侧显示当前应用的真实图标（默认 VS Code，点一下就用它打开项目目录），右侧箭头展开本机已安装的应用列表（VS Code / Cursor / Xcode / Sourcetree / iTerm / 终端 / 访达等，只列真装了的）。图标由后端从 `.app` 的 `.icns` 转成 PNG 缓存在本机配置目录 `.lantern/local/uiauto/app-icons/`，升级应用后自动重抽；选中项记在浏览器本地，下次沿用。
- **生成**（AI 写脚本）：切到「生成」Tab 后整页铺满（隐藏页面标题、去掉卡片外边距与描边）。布局是左右两栏：左边「需求 / 步骤计划」占满整列全高（300–560px，可拖分隔条调宽），右边上半是「探索活动 / 代码 / 变更」+ 最近一步截图，下半是可拖高（160px–65vh）、可收起到 36px 的「控制台 / 网络 / 试跑」面板；面板 Tab 行正中有展开 / 收起图标，收起 / 展开带高度过渡。
  - **探索不自动试跑**：探索阶段模型只提交步骤、不调用 `ui_test_verify`；试跑由你在右下「试跑」里发起，失败才会带着日志让模型修步骤。
  - **先出计划、再探索**：需求框高度可拖（输入框下方的小把手，72–420px，按空间记住）。输入需求点左边的「生成步骤」，模型只做测试设计，产出一份「动作 + 目标描述」的计划（不含定位器），可以手动上移 / 下移 / 删除 / 新增 / 改描述（改动 400ms 防抖保存）。**没有步骤时「开始探索」不可点**，避免模型跳过计划直接乱点。
  - **探索时才绑定定位器**：模型真的开一个浏览器把流程点一遍（默认有头，可以围观；也可以切无头），按无障碍快照里的临时 `ref` 操作，每步用 `locator_probe` 把 `ref` 换成定位器并校验「唯一 + 指的就是刚才点的元素」，带 `stepId` 时结果直接回填到左侧对应步骤（状态变「已绑定」并显示 `role=button name="登录"` 这样的摘要；没绑上会写原因）。随后由同一份步骤 JSON 渲染 TS（`@playwright/test`）或 pytest（`playwright.sync_api`）脚本，两种语言共用步骤，换语言只重新出码、不重跑模型。
  - 定位器优先级按官方建议：`data-testid` → `getByRole` → `getByLabel` / `getByPlaceholder` → `getByText` → 稳定属性 → 短 CSS；只能靠长 CSS 或第 N 个同名元素时提示「低置信度」，不承诺全自动自愈。
  - 账号等敏感值写成 `${ENV_NAME}`，出码变成 `process.env.NAME` / `os.environ.get("NAME")`，不会把凭据写进脚本；活动日志里填写 / 选择的值会打码，只保留 `${ENV}` 占位。
  - **生成会话**：需求、步骤计划、定位器绑定、试跑记录与每步截图只对本机有意义，存在本机缓存 `.lantern/local/uiauto/sessions/`（不进 `自动化测试/` 内容目录，也不随空间同步）；旧版本留在 `自动化测试/sessions/` 的会话会在插件启动后自动搬过来。
  - **草稿工作区**：试跑写在项目内 `.lantern-ai/<会话>/`（目录自带 `.gitignore`，内容为 `*`），结构是 `playwright.config.ts`（继承项目配置，只把 `testDir` 指向 `./draft`）、`draft/<标题>.spec.ts`、`results/`。**跑完不删**：失败现场可以「打开草稿」「打开目录」、看 trace，也可以「调试运行」（`--headed --trace=on`）或「Playwright UI」（长驻进程，面板里给地址，可「结束 UI」；离开页面 / 服务退出会自动结束）。「清理草稿」手动清，超过 7 天的草稿在下次建会话时顺手清掉。
  - 流程分三步、不自动串起来：**生成步骤 → 开始探索 → 生成代码 → 试跑**。探索只负责在浏览器里把流程点一遍并产出步骤；结束后按步骤出码（左栏「生成代码」可手动重出），**不会自动试跑**。试跑是右下「试跑」子 Tab 里的动作：失败时让模型只改步骤（定位器 / 等待 / 断言），最多 3 轮；没配模型就只跑一次、保留日志。页面行为本身不符合需求时保留失败并提示疑似缺陷，不会为了跑绿改断言。右下「试跑」子 Tab 显示状态、耗时、草稿 / trace 路径与上述调试按钮。
  - 确认路径后再「写入项目」：一条用例会同时产出**整组文件**——主用例（spec）、按页面拆出的 page object（`tests/pages/<Page>.ts` / `tests/pages/<page>_page.py`）、项目有登录态时再加一个 `tests/fixtures/auth-state.ts` 常量文件。右上「代码」Tab 左侧是文件清单（标出「用例 / 页面 / 登录态」），右侧预览与可编辑的写入路径，左下按钮明确写「写入 N 个文件」；路径都在项目目录内、写入前整批预检。**目标文件已存在时默认合并，不整文件覆盖**：spec 只在原有文件末尾追加这个新用例（缺的 `import` 补到 import 区，`test.use` / `BASE_URL` 不重复），page object 只在类里补缺失的方法，登录态文件已有 `STORAGE_STATE` 就不动；合并写不进去（例如文件名撞上别的类）才按冲突处理，整批不写，此时勾选「整文件覆盖」再重试。写盘中途失败会按 before 回滚已写过的文件，不留半套。写入时记录 before / after，右上「变更」Tab 立刻出精确到行的 diff（新增绿 / 删除红 / 3 行上下文，追加的条目标「追加」），并能「打开文件」「打开目录」；下面还有一段只读的「项目工作区其它改动」（`git status`，过滤 `node_modules` / `.lantern-ai` 等噪音）。
  - 写入后点「**按项目配置验收**」：用项目自己的 Playwright / pytest 命令跑正式文件（不再走草稿配置）。若文件被项目 `testMatch` 排除，会明确提示「没被项目配置识别为用例」，而不是笼统判失败。
  - **提示词**：打开「自动化测试」开关时，会往当前空间的 `提示词管理/Playwright提示词.md` 写一份种子。这份文件分「规划阶段 / 探索阶段 / 生成代码」三段：前两段分别用于「生成步骤」和「开始探索」，第三段约束出码要跟随项目原有的目录结构、语法风格与代码规范（复用已有 page object / fixture，按项目 formatter 与命名来，已有文件只追加不重排）；支持占位符 `{{project}}` / `{{dir}}` / `{{language}}` / `{{plan}}`。顶栏项目下拉**左边**是一个固定宽度的提示词框：只显示当前项目挂载的那份文件名，超出省略号、悬停弹气泡显示全名，**不做下拉、旁边也没有添加按钮**；点它就打开「挂载提示词」弹窗——只列出**能用来生成的**提示词（自动化测试自己那份 + 用户在提示词管理里自己建的 `.md`，工作汇报 / 默认提示词这类别的用途不显示），选一份点「挂载」即挂到当前项目并存盘，**挂上即被引用**——提示词管理里立刻标「引用中」。弹窗里没有「跟随插件默认」，也没有新建入口；要新建提示词去「提示词管理 / 工作台」建，回到本页就能选到。**项目没挂提示词时页面会被拦住**：自动弹出「先挂载提示词」，没有取消按钮、点遮罩也关不掉，必须选一份挂上才能继续用（列表里一份提示词都没有时不做拦截，避免选无可选）。挂载结果**按项目保存、一个项目只挂一份**：Playwright 项目和 pytest 项目可以各挂各的，换项目自动带出上次选的那份；在弹窗里换一份就替换掉原来那份，**上一份立刻取消引用**（提示词管理里不再标「引用中」，也恢复可删 / 可改名）；项目里存的那份被删 / 改名时，同样按「未挂载」拦截，重新挂一份即可。
  - **新增提示词**：在「提示词管理」或工作台里新建 / 编辑（`提示词管理` 支持直接复制一份再用改名按钮改成想要的名字），回到本页（切走再切回或刷新）就能在挂载弹窗里选到；自动化测试页不再内置新建入口。
  - **平台约定**：提示词一律以「提示词管理」里的文件为准，代码里写死的只是几行极简兜底。点「生成步骤」/「开始探索」前读不到提示词（文件不存在，或没有可用的规划 / 探索段）时，会弹错误 toast 并停下，不会悄悄用兜底文案顶上。**升级规则**：你改过的内容一个字都不动；没改过的种子（内容与上次插件写入一致）会跟着插件内置模板自动升级，不留旧文案；老版本留下的种子第一次见到只登记指纹、不覆盖。插件开启期间这份文件不可删除 / 改名，关掉插件后可以删，再打开会重新生成种子。种子指纹记在 `.lantern/local/plugin-prompts.json`。
  - 项目里已有 `auth-admin.json` / `auth-user.json` 会自动当登录态复用（填 `-` 表示不用）。需要验证码 / 2FA 时点「手动登录」：模型会在下一个工具调用前停住，你在已经弹出的浏览器窗口里把登录做完，再点「我已登录，继续」放行；这个按钮只在探索阶段、有头浏览器时出现（规划阶段没有浏览器窗口，不显示）。
  - 重新点「生成步骤」或「开始探索」等于开新一轮：服务端会清掉上一轮的步骤 IR、试跑结果与活动日志，代码页 / 试跑面板同步清空，不会把上一条用例的脚本当成这次的产出。探索活动会跟着会话存下来，切走的 Tab 再回来、刷新页面都还能看到上一轮的过程。
  - 步骤计划里只写测试动作（打开页面 / 点击 / 填写 / 断言 / 等待等），**不会有「截图」步骤**：截图只是探索时给你看的过程记录，不会进脚本。
  - 依赖项目自己装好的 Playwright（或 pytest-playwright），Harness 不额外下载浏览器；草稿放在被挂载项目的 `.lantern-ai/`。
- 数据按项目分目录：`自动化测试/自动化测试.json` 记项目与运行历史，每个项目的报告 / 结果 / 原始日志各在自己的目录里（`自动化测试/<项目名>/报告/`、`结果/`、`日志/`），同名项目会自动加后缀；切换空间各用各的。
- 旧版本的 `UI自动化/` 目录与平铺的 `报告/ 结果/ 日志/` 在首次读取时自动改名 / 搬迁到新结构，不需要重新打开插件开关，历史报告链接也不会失效。老数据没有框架字段时按 Playwright 处理。
- 首次运行前请先在项目目录装好依赖 / 解释器：插件**不自动** `npm install` / `playwright install` / `pip install` / `mvn`，环境未就绪时卡片上会直接给提示。

### 仪表盘

「我的插件」→「仪表盘」→「仪表盘」开启后，侧栏出现「仪表盘」入口（`/dashboard/`；新空间默认在最前面，已有空间按已保存的菜单顺序追加，可在侧栏拖动调整）。

- 首次进入是空白画布：所有卡片默认全部关闭，点右上角「编辑组件」自己挑要显示的卡片（之后布局按空间记住）。
- 页头照 luckytask 的工作台：左侧图标块旁是按当前时间变的问候（早上好 / 上午好 / 中午好 / 下午好 / 晚上好），有逾期待办时在问候后跟一句「N 项已延期」，下面是「2026年10月19日 星期一」格式的日期。
- 纯前端聚合当前空间的待办、任务与测试统计，不新增数据目录；数据仍由各自插件维护，仪表盘只读展示，只有「今日待办」的勾选完成会写回待办。
- 卡片清单：
  - **进行中待办**：状态为「进行中」的待办数量，下方补充「共 N 条待办」。
  - **进行中任务**：状态为「进行中」的任务数量，下方补充「共 N 个任务」。
  - **已逾期**：已过截止日期且未完成的待办数量，有逾期时数字与「需要关注」标红。
  - **待办完成率** / **任务完成率**：已完成 ÷ 可计完成（待办排除已取消、任务排除已关闭 / 已取消）；分母为 0 时显示 0%，带进度条与「已完成 / 总数」。每个指标各是一张独立卡片，不再合并成一张「待办概览」；旧布局里存过的「待办概览」会在读取时自动拆成五张。活跃项目与数据空间也是同样样式的独立指标卡。
  - **活跃项目**：项目管理里状态为「进行中」的项目数量，下方补充项目总数，点卡片进入项目列表（需要同时开启「项目列表」与本地服务）。
  - **数据空间**：当前账号下一共有多少个数据空间，下方标出正在使用的空间名；静态部署 / 服务不可用时显示「—」。
  - **倒计时**：四格数字块显示天 / 时 / 分 / 秒，右上角四格切换终点：**今天**（到今天 24:00）、**下班**（到自己设的下班时间）、**周末**（到下一个休息日，默认 00:00，可改成 18:00 之类）、**今年**（到次年 1 月 1 日 00:00），选择按空间记住。第一次点「下班」会先在说明行弹出时间输入框（预填 18:00，回车或点「确定」保存，点「取消」退回原来的终点并清掉这次的选择），之后按这个点倒计时；「下班」和「周末」说明行的「修改」都可随时改时分（平时隐藏，鼠标移入这一行才出现），时间按空间记住。过了下班点就停在 0 并写「已经下班啦」，不会自动跳到明天。周末设了非 00:00 的时点后，按休息日前一天的该时点算（下一个休息日是 10-24 周六时，设 18:00 就倒到 10-23 周五 18:00，下班即算进入周末），过了这个点直接显示「愉快」，不用等到周六；设回 00:00 时终点仍是休息日当天 0 点（周六 0 点 = 周五 24 点）。底部一行注明终点，例如「到 2026-10-23 18:00 开始休息」。休息日 = 法定节假日 + 周末，调休补班的周六 / 周日不算（例如 2026-10-10 补班，倒计时直接跳到 10-11 周日）。当天已在休息（周末或假期）时，周末终点显示全 0 并写「周末愉快 / XX 假期愉快」。节假日与调休数据单独放在 `public/cn-holidays.json`（不参与编译，改完刷新即生效），每年国务院办公厅公布次年安排后照通知往 `years` 里加一年即可，逻辑不用动；没有收录的年份按普通周末算。已录入 2026（正式）与 2027（官方尚未公布，只录了法定假日，卡片上会标「2027 年安排待公布」）。
  - **今日待办**：表格展示「开始时间 ~ 截止时间」区间包含今天的未完成待办（只填一端时按那一天算），已过截止日期的「已延期」待办也会留在列表里继续跟进，列为待办名称 / 待办状态 / 所属任务 / 开始日期 / 截止日期，每页 5 条可翻页；点名称前的圆圈可直接标记完成（立即写回待办，完成后会从本卡移出）；状态胶囊只读展示，改状态请到待办页。
  - **进行中任务**：表格展示状态为「进行中」的任务，列为任务描述 / 任务状态 / 重要紧急程度 / 开始日期 / 结束日期，每页 5 条可翻页；结束日期逾期标红。
  - **测试统计**：每个维度取最新一天的数量，按数量降序最多 10 个维度；照飞书柱状图带纵轴刻度（居中贴网格线）、横向网格线与柱顶数值，拉高时柱子一起变高。
  - 表格单元格 / 柱状图维度名过长会显示省略号，鼠标悬停出气泡看全称；内容超出卡片高度时卡片内出现细滚动条（表头吸顶）。
  - **待办日历**：照飞书日历的日 / 周 / 月视图。跨天待办按「开始 → 截止」展示：周 / 日视图的全天区是一条横跨多列的色条（同一天开始的自动上下分泳道，最多 3 行，日视图 6 行；超出可视范围的部分裁到首末列）；月视图同样是一条跨日期的连续长条，按周换行（跨周自动断开），泳道先按整月排好再按周裁切，同一条待办每一周都停在同一行、上下顺序不会每周翻一次，每周能铺几条按卡片高度自动算，放不下的在右下角显示「+N」。日 / 周 / 月切换按空间记住，刷新后还是上次的视图。每条待办在日历上颜色不同（按 id 稳定取 8 个浅色之一，刷新不变色），左侧 2px 色条仍表示重要紧急程度；已完成统一置灰并划线。下方 00:00–23:00 完整 24 小时网格，今天带红色当前时间线与时刻。点月视图的日期（或周 / 日视图的日期）弹出当天的全部待办；点列表里的记录看详情（名称 / 状态 / 重要紧急程度 / 起止日期 / 备注，左上角 ‹ 返回当天的列表），点横条直接看该条详情；弹层上方 / 下方带一个小三角指回所点的格子或横条，可按 Esc 或点空白处关闭。左上角「今天」回到今天，‹ › 按当前视图翻页。卡片被拉高时，小时网格跟着均分撑满；放不下 24 小时时自动滚到当前时间附近。日历最小高度 320px，避免压到网格放不下。
- 数据按对应插件开关决定是否拉取：待办 / 任务 / 测试统计任一插件关闭时，相关卡片显示「插件未启用 + 去开启」，不影响其它卡片。
- 卡片排布是照飞书仪表盘的 12 列自由画布（`react-grid-layout`）：每张卡记一组坐标（列 / 行 / 宽 / 高），拖到哪就停在哪，同一行的卡片不再互相等高，右侧卡片也不会被左侧撑高。鼠标移到卡片上，顶部中间出现六个小圆点手柄，按住即可拖动位置；拖动时出现的淡蓝色块是落点预览。选中卡片带蓝色描边，点画布空白处取消选中。拖到视口上下边缘会自动滚动，长页面也能一路拖上去。位置松手后立即保存。鼠标悬停任意卡片都会轻微抬起并加深阴影（拖 / 拉期间不跟随浮动），被悬停的卡片连同选中描边一起压在其他卡片上方，不会被邻居的边框切掉。
- 卡片右下角有四点拉伸把手（悬停卡片时出现）：按住可独立改宽 / 改高，宽度按 12 列吸附、高度按 20px 一档吸附；挡住相邻卡片时，松手会把它们顺势推开（推开的卡再压到别的卡就继续传递），所以拉高右侧卡片不会再被左侧高度限制。拖动卡片落到别的卡上时，被压住的卡会先往同一行的空位左右挤开（左右都放不下才向下让位）；**往上拖**时原本在上面的卡片优先继续往上让（回到拖动卡腾出的空位），上方实在放不下才往下推，不会「往上一拖就把上面的卡全顶下来」。缩放卡片仍只往下推。双击把手在原位恢复这张卡的默认大小（原位放不下时排到画布最下方）。卡片内容跟着尺寸自适应，只有内容真的超出高度时才在卡片内出细滚动条；指标卡被拉高时数字块在标题和说明之间垂直居中，不会挤在顶部、底下空一大片。
- 卡片之间的间距是 12px（格子内边距 6px）；默认摆放会从左上角依次填空位，不再在中间留下整块空档。已有布局如果被拖出了空隙，可在「编辑组件」里点「自动整理」：只把卡片往上收、横向位置不变，每张卡保留自己拖好的宽高。组件目录里后来新增的卡片（例如「活跃项目」「数据空间」）会自动补到画布的第一个空位，不会压在已经摆好的卡片上。
- 页头右上角「编辑组件」：以卡片形式挑选组件，一行三个、组件多时弹层内滚动，点一下切换添加 / 移除（重新添加会尽量放回原位），左下角「全部添加」可一次放回所有卡片（已经摆好的卡保留原位置和大小，只补上缺的），旁边的「自动整理」把卡片往上收掉纵向空档（横向位置不变）；布局（显示 / 坐标 / 宽高）改动立即保存，按当前数据空间记在浏览器本地（`tw.view.dashboard.layout.v1`），不写空间文件，也不进 git。
- 页面没有单独的「刷新」按钮：数据每 15 秒静默轮询，回到前台（窗口聚焦或切回标签页）也会自动刷新；页面在后台时跳过一次请求。
- 刷新页面或重新进入仪表盘会回到上次浏览到的滚动位置（按标签页记在 `sessionStorage`，卡片高度撑开后再恢复），新开的标签页仍从顶部开始。
- 画布窄于 760px（手机、分栏、侧栏展开后剩余很窄）时不再按坐标铺开：卡片按「从上到下、从左到右」的阅读顺序堆成一列满宽，拖动 / 缩放手柄暂时隐藏，避免在十几 px 的列宽里挤成一团；窗口变宽后自动回到原来保存的坐标。

### 插件开发

> 需在 Lantern Harness 源码仓库中运行（`pnpm dev` / 本地服务），并能读写项目源码。生成的新插件进入仓库代码，开发服会热更新。

1. `+` →「扩展插件」→「插件开发」（或输入 `/` 选择）：输入框上方出现「插件开发」胶囊，形态与「计划」一致，没有侧边抽屉。
2. 直接在主输入框描述插件需求（做什么、给谁用、希望从哪里进入）后发送：模型先只读评估，再用选择题给出确认项（形态 / 范围 / 命名与入口 / 默认开关）。
3. **确认之前不会改任何文件**；在提问卡片里选定选项并提交后，才按项目插件规范实现，新插件并入「扩展插件」。
4. 开发会话自动切到 harness 源码根（`pnpm dev` 时即仓库根）并设为「工作区内修改」：`src / lh-plugins / config / docs` 都能直接改，`node_modules`、`dist`、`.git` 仍禁写。该目录只是临时占用，**不会**在侧栏「工作区」里新增一条。在已有内容的会话里进入插件开发不会自动新建会话（避免出现重复会话、像输入被吞），需要独立上下文时可先手动「新会话」。
5. 胶囊保持激活时后续消息继续使用同一套固定提示词；点胶囊上的 × 退出（清除本会话的插件开发配置）。

### 生成类扩展（用例 / 提示词 / 知识库）

1. 用 `/` 或 `+` →「扩展插件」打开对应配置抽屉，确认后进入（或复用）空会话，标题保持「新对话」直至首次发送。
2. 抽屉内可增删改类型 / 分类（删除为行内二次确认）；确认后输入区上方显示「已启用 · 配置摘要」，可「改配置」或「取消」。
3. 在主输入框描述素材与要求后发送；结果经质检后写入对应目录，可在「用例管理 / 提示词管理 / 知识库管理」中查看。
4. 生成用例可另选：用例类型、输出格式（Markdown 表格 / Excel / CSV）、需求文档、用例模板、提示词、知识库文档。

> 类型 / 分类与磁盘目录：模板库按分类分子目录（如 `测试模板库/安全测试用例/`）；用例与知识库为**平铺**存储——用例类型体现在文件名，知识库分类写入文档 frontmatter，均不产生子目录。改名不会自动迁移已有文件。

### 知识库检索（@ 引用）

1. 插件库打开「知识库检索」。
2. 在 AI 工作台输入 `@`（可继续输入关键词过滤），↑↓ 选择，Enter 确认；文档会挂到输入框附件区并随消息发送。
3. 构建期写入文档列表，静态站同样可用（读 `/raw/...` 路径）；工作区文件需本地文件服务。
4. 未启用「知识库检索」时，`@` 只列工作区文件，并在菜单里提示启用后可引用 `知识库管理/`、`测试模板库/` 文档。

### 会话记忆

1. 插件页打开「会话记忆」后，工作台出现「记忆」Tab；存储为 `.lantern/local/memories/`。
2. 记忆轨：长期记忆 `MEMORY.md`、项目关键记忆 `KEY.md`（两者注入对话）、项目日志（可直写但不注入），存储层另有用户档案与每日日志。
3. 重要事实先进入「待确认记忆建议」：**采纳**才写入对应轨并注入，**拒绝**则丢弃；可在 Tab 内浏览、手动添加、归档或删除。
4. 「全局规则」页展示工作区 `AGENTS.md` 等规则文件；模型工具：`memory_search` / `memory_read` / `memory_suggest` / `memory_append`。
5. 旧版 `graph.json` 首次启动会尝试迁入用户档案 / 长期记忆。

`.lantern/` 已加入 `.gitignore`，**不会提交到 Git**。

## 权限与本地能力

访问权限三档（输入区左侧切换），离线或静态站下文件与命令类工具均不可用：

| 档位         | 行为                                                 |
| ------------ | ---------------------------------------------------- |
| 仅可查看     | 只提供读取与搜索，不提供写入工具，命令执行不可用     |
| 工作区内修改 | 可在工作区读写；命令执行的工作目录被强制限定在工作区 |
| 完全权限     | 放开工作区外路径与更大范围的命令执行                 |

> 工作区默认是**当前空间目录**。插件开发会把工作区切到 harness 源码根（`pnpm dev` 时即仓库根）：这是唯一允许把「空间上级目录」设为工作区的例外，且只临时占用、不会出现在「工作区」列表里；其它上级目录仍会被拒绝。读不到仓库源码时，先确认是否落在「工作区内修改」及以上。

本地工具（需本地服务）：文件读写与 `glob` / `grep` 搜索、`bash` / PowerShell（含持久会话与后台任务）、网页搜索与抓取、Office 转 PDF（需本机 LibreOffice）、`present` 交付清单、超大结果落盘（spill）、按需加载工作区 Skill；另外会自动加载工作区 `AGENTS.md` / `CLAUDE.md` 并注入当前时间。
