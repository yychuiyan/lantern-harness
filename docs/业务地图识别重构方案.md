# 业务地图重构说明

## 目标结构

业务地图系统详情只保留两个主视图：

1. **功能目录**：真实菜单驱动的目录树，目录和功能同树展示，支持手工整理和 AI 识别。
2. **业务流程**：基于已确认功能维护纵向步骤，AI 作为独立会话协助识别。

系统卡片、入口、源码目录和登录配置继续保留；系统概览、发布状态、发布检查、旧识别设置表单和独立提案审核不再作为产品入口。

## 数据模型

`业务地图.json` 升级为版本 2。系统新增扁平化目录数组：

```ts
interface BusinessDirectory {
  id: string;
  parentId: string;
  name: string;
  order: number;
  source: 'menu' | 'ai' | 'manual';
  menuPath: string[];
  entryUrl: string;
  evidence: BusinessEvidence[];
  createdAt: string;
  updatedAt: string;
}
```

功能新增 `directoryId` 和 `order`。旧版 `domain/module` 保留读取兼容，首次迁移时自动生成：

```text
业务域目录
└── 模块目录
    └── 功能
```

迁移前生成 `业务地图.json.v1.bak`，保留原功能、流程、步骤和证据 ID。不能把目录移动到自身或子目录；非空目录必须显式级联删除，被删除功能的流程步骤保留标题并清空失效关联。

## 菜单采集

页面目录记录：

- `menuPath`
- `menuOrder`
- `actionable`
- `status`
- `contentLength`
- `parentId`

采集器优先使用标准 ARIA 菜单层级；同时扫描左侧 `nav / aside / menu / sidebar` 等容器中的自定义可点击行，按 DOM 顺序、视觉缩进和祖先路径生成独立 `navigation` 清单。无法判断层级时按平铺处理并记录说明。AI 以该清单为目录顺序的唯一依据，不得自行合并、概括或重排；清单为空时继续使用页面正文和证据，但会明确标记目录覆盖可能不完整。

## AI 会话

每个业务系统维护一份持久化会话，入口为系统顶部「AI 助手」。

### 第一阶段：功能目录

1. 只读扫描系统菜单与页面。
2. AI 以菜单为骨架生成目录和功能草案。
3. 功能必须带页面证据；菜单名不能直接当作功能。
4. 用户可继续对话修改草案。
5. 点击「应用为功能目录」后写入正式地图，并开放第二阶段。

### 第二阶段：业务流程

1. 只使用已经应用的功能目录。
2. 默认覆盖全部功能，可在对话中缩小到目录或指定功能。
3. 系统步骤必须关联已存在功能；人工步骤可以不关联。
4. 用户点击「应用业务流程」后整批写入。

## 会话持久化

- 会话元数据：`.lantern/local/business-map/assistant/<系统ID>.json`
- 页面目录和原始证据：`.lantern/local/business-map/assistant/<系统ID>.checkpoint.json`
- 关闭窗口后后台继续运行。
- 重新进入时先读取会话快照，再通过 SSE 从最后序号继续接收事件。
- 服务重启会把运行中会话标记为中断，历史消息和日志保留。
- 模型请求最多等待 90 秒；等待期间每 5 秒记录已等待时间，前端显示不确定进度动画。超时会转入可重试错误，不再永久停在 0%。
- 模型凭证只存在于运行内存，不写入会话、日志或业务地图。
- AI 助手从页面右侧以宽抽屉打开；执行任务栏固定在抽屉右侧，输入区复用工作台会话 composer 的结构与交互。

## 兼容边界

- 旧版 `.lantern/local/business-map/analyses/` 任务和地图中的旧提案/发布字段继续可读，不再驱动新 UI。
- 旧 `/analyze` 与 `/analyses` 接口暂留兼容，但新页面只调用 `/assistant/*`。
- 页面采集仍严格执行只读请求，拦截写请求、危险 URL、WebSocket 与 beacon。
