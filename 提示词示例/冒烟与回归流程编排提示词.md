# 冒烟与回归流程编排

流程证明多个功能、多个角色或跨页面业务链路能按顺序走通；原子自动化只证明单条功能结果。

## 规则

- 至少两条已接入且有步骤 IR 的原子用例。
- `flowOnly=true` 的原子块可进入流程，但不能单独运行。
- 按真实业务顺序编排，允许上下调整。
- 冒烟覆盖最小核心闭环；回归覆盖完整链路和关键分支。
- 单条独立功能不需要流程。
- 跨角色、跨页面、前序数据依赖或不可分割链路必须建流程。

## 角色

- 每个角色独立 Browser Context 和 storageState。
- 只保存环境变量名和登录态路径，不保存账号密码。
- 缺角色时在生成前阻断并列出待补角色。
- 上游 `captureAs`，下游 `valueFrom`，业务数据通过 `flowData` 传递。
- 生成前按执行顺序校验 `valueFrom`；缺少前序 `captureAs` 时必须阻断，不能生成会在运行时才报错的脚本。

## 检查点

结果为 `pending / passed / failed / blocked / not_reached / skipped`。失败分类包括 `environment / login / missing_role / role_permission_mismatch / role_session_expired / locator / test_data / assertion / dependency`。

失败后后续检查点标 `not_reached`，不能默认通过。流程通过只回写流程和检查点，不批量回写来源功能用例。

## 写入

先预览检查点、Playwright + TypeScript 多 Context 脚本和业务地图只追加补丁。业务地图写入携带最新 revision；用户确认后再写 iteration、流程和地图。流程含相对地址时，每个角色 Context 必须继承项目 baseURL；项目未配置 baseURL 时在生成前阻断。
