# Lantern Harness

> 提灯的人不问路。

AI 工作台：对话与插件工具、需求 / 用例 / 知识内容库、技能（业务规则 / 流程 / 资源）、模板库、会话记忆，数据全部留在本机。

仓库：[yychuiyan/lantern-harness](https://github.com/yychuiyan/lantern-harness) · 文档：[lantern.yychuiyan.com](https://lantern.yychuiyan.com/) · npm 包 `lantern-harness`，命令 `lantern` · [变更日志](https://lantern.yychuiyan.com/docs/changelog/)

## 功能

| 模块      | 说明                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AI 工作台 | 多轮对话，流式输出，BYOK（自带密钥）直连模型；空间基础规则按技能维护，可按插件挂载工具                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 会话记忆  | 五轨记忆（用户档案 / 全局事实 / 项目关键 / 项目日志 / 每日），待确认队列与工作台「记忆」Tab                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 插件库    | 内置能力开关：内容库（需求 / 用例 / 知识库 / 模板 / 报告管理）、生成能力、业务地图（系统卡片检索与概览、待完善项定位、手工维护功能 / 流程 / 证据，以及指定功能 / 多个功能 / 系统全量的 AI 后台识别与低风险自动入草稿）、记忆与检索、任务 / 待办 / 工作汇报 / 测试统计、人生管理（OKR 六表）、自动化测试（自动化项目 / 自动化执行，支持 Playwright / pytest / Selenium，可从零生成企业级基础框架，生成前先做结构 / 选项体检并可让 AI 按「自动化项目创建」技能补全，Playwright 项目可直接编辑 `.env.<ENV>` 环境配置）、项目管理（项目 / 迭代 / 需求 / 缺陷）、仪表盘、开发工具；开启后侧栏出现对应入口，也可让模型推荐能力建议 |

业务地图支持在系统设置维护账号密码、SSO / 接口及手动验证码登录，自动识别复用保存的登录态；凭据独立保存在本机用户配置目录，按空间与系统隔离。

模型配置（BYOK）、内容目录约定、插件用法见 **[操作手册](https://lantern.yychuiyan.com/docs/manual/)**。

## 快速开始

两种用法任选其一。装好后都在侧栏「设置」配置 BYOK；默认打开 `http://127.0.0.1:4321/`，会直接进「自动化测试」（`/test-automation/`，插件关闭时回落到 `/workbench/` 的「我的工作台」）。

### 方式一：免安装方式（推荐）

1、 安装：

```bash
npx lantern-harness
```

执行后会安装全局短命令 `lantern`，之后用 `lantern init` / `lantern web` 操作即可。升级有两种方式：终端执行 `lantern update`（在跑的服务会自动停掉、装完重新拉起），或在页面「设置 → 通用 → 平台版本」点「检查更新 / 更新并重启」——有新版本时侧栏版本号旁会出现小圆点，但**不会在后台自动升级**，点按钮才装。`npx` 模式下的页面更新会先装到全局，再用全局 `lantern` 启动。

2、 初始化数据空间池根（首次必做；可再次执行以更换）：

```bash
lantern init                 # 默认同时写入产品与开发池根
lantern init --scope=web     # 仅 lantern web / npx
lantern init --scope=dev     # 仅 pnpm dev
```

按序号选择目录后再选作用域。`dataRoot` 与 `devDataRoot` 路径相同则共用数据，不同则分离；未单独配置开发池根时 `pnpm dev` 回退产品池根。

3、 常用命令：

```bash
lantern init           # 选择并记住池根（可加 --scope）
lantern web            # 启动本地 Web 服务
lantern stop           # 停止服务
lantern restart        # 重启服务
lantern status         # 运行状态、端口、产品/开发池根
lantern open           # 在浏览器中打开工作台
lantern path           # 显示产品池根路径
lantern config         # 显示配置文件地址
lantern logs           # 查看服务日志
lantern doctor         # 检查运行环境与配置是否正常
lantern help           # 显示操作命令列表
lantern version        # 显示当前版本号
lantern list           # 显示可用版本列表
lantern update         # 更新到最新版本（在跑的服务会自动重启）
lantern update 0.1.x   # 更新到指定版本（同上）
lantern uninstall      # 卸载本机 lantern 命令（保留数据空间）
lantern wipe           # 删除当前数据空间（需确认；不可恢复）
lantern space list     # 列出全部数据空间与当前项
lantern space add      # 新建数据空间（--use 顺带设为当前）
lantern space use      # 切换当前数据空间
lantern ask            # 无界面单轮问答，lantern ask <问题或要求>
lantern rpc            # 以 stdio JSON-RPC 暴露本地问答能力
lantern acp            # 以 ACP 子集供外部编排驱动无 UI Agent
lantern mcp            # 以 stdio MCP 向 Codex 暴露 Lantern 能力（可选 --url / --port）
```

4、 插件默认值：

侧栏提供独立「插件仓库」菜单，分为扩展插件、MCP、技能。原「提示词管理」菜单已移除；空间默认规则在「插件仓库 → 技能」维护并常驻生效。技能按独立名称、描述和能力包维护，旧提示词按原文迁为技能内部变体，旧路径继续兼容；插件只声明推荐关系，不会覆盖技能启停。其余扩展插件（其它内容库含报告管理、生成能力、业务地图、知识库检索、会话记忆、任务管理 / 待办事项 / 工作汇报 / 测试统计 / 用例执行统计 / 自动化测试、人生管理、项目列表 / 迭代管理 / 需求管理 / 缺陷管理、仪表盘、插件开发）都要在「插件仓库」按分类手动开启；由「插件开发」新增的插件同样默认关闭。

### 方式二：源码启动

适合改代码或二次开发。

1、 克隆仓库到本地：

```bash
git clone https://github.com/yychuiyan/lantern-harness.git
cd lantern-harness
```

2、 开发模式（热更新，含本地落盘 API；池根见上文 `lantern init --scope=dev`）：

```bash
pnpm install
pnpm dev
```

3、 预览静态页（需先打包；无本地落盘）：

```bash
pnpm build
pnpm preview
```

## 许可证

[MIT](https://github.com/yychuiyan/lantern-harness/blob/main/LICENSE)

插件开启时自动准备对应技能；已有修改保留。技能支持规则与流程编辑、Markdown / JSON 技能包导入、资源导出、版本恢复、输出校验与在工作台使用。业务功能复用原执行器；关闭扩展插件不删除共享技能。目录和迁移说明见 [操作手册](docs/操作手册.md)。

Codex 可通过 `lantern mcp` 调用当前空间的需求分析、技能和测试点能力，支持导入需求、拆解并保存故事、单条修改 / 删除故事、审查与生成测试点；页面与 Codex 共用数据并用 revision 防止并发覆盖。还可通过 `lantern_mcp_tools` / `lantern_mcp_call` 发现并调用当前空间的腾讯文档等外接 MCP，复用现有连接与凭据。接入方式见 [Codex MCP 集成](docs/Codex-MCP集成.md)。

### 缺陷规则

在「插件仓库 → 测试技能」开启「缺陷规则」。卡片管理规则，链接识别字段或手动添加，每个字段配置填写要求和必填状态；规则可手动维护当前迭代并自动带入目标“迭代版本”字段。点击「在工作台使用」携带规则到会话，结合输入直接处理目标缺陷。Codex 接入见 [Codex MCP 集成](docs/Codex-MCP集成.md)。

缺陷规则卡片支持点击编辑、在工作台使用和二次确认删除。省略文字通过平台气泡查看完整内容。
